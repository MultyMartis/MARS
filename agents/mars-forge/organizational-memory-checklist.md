# Organizational Memory Checklist - MARS Forge

**Status:** **documented** - Forge overlay checklist for human-supervised organizational memory and institutional knowledge QA.  
**Not:** autonomous institutional AI, permanent memory system, runtime persistence, universal organizational law, or perfect historical continuity.

**Parent governance:** [`../../projects/mars-website-factory/organizational-memory-governance.md`](../../projects/mars-website-factory/organizational-memory-governance.md).  
**Institutional knowledge model:** [`../../projects/mars-website-factory/institutional-knowledge-model.md`](../../projects/mars-website-factory/institutional-knowledge-model.md).  
**Drift taxonomy:** [`../../projects/mars-website-factory/knowledge-memory-drift-taxonomy.md`](../../projects/mars-website-factory/knowledge-memory-drift-taxonomy.md).

---

## 1. When To Run

Run this checklist before freeze, handoff, report closure, cross-project transfer, continuity checkpoint, or long-session closure when any of the following affect the section, page, or delivery scope:

- the work produced a reusable operational lesson;
- a prior project, prior report, old decision, or historical pattern influences the current scope;
- a repeated mistake, rediscovery loop, or recurring drift pattern appears;
- important knowledge exists only in memory, chat, or long reports;
- freeze, source, workflow, visual, recovery, or transfer lessons should survive the current project;
- future operators need to understand why a rule, constraint, or decision exists;
- archived documentation exists but lesson survivability is unclear.

Record results as **ORGANIZATIONAL MEMORY FINDINGS**.

---

## 2. Organizational Memory QA

- [ ] The operational lesson that should survive is named, or **SAFE UNKNOWN** is recorded.
- [ ] The source event, report, decision, freeze, failure, or drift that produced the lesson is identified.
- [ ] The lesson is distinguishable from raw documentation, old report text, archive presence, or project nostalgia.
- [ ] The lesson states what future mistake, rediscovery loop, or drift pattern it helps prevent.
- [ ] The lesson has a visible scope: project-specific, reusable, partial, deprecated, escalation-bound, or SAFE UNKNOWN.
- [ ] The lesson remains human-readable without private session memory.
- [ ] The lesson does not claim perfect continuity or universal authority.

---

## 3. Lesson Survivability QA

- [ ] Lesson source and evidence are traceable.
- [ ] Lesson action is clear enough for future operators.
- [ ] Lesson limitation, exception, or transfer boundary is visible.
- [ ] Lesson is not buried only in a long report, chat, archive folder, or final summary.
- [ ] Lesson can survive handoff, compression, archive, and later continuation.
- [ ] Lesson does not depend on tribal knowledge or unstated operator memory.

---

## 4. Continuity Inheritance QA

- [ ] Future work can see what continuity it may inherit.
- [ ] Inheritance state is classified: reusable, project-specific, partial, escalation-bound, deprecated, or SAFE UNKNOWN.
- [ ] Prior findings are not treated as automatic instructions without source, scope, and compatibility review.
- [ ] Freeze-history, governance-history, escalation-history, and reusable-understanding layers are preserved when material.
- [ ] Continuity inheritance does not import stale project assumptions or "start from scratch" culture.

---

## 5. Rediscovery-Risk QA

- [ ] Repeated mistakes or recurring drift patterns are named.
- [ ] Prior lessons are checked before re-investigating the same issue.
- [ ] The current report explains whether this is a new issue, repeated issue, or known pattern.
- [ ] Rediscovery risk is reduced by a future trigger or application note.
- [ ] If prior lesson evidence is missing, **SAFE UNKNOWN** is recorded rather than reinvented history.

---

## 6. Historical Traceability QA

- [ ] Historical decision, source version, freeze state, or report reference is traceable when it affects the lesson.
- [ ] Active, stale, superseded, deprecated, and unknown historical material are not blended.
- [ ] Operational lineage from event -> evidence -> lesson -> governance placement -> reuse boundary is readable.
- [ ] Historical context is not inferred from archive presence alone.
- [ ] Missing history is surfaced as **SAFE UNKNOWN**, HITL, or blocked reuse when material.

---

## 7. Institutional Readability QA

- [ ] The lesson is written for a future operator who was not present.
- [ ] The lesson separates fact, interpretation, assumption, unknown, and action when material.
- [ ] The lesson identifies which governance layer should consume it.
- [ ] The lesson avoids vague phrases such as "previously known," "from old work," or "as usual" without evidence.
- [ ] The lesson can be compared with future findings using stable vocabulary.

---

## 8. Memory Drift Classification

Classify any issue using [`knowledge-memory-drift-taxonomy.md`](../../projects/mars-website-factory/knowledge-memory-drift-taxonomy.md):

- [ ] Institutional memory loss.
- [ ] Rediscovery loop.
- [ ] Lesson fragmentation.
- [ ] Tribal knowledge collapse.
- [ ] Undocumented operational wisdom.
- [ ] Historical amnesia.
- [ ] Continuity inheritance failure.
- [ ] Governance-memory erosion.
- [ ] Reusable-lesson decay.
- [ ] Pattern-history loss.
- [ ] Operational-lineage fragmentation.
- [ ] Institutional drift.
- [ ] Historical-context collapse.

## 9. Reporting Block

Use this block in Forge reports when organizational memory is in scope:

```text
ORGANIZATIONAL MEMORY FINDINGS - <section / scope / lesson>

Memory source:
- <project / report / freeze / failure / decision / SAFE UNKNOWN>

Institutional knowledge layer:
- <operational-history / lesson / freeze-history / governance-history / reusable-understanding / escalation-history / continuity-survivability>

Lesson survivability:
- Lesson:
- Risk prevented:
- Scope: reusable | project-specific | partial | escalation-bound | deprecated | SAFE UNKNOWN
- Limits / transfer boundary:

Continuity inheritance:
- Future trigger:
- Governance layer:
- Reuse disposition:

Memory drift taxonomy:
- Patterns:
- Severity:
- Rediscovery / handoff / freeze / transfer impact:

Disposition:
- PASS | PARTIAL | FAIL | SAFE UNKNOWN | HITL REQUIRED | STOP
- Action: preserve lesson | classify local | request history | escalate | quarantine | stop
- Evidence / unknowns:
```

Keep this separate from `CONTEXT SURVIVABILITY FINDINGS`, `TEMPORAL EVOLUTION FINDINGS`, `SOURCE LINEAGE FINDINGS`, `WORKFLOW DISCIPLINE FINDINGS`, and `CROSS-PROJECT TRANSFER FINDINGS`.

---

## 10. SAFE UNKNOWN

Record **SAFE UNKNOWN** when:

- lesson source cannot be named;
- historical authority cannot be established;
- operational lineage is fragmented;
- reuse boundary is unclear;
- archived files exist but lesson meaning is buried;
- tribal memory is the only evidence;
- prior reports mention a lesson without evidence or scope;
- continuity inheritance requires guessing.

**Action:** state what memory is missing, what would restore traceability, and whether the lesson is reusable, project-specific, partial, deprecated, HITL required, blocked, or SAFE UNKNOWN.

---

## 11. Non-Goals

- Do not redesign Triumph or any other project.
- Do not invent autonomous institutional AI.
- Do not create permanent memory systems.
- Do not claim perfect historical continuity.
- Do not define universal organizational law.
- Do not treat archives, reports, or documentation volume as institutional knowledge by default.
