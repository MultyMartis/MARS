# FP-0002 V7 PNG-GROUPED PAGE IMPLEMENTATION PROTOCOL

## Authority

1. Approved desktop PNG.
2. Approved mobile PNG.
3. Canonical Figma only for exact asset/text retrieval after visual identification.
4. Existing page source is implementation material, not authority.

## Mandatory pass opening

- Git preflight.
- New operator checkpoint backup.
- Confirmed target page and source.
- Confirmed PNG hashes.

## Group workflow

1. Select a small continuous visual group.
2. Create fresh desktop/mobile design crops.
3. Create runtime-before crops.
4. Produce visible text transcript.
5. Compare text, structure, count, assets and order.
6. Apply only targeted source changes.
7. Use existing partial only if anatomy matches.
8. Build.
9. Create runtime-after crops.
10. Desktop acceptance.
11. Mobile acceptance.
12. Commit only if every row is PASS.
13. Continue to next group.

## Prohibitions

- No stale extracted JSON as visual authority.
- No component-name assumptions.
- No whole-page blind assembly.
- No approximate Home block reuse.
- No invented copy.
- No omitted visible Lorem.
- No new root tokens.
- No destructive Git operations.
- No commit with acceptance FAIL.

## Page completion

- All groups COMPLETE.
- Full-page desktop/mobile screenshot.
- Functional QA.
- Regression QA.
- Stable source backup.
- Stable tag.
- Operator review.
