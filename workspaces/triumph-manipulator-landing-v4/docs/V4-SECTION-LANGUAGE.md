# Triumph Manipulator Landing V4 — Section Language

## 1. Purpose

This document defines how V4 should talk about sections before implementation begins.

The goal is to prevent false semantic certainty, screenshot worship, atmosphere laundering, and decorative redesign.

## 2. Source-Led Naming

V4 section names must be assigned after V1 source inspection.

Allowed temporary language:

- `screen-01` or `strip-01`
- `screen-02` or `strip-02`
- `screen-03` or `strip-03`
- `screen-04` or `strip-04`
- `first-screen shell`
- `header system`
- `hero content system`
- `proof/contact/footer system` only if source evidence supports it.

Forbidden temporary language:

- Names copied from V3 implementation.
- Names copied from V2 homepage flow.
- Marketing-improved names that imply unverified strategy.
- Component names that smuggle implementation decisions before source analysis.

## 3. Screen Structure Language

The V1 index authorizes only this high-level language:

- V1 is a four-part continuous landing scroll.
- `01.png` through `03.png` share indexed dimensions of 1672 x 941.
- `04.png` has indexed dimensions of 1536 x 1024.
- The natural order is `01` -> `02` -> `03` -> `04`.

V4 must not convert this into final semantic sections until visual content is inspected.

## 4. Cadence Language

Use cadence terms only when evidence exists:

- Visual density.
- CTA pressure.
- Proof rhythm.
- Transition from top offer to supporting content.
- Contact closure.
- Dark/light or image/content atmosphere shifts.

Until V1 raster inspection confirms them, these remain hypotheses and must be marked SAFE UNKNOWN.

## 5. Atmosphere Language

Atmosphere must describe source evidence, not desired mood.

Allowed:

- "V1 appears to use..." after visual inspection.
- "Source shows..." when directly visible.
- "SAFE UNKNOWN" when evidence is missing.

Forbidden:

- "Modernize."
- "Make cleaner."
- "SaaS-like."
- "Premium redesign."
- "Improve source intent."
- "Polish until it feels right."

## 6. Commercial Pressure Language

Commercial pressure must be source-bound.

Before implementation, identify from V1:

- Primary conversion point.
- Secondary conversion point.
- Trust/proof support.
- Regional/service claims.
- Pricing or timing claims.
- Repeated CTA rhythm.

No claim may be invented from a later version or implementation memory.

## 7. Header / Hero / Slider Language

Always preserve:

**HEADER != HERO != SLIDER**

Use these exact terms:

- Header system.
- First-screen shell.
- Hero content system.
- Hero background ownership.
- Future slider possibility.
- Mobile header ownership.
- Navigation survivability.

Do not collapse them into a generic `hero` unless V1 evidence proves a single inseparable system and the decision is documented.

## 8. Russian Typography Language

Russian typography survivability is an operational rule.

When V4 later creates HTML, required non-breaking examples include:

- `в&nbsp;Краснодаре`
- `с&nbsp;НДС`
- `от&nbsp;30&nbsp;минут`
- `и&nbsp;т.д.`
- `для&nbsp;юр.&nbsp;лиц`

This applies to source copy transfer, not only final styling.

## 9. Asset Language

Use "approved asset candidate" for files in `shared-assets/` until their placement is confirmed by V1 or operator instruction.

Use "approved asset used as-is" only when implementation references the exact existing file without transformation.

Use "derived asset" only when a new transformed asset is created and documented with source lineage, dimensions, and transformation reason.

## 10. SAFE UNKNOWN

Current section language SAFE UNKNOWN:

- Exact semantic section names.
- Exact atmosphere transitions.
- Exact commercial pressure rhythm.
- Exact reusable visual system placement.
- Exact content/copy locks.
- Exact responsive collapse rules.
