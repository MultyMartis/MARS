# Sidebar Telemetry Metadata Line Pass v1

## Почему boxed telemetry отклонена

Boxed/capsule-модель делала нижнюю строку визуально тяжелой и превращала каждую сущность sidebar в набор отдельных мини-виджетов. В результате telemetry начинала конкурировать с названием проекта или инструмента, а сама строка читалась как вложенная карточная структура вместо тихого operational metadata layer.

Ключевые причины отказа:
- отдельный border/background на каждом индикаторе создавал ложное ощущение интерактивных chips/buttons;
- равный визуальный вес всех счетчиков ломал иерархию строки;
- суммарная высота ряда росла и давала mini-card perception;
- Projects/Tools переставали восприниматься как grouped list внутри панели.

## Новая metadata-line модель

Telemetry закреплена как вторая строка сущности, но теперь оформляется по модели `icon + number   icon + number   icon + number   icon + number` без индивидуальных поверхностей у элементов.

Принципы модели:
- каждый индикатор остается семантическим, но не выглядит отдельным виджетом;
- у telemetry нет собственного card/chip языка;
- читаемость обеспечивается через компактный gap, табличные цифры, тихую прозрачность и семантический цвет;
- hover принадлежит строке целиком, а не отдельным telemetry items.

## Решение по иерархии строки

Структура строки сохранена двухуровневой:
- верхняя строка: semantic icon + title;
- нижняя строка: operational telemetry metadata.

Иерархическое правило прохода:
- title остается первичным объектом восприятия;
- telemetry визуально привязана к title через уменьшенный межстрочный зазор;
- общая поверхность строки ослаблена, чтобы панель читалась как operational list, а не как стек карточек;
- Projects сохранены чуть сильнее Tools через более заметный title/icon/surface вес.

## Порядок визуального приоритета telemetry

Принятый порядок приоритета:
1. Problems/warnings — самые заметные только при значении больше нуля.
2. Active tasks — заметные, но спокойнее problems.
3. Entity count — нейтральный базовый сигнал.
4. Completed/done — самые тихие и не должны доминировать даже при больших значениях.

Дополнительно:
- `problems = 0` уводится в muted neutral state без тревожного сигнала;
- completed остается тихим даже при высоком значении;
- новые цвета не вводятся, используется существующая палитра проекта.

## Remaining implementation notes

- Следующий визуальный проход стоит проверять уже по живому рендеру на предмет точного perceived density между Projects и Tools.
- Если telemetry все еще кажется слишком активной, ослаблять нужно сначала opacity и inter-pair gap, а не возвращать surfaces.
- Quick Access должен оставаться отдельным utility layer и не наследовать telemetry/card language.
- `#main_area`, shell geometry и Operational Interaction Layer v1 в этом проходе не меняются.
