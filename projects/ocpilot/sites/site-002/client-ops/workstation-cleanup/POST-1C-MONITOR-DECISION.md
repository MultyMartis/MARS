# Post_1C Monitor — Decision

## Chosen token

**POST_1C_MONITOR_KEEP_OPTIONAL_HYGIENE**

(Equivalent operational phrase historically: `KEEP_WINDOWS_HIDDEN_NONINTERACTIVE`.)

## Why

1. Server-side Client Ops completion dispatch + watchdog fully own **production reporting** Telegram authority.
2. Post_1C Catalog Monitor remains useful for **catalog/sitemap/onboarding hygiene** after 1C category changes — a different job than Client Ops.
3. Task is currently **Enabled / Ready**, hidden/noninteractive (self-hide runner), last observed healthy (2026-08-25).
4. It is **not** required for `SITE002_REPORTING_REQUIRES_OPERATOR_WORKSTATION=NO`.
5. Deleting it in this phase would exceed charter and remove optional hygiene without a replacement checklist.

## Not chosen

- `POST_1C_MONITOR_KEEP_REQUIRED` — Client Ops does not require it.
- `POST_1C_MONITOR_DELETE_RETIRED` — still provides non-Client-Ops hygiene value; not proven fully redundant for that role.
- `POST_1C_MONITOR_UNKNOWN_NEEDS_REVIEW` — role is clear enough for OPTIONAL_HYGIENE.

## This phase

**Do NOT delete** the monitor or its scripts/tasks.
