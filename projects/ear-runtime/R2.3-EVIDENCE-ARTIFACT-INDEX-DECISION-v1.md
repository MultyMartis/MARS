## Rationale

1. **Normative alignment** — [EAR-EVIDENCE-PACKAGE-v1.md](../../shared/external-access-runtime/EAR-EVIDENCE-PACKAGE-v1.md) requires an artifact index; [EAR-CONNECTOR-CONTRACT-v1.md](../../shared/external-access-runtime/EAR-CONNECTOR-CONTRACT-v1.md) requires connector `artifact_index` output — R2.3 maps both to `EvidenceArtifactIndex` without inventing acquisition-specific types.
2. **Model alignment** — R2.1 three-field `EvidenceArtifact` + `artifact_count` / `artifacts` tuple matches charter; no forbidden snapshot or quality fields.
3. **Status separation** — Package `connector_status` and per-artifact `status` documented with ART-ST-01–05; constants added to prevent enum overlap at R2.4.
4. **Invariants** — ART-INV-01–10 documented for R2.4 fail-closed checks; structural fields present; enforcement deferred appropriately.
5. **Minimal code change** — Taxonomy constants only; no generator/validator/persistence — scope respected.

**PASS WITH NOTES** (not bare **PASS**): index **assembly and validation are not implemented**; R1.6 mock pipeline still lacks `artifact_index`; quarantine ref format and hybrid `leg_ref` remain **Future** / **SAFE UNKNOWN**.

**FAIL** would apply if model omitted required index, mixed `package_quality_level` into artifacts, or contradicted EAR evidence spec — **none apply**.
