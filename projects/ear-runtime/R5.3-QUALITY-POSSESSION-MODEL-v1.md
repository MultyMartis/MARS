## Purpose

Define the canonical **Quality Possession** model — what **L0–L3** mean as R5 **certification concepts** at EAR Validate — as frozen dataclass models in `runtime/shared/quality_possession_models.py`.

Possession concept layer only: no Validate Engine, no R5-V-* rules, no scoring, no thresholds, no certification algorithms, no Publish execution.

**Critical disambiguation (mandatory):**

| Artefact | Stage | Numeric field | Meaning |
|----------|-------|---------------|---------|
| **R3 candidate** | Assembly | `package_quality_level: 0` | Honest **placeholder** — uncertified assembly |
| **R5 certified** | Validate pass | `certified_quality_level` 0–3 | Possession-**assessed honest claim** |
| **R4 published** | Publish | Frozen `package_quality_level` | Must match R5 certified — no inflation |

**Rule (VB-R3-06; Q-INV-R5-01):** R3 `package_quality_level: 0` is **NOT** R5 certified L0. Same numeric value, **different semantic stage**. R3 candidate quality is a placeholder. R5 certified quality is an assessed claim.

This milestone defines **what levels mean**. It does **not** define **how levels are earned**.

## Level hierarchy

```text
QualityPossessionRegistry
└── levels[]                         → QualityPossessionLevel
    ├── level_id                     → int (0–3; canonical constant)
    ├── description                  → QualityPossessionDescription
    │   ├── title
    │   └── purpose
    ├── ownership[]                  → what R5 certifies at this level (conceptual)
    └── non_goals[]

QualityPossessionReference           → lightweight pointer (level_id)

QualityPossessionAssessment          → conceptual record (no certification logic)
    ├── assessment_id
    ├── claim_stage                  → "candidate" | "certified"
    ├── level                        → QualityPossessionReference
    ├── target_level                 → optional declared certify target
    └── summary                      → operator-facing note slot
```

All types are **frozen** `@dataclass` instances. Immutable collections use `tuple`; `to_dict()` emits JSON-safe lists.

**Flat level set:** four peer levels L0–L3 — no nested sub-levels at R5.3. Future R5-V-* possession rules attach to level concepts and the **Possession** / **Quality** validation categories.

## Canonical registry

| Constant | `level_id` | Title | Normative source |
|----------|------------|-------|------------------|
| `QUALITY_LEVEL_L0` | **0** | Identity only | EAR-OPENCART-QUALITY-MAPPING § Level 0 |

### Per-level ownership (conceptual only)

#### L0 — Identity only

| Ownership (R5 certifies) | Non-goals |
|--------------------------|-----------|
| Site and package identity | Baseline diff capability |
| Environment class or explicit UNKNOWN | Structural file proof |
| Acquisition-log minimum audit fields | Extension or ocMod analysis |
| Safe-unknown honesty for all gaps | Scoring; R3 placeholder semantics |

**R3 role:** Assembles min metadata, environment, acquisition-log, safe-unknown listing all non-acquired sections.

#### L1 — Identity + structure

| Ownership (R5 certifies) | Non-goals |
|--------------------------|-----------|
| Version proof or explicit safe-unknown | Extension-inventory possession |
| File-manifest subset adequacy | ocmod-inventory possession |
| database-metadata or section safe-unknown | Comprehensive manifest |
| seo-structure or section safe-unknown | R3 section population rules |
| theme-info or section safe-unknown | Weighted quality indexes |

**R3 role:** Populates or gaps: file-manifest, database-metadata, seo-structure, theme-info.

#### L2 — Identity + structure + extensions

| Ownership (R5 certifies) | Non-goals |
|--------------------------|-----------|
| extension-inventory adequacy | Comprehensive path manifest |
| ocmod-inventory or section safe-unknown | Residual-only safe-unknown at L3 |
| Corroboration where architecture mandates | Full file contents in package |

**R3 role:** Optional placeholders / safe-unknown at R3 L1 engineering target.

#### L3 — Full read-only audit

| Ownership (R5 certifies) | Non-goals |
|--------------------------|-----------|
| Comprehensive manifest per scope policy | Full file contents in published package |
| Extension and integration indicators | Database row data in package |
| ocmod classification where possible | Live connector after Publish |
| database-metadata baseline indicators | Numeric completeness thresholds |
| safe-unknown is residual-only | Publish level freeze (**R4**) |

**R3 role:** Not R3 L1 engineering target.

### Candidate vs certified quality matrix (mandatory)

| Stage | Who sets | Field | Value | Meaning |
|-------|----------|-------|-------|---------|
| **R3 candidate** | **R3** | `metadata.package_quality_level` | **0** only | Uncertified assembly placeholder |
| **R5 Validate pass** | **R5** | `ValidationSummary.certified_quality_level` | **0–3** | Possession-assessed honest claim |
| **R4 Publish** | **R4** + operator | Store `package_quality_level` | Matches R5 | Frozen published claim — no inflation |

**Downgrade policy (conceptual):** R5 may certify a level **lower** than operator `target_certify_level` when possession is insufficient. **Inflation forbidden** (Q-INV-R5-02–05). Algorithms deferred to R5.7+.

## Ownership matrix

Classification: **R3** = assembly; **R5** = EAR Validate certification; **R4** = Publish; **R2** = evidence structural.

| Concern | Owner | R5 level model role |
|---------|-------|---------------------|
| Evidence shape valid | **R2** | Not represented — precondition |
| Handoff / assembly eligibility | **R3** | Not represented — precondition |
| Candidate `package_quality_level: 0` enforcement | **R3** | Distinct from certified L0 via `claim_stage` |
| Section skeleton presence | **R3** | Input to Structure/Possession categories — not level assignment |
| Section population / safe-unknown shape | **R3** | Input — R3-V-13/14 |
| Section possession adequacy for target | **R5** — **Possession** category | Feeds level assessment — not defined here |
| L0–L3 certification concept definitions | **R5** — this model | **Authoritative registry** |
| Certified `package_quality_level` assignment | **R5** — **Quality** category | Uses this registry + possession outcomes |
| Downgrade / inflation detection | **R5** — **Quality** category | Policy only — algorithms deferred |
| Published quality freeze | **R4** | Reads R5 certified level — must not exceed |
| `package_quality_level` on evidence | **Forbidden** | **R2** — absent by design |

### Boundary review answers

| Question | Answer |
|----------|--------|
| **What quality belongs to R3?** | Candidate assembly only: enforce `package_quality_level: 0`; populate sections or honest safe-unknown; skeleton presence; gap propagation shape. R3 does **not** certify possession levels. |
| **What quality belongs to R5?** | L0–L3 **certification concepts** (this model); section possession adequacy review (**Possession** category); certified level assignment and downgrade/inflation policy (**Quality** category); redaction; readiness inputs; consistency alignment. |
| **What quality belongs to R4?** | Publish execution; frozen published `package_quality_level` that must match R5 certified level; consumer-visible reference. R4 does **not** assess possession. |

Reviewed against [R3-CHARTER-v1.md](R3-CHARTER-v1.md), [R3.6-VALIDATION-BOUNDARY-REVIEW-v1.md](R3.6-VALIDATION-BOUNDARY-REVIEW-v1.md), [R5-CHARTER-v1.md](R5-CHARTER-v1.md) § Quality Ownership, [R5-IMPLEMENTATION-CHARTER-v1.md](R5-IMPLEMENTATION-CHARTER-v1.md) § R5.3.
