## Purpose

Define the **exact boundary** between:

- **R2 Evidence Validation** — structural and honesty checks at the **Evidence Package** boundary (pre-Validate gate input quality), and  
- **R5 Snapshot Validation** — contract, quality possession, redaction, and publish-readiness checks on **candidate / stored Snapshot Package** during EAR Validate.

This document exists to prevent validation overlap, quality inflation, and evidence/snapshot confusion **before** any `EvidencePackageValidator` code is written.

**Explicit exclusions:** validator implementation, generator, quarantine enforcement, persistence changes, snapshot generation, OpenCart sections, SITE-001, SFTP, acquisition, network.

## Authoritative validation ownership

| Stage | Program | Validator (when implemented) | Input artefact | Output meaning |
|-------|---------|------------------------------|----------------|----------------|
| **Pre-Validate structural gate** | **R2** | `EvidencePackageValidator` (R2.4 implementation milestone) | `EvidencePackage` logical model | Evidence is **contract-shaped and honest** — safe input to Validate transform |
| **Validate transform + snapshot gate** | **R5** (+ human HITL) | Validation Helpers (R5 backlog) | Evidence Package **read** + **candidate Snapshot Package** assembled by **R3** | Snapshot contract satisfied; quality possession honest; publish readiness per gates |
| **Section assembly** | **R3** | Snapshot Builder (not validation) | Validated evidence handoff | OpenCart sections populated — **not** R2 or R5 validation scope in this document |

Per [R2-CHARTER-v1.md](R2-CHARTER-v1.md) pipeline: Evidence Package → **EAR Validation (R5 + human)** → Snapshot Package. R2 validation runs **before** that boundary; R5 validation runs **at** Validate on snapshot-shaped output.

**Critical distinction:** R2 validates **evidence honesty and shape**. R5 validates **snapshot contract, quality, and publish gates**. R3 **builds** snapshot sections between them.

## R2 Validation Scope

What **R2 MUST validate** (Evidence Package boundary — structural + honesty). Fail closed unless noted.

### Identity block (`EvidenceIdentity`)

| Check ID | Requirement | Authority |
|----------|-------------|-----------|
| R2-V-01 | `acquisition_id`, `site_ref`, `connector_class` present and non-empty | INV-01; R2-IMPLEMENTATION-CHARTER |
| R2-V-02 | No forbidden identity fields (`evidence_id`, `site_id`, `snapshot_id`, `package_quality_level`) | INV-02; R2.2 |

### Provenance block (`EvidenceProvenance`)

| Check ID | Requirement | Authority |
|----------|-------------|-----------|
| R2-V-03 | `channel`, `started_at`, `operator_approval_ref` present and non-empty | R2-IMPLEMENTATION-CHARTER |
| R2-V-04 | `completed_at` present and non-empty when run is terminal (inferred from `connector_status` or generator flag) | R2-IMPLEMENTATION-CHARTER § Identity Model |
| R2-V-05 | **Do not** parse or certify ISO 8601 validity beyond non-empty string | R2.1 explicit exclusion |

### Scope echo (`EvidenceScopeEcho`)

| Check ID | Requirement | Authority |
|----------|-------------|-----------|
| R2-V-06 | Block present on package (structural — satisfied by model) | EAR-EVIDENCE-PACKAGE-v1 |
| R2-V-07 | `approved_scope` and `attempted_scope` fields accessible (lists/tuples — may be empty pending policy) | **SAFE UNKNOWN** minimum cardinality |

### Artifact index (`EvidenceArtifactIndex`)

| Check ID | Requirement | Authority |
|----------|-------------|-----------|
| R2-V-08 | Index present | ART-INV-01 |
| R2-V-09 | `artifact_count == len(artifacts)` | ART-INV-02 |
| R2-V-10 | Each entry: non-empty `artifact_type`, `artifact_ref`, `status` | ART-INV-03 |
| R2-V-11 | `artifact_ref` unique within index | ART-INV-04 |
| R2-V-12 | ≥1 entry with `artifact_type == manifest` OR explicit `safe-unknown` placeholder with documented rationale in warnings | ART-INV-05 |
| R2-V-13 | `artifact_type` ∈ canonical set (`identity`, `manifest`, `connector-output`, `log`, `metadata`, `safe-unknown`, `other`) | ART-INV-09 |
| R2-V-14 | No index entry paths matching OpenCart snapshot section prefixes (`file-manifest/`, `theme-info/`, etc.) | ART-INV-07 |
| R2-V-15 | **Do not** verify filesystem existence of `artifact_ref` | R2.3 reference rules |

### Connector status (`EvidenceStatus` + package carriers)

| Check ID | Requirement | Authority |
|----------|-------------|-----------|
| R2-V-16 | `connector_status` ∈ {`success`, `partial`, `failed`} | Model constants; R2-IMPLEMENTATION-CHARTER |
| R2-V-17 | Per-artifact `status` ∈ {`present`, `missing`, `partial`, `skipped`, `unknown`} | ART-INV-10 |
| R2-V-18 | Per-artifact `status` must not use connector enums (`success`, `failed`) | ART-ST-01 |
| R2-V-19 | When `connector_status == failed`, package must not claim success-only semantics (no empty errors when connector contract requires) | R2-IMPLEMENTATION-CHARTER; connector contract |
| R2-V-20 | `warnings` / `errors` present when applicable per connector contract | R2-IMPLEMENTATION-CHARTER |

### Evidence vs snapshot separation

| Check ID | Requirement | Authority |
|----------|-------------|-----------|
| R2-V-21 | Serialized package must not contain `package_quality_level` | R2-CHARTER forbidden |
| R2-V-22 | Serialized package must not contain snapshot section payloads or `snapshot_contract` | R2-IMPLEMENTATION-CHARTER |
| R2-V-23 | Serialized package must not contain OpenCart section tree paths as evidence content | R2 non-goals |

### Storage / serialization policy

| Check ID | Requirement | Authority |
|----------|-------------|-----------|
| R2-V-24 | No credential patterns in git-bound serialization (policy check on string fields — heuristic, not full secret scan) | R2-IMPLEMENTATION-CHARTER § Storage policy |
| R2-V-25 | Bulk refs opaque — **do not** resolve or fetch external paths in R2 validator | R2.3; no network |

### Explicit R2 non-validation (within R2 scope document)

R2 validator **must not**:

- Certify snapshot quality level  
- Validate OpenCart section contents  
- Approve Publish or consumer intake  
- Replace R5 Validate stage  
- Perform quarantine filesystem layout enforcement (R2.5)  
- Run acquisition or network I/O

## R5 Validation Scope

What **R2 must NEVER validate** — owned exclusively by **R5 Validation Helpers** (and human HITL at Validate), with **R3** responsible for assembly.

### Snapshot contract and identity

| Concern | R5 responsibility | R2 prohibition |
|---------|-------------------|----------------|
| `snapshot_id`, `snapshot_version` (`ear-snapshot-v1`) | R5 validates candidate snapshot | R2 must not require or emit |
| Snapshot metadata section completeness | R5 | R2 forbidden |
| Consumer handoff rules | R5 + R4 | R2 forbidden |

### Quality levels (L0–L3)

| Concern | R5 responsibility | R2 prohibition |
|---------|-------------------|----------------|
| `package_quality_level` assignment | R5 per [EAR-OPENCART-QUALITY-MAPPING-v1.md](../../shared/external-access-runtime/EAR-OPENCART-QUALITY-MAPPING-v1.md) | **Forbidden** on evidence — R2-V-21 |
| Level 1+ possession (`file-manifest`, `database-metadata`, `theme-info`, `seo-structure`) | R5 validates sections after R3 assembly | R2 checks index **ref** only, not section adequacy |
| Level 2+ (`extension-inventory`, `ocmod-inventory`) | R5 | R2 forbidden |
| Level 3 comprehensive manifest | R5 | R2 forbidden |
| Honest downgrade / max level from possession | R5 | R2 forbidden |

### Validate-stage gates

| Gate | Owner | R2 role |
|------|-------|---------|
| G1 — Acquire complete → Validate | R5 + operator | R2 may pre-check evidence shape only |
| G2 — Validate passed → Store | R5 | **None** — evidence pass ≠ G2 pass |
| G3 — Store → Publish | R5 + R4 | **None** |
| G4 — Publish readiness | R5 | **None** |
| PII/secrets in **candidate snapshot** | R5 | R2 checks evidence serialization policy only |
| `safe-unknown` completeness at snapshot | R5 | R2 does not certify snapshot gaps |
| Validate report / Publish allowed flag | R5 | R2 emits evidence validation result only — distinct artefact |

### Overlap prevention (authoritative)

| Concern | R2 validates | R5 validates |
|---------|--------------|--------------|
| Partial run visible | `connector_status` + scope echo + artifact statuses | Snapshot `safe-unknown` + operator downgrade |
| Manifest exists | Artifact **ref** in evidence index | `file-manifest/` section adequacy for Level 1+ |
| Operator approval | `operator_approval_ref` on evidence provenance | `operator_approval` in snapshot metadata |
| Quality claims | **Forbidden** on evidence | **Required** at snapshot Validate |
| Connector session outcome | `connector_status` enum + honesty | N/A — uses evidence as input |
| Artifact bytes / hashes | **Not** R2 (ref only) | Section-level hash/path rules at snapshot |

## Validation Invariants

Authoritative rules preventing overlap and quality inflation. Derived from architecture + R2 charters — **not** new policy.

| ID | Invariant | Authority |
|----|-----------|-----------|
| **VAL-INV-01** | **Evidence pass ≠ Snapshot pass** — R2 structural pass does not imply R5 Validate pass on candidate snapshot | R2-IMPLEMENTATION-CHARTER § Overlap avoidance; EAR-SNAPSHOT-LIFECYCLE-v1 |
| **VAL-INV-02** | **Evidence pass ≠ Publish approval** — no Publish gate may be satisfied by R2 alone | R2-CHARTER; EAR-READINESS-GATES-v1 |
| **VAL-INV-03** | **Evidence pass ≠ Quality level** — R2 pass must not set or imply `package_quality_level` ≥ 0 on snapshot | R2-CHARTER SC-05; forbidden at evidence stage |
| **VAL-INV-04** | **Artifact index integrity ≠ OpenCart quality** — valid index with manifest ref does not certify Level 1+ | R2.3 ART-ST-05; EAR-OPENCART-QUALITY-MAPPING-v1 |
| **VAL-INV-05** | **`connector_status: success` ≠ snapshot completeness** — connector success does not require all artifacts `present` (ART-ST-03) | R2.3 |
| **VAL-INV-06** | **`connector_status: partial` ≠ snapshot ready** — partial acquisition preserved; snapshot remains Level 0 / `safe-unknown` until R3+R5 | R2-IMPLEMENTATION-CHARTER binding rule 5 |
| **VAL-INV-07** | **`connector_status: failed` ≠ silent omission** — failed legs visible in evidence; must not produce complete snapshot claim without R5 downgrade | EAR-EVIDENCE-PACKAGE-v1 |
| **VAL-INV-08** | **Per-artifact `status` ≠ `connector_status`** — separate enums, separate semantics (ART-ST-01) | R2.3 |
| **VAL-INV-09** | **Evidence Package ≠ Snapshot Package** — validation transforms; does not rename types | EAR-EVIDENCE-PACKAGE-v1 |
| **VAL-INV-10** | **R2 validation runs on evidence model** — R5 validation runs on snapshot contract (+ evidence as provenance input) | R2-IMPLEMENTATION-CHARTER pipeline |
| **VAL-INV-11** | **Mock Store Level 0 honest** — evidence or R2 pass must not inflate mock persist quality | R2-CHARTER SC-05; N-03 |
| **VAL-INV-12** | **Manifest ref in index ≠ `file-manifest/` section** — logical evidence pointer vs OpenCart snapshot section | R2.3; R2 non-goals |
| **VAL-INV-13** | **R2 fail closed** — missing required identity/provenance/index/status → evidence invalid for Validate handoff | R2-IMPLEMENTATION-CHARTER |
| **VAL-INV-14** | **R5 fail closed on Publish** — uncertainty blocks consumer intake, not best-effort | EAR-READINESS-GATES-v1 |

## Model Implications

Review of `runtime/shared/evidence_package_models.py` — **documentation only**, no code changes in R2.4.

### Structural implications for future R2 validator

| Model element | Validation implication |
|---------------|---------------------|
| Frozen `@dataclass` aggregates | Validator receives immutable package; checks are read-only |
| `EvidenceIdentity` — 3× `str` | R2-V-01, R2-V-02 — non-empty and forbidden field scan on `to_dict()` |
| `EvidenceProvenance` — 4× `str` | R2-V-03, R2-V-04 — conditional `completed_at` |
| `EvidenceScopeEcho` — default empty tuples | R2-V-06 satisfied structurally; R2-V-07 **SAFE UNKNOWN** for semantic minimum |
| `EvidenceArtifactIndex.artifact_count` + `artifacts` | R2-V-08–R2-V-15 — count consistency, entry rules, taxonomy constants |
| `EvidenceArtifact` — type/ref/status | Enum checks against module constants L17–L31 |
| `EvidenceStatus.connector_status` | R2-V-16 — single enum field; constants L13–L15 |
| `EvidencePackage.warnings` / `errors` | R2-V-19, R2-V-20 — package-level tuples, not nested under status |
| `to_dict()` nesting | Validator may operate on dataclass fields or serialized dict — keys stable for forbidden-field scan |

### Constants as validation vocabulary

| Constant group | R2 validator use |
|----------------|------------------|
| `CONNECTOR_STATUS_*` | Allow-list for R2-V-16 |
| `ARTIFACT_STATUS_*` | Allow-list for R2-V-17; reject connector enums R2-V-18 |
| `ARTIFACT_TYPE_*` | Allow-list for R2-V-13 |

### Explicit non-implications (model does not require)

| Topic | Status |
|-------|--------|
| Datetime parsing | **Not implied** — docstring forbids |
| Filesystem I/O | **Not implied** — module docstring |
| Persistence / quarantine | **Not implied** — deferred R2.5 |
| Validation logic in model | **Explicitly deferred** — R2.1 L140; R2.4 implementation |
| `package_quality_level` field | **Absent by design** — R2 must reject if injected in dict |

### Gap between R1.6 mock and R2 model

| Item | Implication for R2.4 boundary |
|------|-------------------------------|
| R1.6 `evidence_models.py` still used by mock CLI | R2 validator targets **R2.1** `EvidencePackage` only; R1.6 not in R2 validation scope until R2.7 migration |
| R1.6 `quality_level` on evidence | Would fail R2-V-21 if present on R2 model serialization |
