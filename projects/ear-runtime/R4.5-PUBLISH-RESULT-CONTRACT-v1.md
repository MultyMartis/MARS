## Purpose

Define the canonical **PublishResult** contract — the sole authoritative R4 outcome of a **Publish attempt** — distinct from R5 certification artefacts, advisory recommendations, and the published snapshot promotion itself.

**Contract layer only:** no `publish_result_models.py`, no Publish Engine, no result builder, no gate automation, no CLI rendering, no filesystem emit path, no Store writes, no Publish execution.

**Critical disambiguation (mandatory):**

| Artefact | Role | PublishResult? |
|----------|------|----------------|
| **`ValidationResult`** | Authoritative R5 certification outcome — PASS / PASS WITH NOTES / FAIL | **No** — precondition citation only via `validation_result_ref` |
| **`PublishEligibilityRecommendation`** | R5 advisory Publish gate input — ELIGIBLE / ELIGIBLE WITH NOTES / NOT ELIGIBLE | **No** — gate citation only via `publish_recommendation_ref` |
| **`PublishedSnapshot`** / **`PublishedSnapshotReference`** | Consumer-visible promotion of validated snapshot — R4.1 aggregate | **No** — output citation only via `published_snapshot_ref` on SUCCESS |
| **`PublishMetadata`** | R4 publication facts — `published_at`, `published_by`, etc. | **No** — output citation only via `publish_metadata_ref` on SUCCESS |
| **`PublishResult`** | R4 aggregate **Publish attempt outcome** — SUCCESS / BLOCKED / DEFERRED | **Yes** — this contract |
| **Operator HITL decision** | Approve / defer / override with audit | **No** — referenced via `audit_ref`; not embedded as certification |

**Rule (PR-INV-R4-01):** `PublishResult.publish_result_state` records **promotion attempt outcome**. It **never substitutes** for `ValidationResult.summary.status`, **never executes** Validate, **never emits** Publish Eligibility Recommendation, **never embeds** `PublishedSnapshot` content, and **never certifies** quality possession.

## Position in the pipeline

```text
R5 Validate bundle (ValidationResult + ValidateReport + PublishEligibilityRecommendation)
        ↓
Store — stored-unpublished validated snapshot (R1.8 layout)
        ↓
Operator HITL #1 — Validate sign-off (mandatory pilot)
        ↓
Operator HITL #2 — Publish approval (mandatory pilot)
        ↓
R4 Publish attempt (future R4.7)
        ↓
PublishResult  ← THIS CONTRACT — attempt outcome only
        ↓
On SUCCESS only:
  PublishedSnapshotReference + PublishMetadata + publish_state: published + visibility grant
        ↓
Consume (consumer programs — not R4)
```

**R5 answers:** *Is this snapshot certified and advisedly publishable?*  
**R4 Publish attempt answers:** *Did the promotion gate execute successfully, get blocked, or get deferred?*

PublishResult sits **after** a Publish **attempt** and **before** consumer intake. It is **not** a Validate outcome, **not** a recommendation, **not** the published snapshot tree, and **not** a deployment command.

## PublishResult top-level contract

```text
PublishResult
├── publish_result_id              → stable result identifier (generation algorithm: SAFE UNKNOWN)
├── publish_result_state           → SUCCESS | BLOCKED | DEFERRED (exactly one)
├── summary                        → operator-first one-line attempt outcome statement
├── published_snapshot_ref         → PublishedSnapshot / reference id (SUCCESS primary; absent on BLOCKED/DEFERRED)
├── publish_metadata_ref           → PublishMetadata / reference id (SUCCESS primary; absent on BLOCKED/DEFERRED)
├── validation_result_ref          → ValidationResult.result_id (mandatory precondition linkage)
├── publish_recommendation_ref     → PublishEligibilityRecommendation.recommendation_id (mandatory gate linkage)
├── notes[]                        → non-blocking context, gate checklist items, deferral rationale
├── audit_ref                      → Publish attempt audit record — HITL refs, gate satisfaction, timestamps
├── snapshot_id                    → target snapshot id (audit convenience — unchanged citation key)
├── generated_at                   → ISO 8601 timestamp (conventional)
└── boundary_declaration           → fixed text: result records attempt outcome; no side effects by itself
```

**Invariant (PR-INV-R4-02):** Every canonical PublishResult **must** link to exactly one `ValidationResult` via `validation_result_ref` and exactly one `PublishEligibilityRecommendation` via `publish_recommendation_ref`. The result **records** gate context at attempt time — it does **not** re-run Validate or regenerate recommendation.

**Invariant (PR-INV-R4-03):** Exactly **three** publish result states exist. No fourth state, no numeric score, no percentage, no implicit Publish approval from prior R5 artefacts.

**Invariant (PR-INV-R4-04):** On **SUCCESS**, `published_snapshot_ref` and `publish_metadata_ref` **must** be present. On **BLOCKED** and **DEFERRED**, those output refs **must** be absent — no partial publish state.

## Publish result state definitions

### SUCCESS

| Field | Definition |
|-------|------------|
| **Meaning** | R4 Publish attempt **completed**. Publish gate executed: publish metadata assigned, `publish_state` transitioned to **published**, consumer visibility grant issued per R4.3. Snapshot remains read-only promotion — no section mutation. |
| **Ownership** | State semantics **R4.5**; execution logic **R4.7** (future); outcome authority **R4** — distinct from R5 |
| **Expected upstream relationship** | Requires R5 bundle present at attempt: `ValidationResult` not FAIL (default path); `PublishEligibilityRecommendation` not NOT_ELIGIBLE (default path); operator Publish HITL approval recorded in `audit_ref`; Store placement confirmed or equivalent in-memory path flagged |
| **Output refs** | `published_snapshot_ref` → R4.1 aggregate or lightweight reference; `publish_metadata_ref` → R4.4 aggregate or reference |
| **Quality semantics** | **Does not certify quality.** SUCCESS confirms promotion and metadata freeze only — certified level already assigned by R5 and frozen on R4.1 aggregate |
| **Non-goals** | Does not re-validate; does not upgrade quality; does not imply consumer intake execution (Consume is separate); does not substitute for `ValidationResult` PASS |

---

### BLOCKED

| Field | Definition |
|-------|------------|
| **Meaning** | Publish attempt **did not execute** — fail closed. No `publish_state` transition; no publish metadata assignment; no visibility grant. Snapshot remains **stored-unpublished** (or pre-attempt state). |
| **Ownership** | State semantics **R4.5**; block reasons recorded in `notes[]` and `audit_ref`; R5 artefacts **unchanged** |
| **Typical causes** | `ValidationResult` FAIL (default path); `PublishEligibilityRecommendation` NOT_ELIGIBLE (default path); missing operator Publish HITL approval; mock `snapshot_id` on production path; Store placement unconfirmed; forbidden transition per R4.2 (e.g. candidate-only input); operator declined without deferral |
| **Validation failure implication** | **BLOCKED does not imply validation failure.** A snapshot may have R5 PASS + ELIGIBLE recommendation and still receive BLOCKED — e.g. missing Publish HITL, storage unconfirmed, or operator declined. Conversely, ValidationResult FAIL typically causes BLOCKED — but the result state is **Publish blocked**, not **Validate failed** |
| **Output refs** | `published_snapshot_ref` and `publish_metadata_ref` **absent** |
| **Non-goals** | Does not mutate ValidationResult; does not change recommendation retroactively; does not quarantine evidence; does not repair snapshot; override-with-audit is operator action **after** BLOCKED emission — separate record |

---

### DEFERRED

| Field | Definition |
|-------|------------|
| **Meaning** | Publish attempt **suspended** — operator or pipeline deferred decision. No publish state transition; no metadata assignment; no visibility grant. Distinct from BLOCKED: deferral implies **may retry** when preconditions satisfied — not a hard fail-closed terminal rejection. |
| **Ownership** | State semantics **R4.5**; deferral rationale in `notes[]` and `audit_ref`; operator owns retry timing |
| **Typical causes** | Publish HITL pending (approval not yet recorded); storage placement confirmation pending; operator explicitly chose "defer" without declining; combined Store+Publish workflow awaiting Store step; transient infrastructure uncertainty — **SAFE UNKNOWN** detail at implementation |
| **Why required** | Without DEFERRED, pipelines conflate *waiting* with *rejected*. Validate HITL and Publish HITL are distinct gates — between them and at Publish approval, **pending is not failure**. BLOCKED would misrepresent operator intent and prevent clean retry semantics without falsely implying validation or eligibility failure |
| **Output refs** | `published_snapshot_ref` and `publish_metadata_ref` **absent** |
| **Non-goals** | Does not auto-retry Publish; does not extend Validate validity; does not bypass NOT_ELIGIBLE on retry without operator override or re-Validate |

## Default gate → state mapping (Publish attempt)

| Gate condition at attempt | Default `publish_result_state` | Notes |
|---------------------------|--------------------------------|-------|
| All preconditions + Publish HITL + execution complete | **SUCCESS** | Output refs populated |
| ValidationResult FAIL (default path) | **BLOCKED** | `validation_result_ref` cites FAIL outcome — Publish blocked, not re-recorded as Validate |
| PublishEligibilityRecommendation NOT_ELIGIBLE (default path) | **BLOCKED** | Fail closed per R5.6; operator override is separate audited action |
| Missing Publish HITL approval (pilot mandatory) | **BLOCKED** or **DEFERRED** | **DEFERRED** when approval explicitly pending; **BLOCKED** when declined |
| Store placement unconfirmed | **DEFERRED** or **BLOCKED** | **DEFERRED** when confirmation in progress |
| Mock `snapshot_id` on production path | **BLOCKED** | R1.8B mock boundary |
| Operator explicit deferral | **DEFERRED** | No state transition |
| Operator explicit decline | **BLOCKED** | Fail closed |

**Rule (PR-MAP-R4-01):** Mapping is **attempt-outcome** advisory at contract layer. Exact dispatch logic deferred to **R4.7** Publish Engine. PublishResult state **must not** upgrade or downgrade `ValidationResult.summary.status`.

## Mandatory disambiguation review

### 1. Why PublishResult ≠ ValidationResult

| Dimension | **ValidationResult (R5)** | **PublishResult (R4)** |
|-----------|---------------------------|------------------------|
| **Question answered** | *Is the snapshot contract-certified?* | *Did the Publish attempt succeed, block, or defer?* |
| **Program stage** | EAR Validate | R4 Publish attempt |
| **Outcome states** | PASS / PASS WITH NOTES / FAIL | SUCCESS / BLOCKED / DEFERRED |
| **Owner** | **R5** | **R4** |
| **Quality** | Certifies possession (R5.3 logic at R5.7) | **Does not certify** — cites R5 via ref only |
| **Consumer visibility** | **Never** grants | SUCCESS records promotion refs only |
| **Timing** | Pre-Store / at Validate | Post–Validate-sign-off, at Publish attempt |

Per PR-INV-R4-01: R5 PASS **≠** PublishResult SUCCESS. Validate may pass while Publish is BLOCKED (missing HITL) or DEFERRED (pending approval).

### 2. Why PublishResult ≠ PublishEligibilityRecommendation

| Dimension | **PublishEligibilityRecommendation (R5.6)** | **PublishResult (R4.5)** |
|-----------|---------------------------------------------|--------------------------|
| **Question answered** | *May this snapshot be considered for Publish?* | *What happened when Publish was attempted?* |
| **Nature** | **Advisory** — pre-Publish gate signal | **Outcome record** — post-attempt result |
| **States** | ELIGIBLE / ELIGIBLE WITH NOTES / NOT ELIGIBLE | SUCCESS / BLOCKED / DEFERRED |
| **Owner** | **R5** emits | **R4** emits |
| **HITL** | Informs operator before Publish decision | Records attempt after operator action |
| **Execution** | **Never** publishes | Records whether Publish **executed** |

ELIGIBLE recommendation **≠** PublishResult SUCCESS (PE-INV-R5-01; VAL-INV-02). Recommendation is consumed as precondition; PublishResult is emitted **after** attempt.

### 3. Why PublishResult ≠ PublishedSnapshot

| Dimension | **PublishedSnapshot (R4.1)** | **PublishResult (R4.5)** |
|-----------|------------------------------|--------------------------|
| **What it is** | Consumer-visible **promotion aggregate** — identity, frozen sections citation, metadata, visibility | **Attempt outcome envelope** — success/blocked/deferred + refs |
| **Content** | Cites immutable OpenCart tree + publish markers | **No section content** — refs only on SUCCESS |
| **Exists when** | Only after successful Publish | After **every** attempt — including BLOCKED and DEFERRED |
| **Consumer use** | Intake citation key | Operator / pipeline audit — not consumer intake target |
| **Reuse forbidden** | PublishResult must not embed or substitute PublishedSnapshot | `published_snapshot_ref` is opaque pointer only |

PublishedSnapshot is the **product** of successful Publish; PublishResult is the **receipt** of the attempt.

### 4. Why SUCCESS does not certify quality

| Reason | Authority |
|--------|-----------|
| **Certification vs promotion** — Quality possession assessed at Validate (R5); Publish **freezes** certified claim on R4.1 aggregate | R5.3; R4-CHARTER § Why R4 does not own quality |
| **SUCCESS semantics** — Records gate execution and output refs — not possession re-assessment | PR-INV-R4-01; ST-IC-R4-05 |
| **Field absence** — PublishResult carries **no** `certified_quality_level`; quality lives on ValidationResult and R4.1 freeze field | R5.1; R4.1 |
| **Inflation prevention** — Only R5 assigns L0–L3; R4 matching validated level at SUCCESS — no upgrade | Q-INV-R5-01–05 |
| **Operator confusion risk** — Treating SUCCESS as quality pass would collapse R5/R4 boundaries | VB-R5-07; R4.8 reserved |

**Critical invariant:** PublishResult SUCCESS means *promotion executed* — not *quality certified* or *quality improved*.

### 5. Why BLOCKED does not imply validation failure

| Scenario | ValidationResult | PublishEligibilityRecommendation | PublishResult |
|----------|------------------|-----------------------------------|---------------|
| Validate FAIL | **FAIL** | typically NOT_ELIGIBLE | **BLOCKED** |
| Validate PASS, missing Publish HITL | **PASS** | ELIGIBLE | **BLOCKED** or **DEFERRED** |
| Validate PASS, NOT_ELIGIBLE | **PASS** (edge — policy) | **NOT_ELIGIBLE** | **BLOCKED** |
| Validate PASS, operator declined Publish | **PASS** | ELIGIBLE | **BLOCKED** |
| Validate PASS, storage unconfirmed | **PASS** | ELIGIBLE | **DEFERRED** or **BLOCKED** |

**Rule (PR-INV-R4-05):** `publish_result_state: BLOCKED` means **Publish did not execute** — not **Validate failed**. Consumers of PublishResult **must** inspect `validation_result_ref` separately for certification outcome. A pipeline may show green Validate and red Publish — that is **correct** separation.

### 6. Why DEFERRED is required

| Without DEFERRED | Problem |
|------------------|---------|
| Pending Publish HITL mapped to BLOCKED | False rejection — operator still intending to approve |
| Storage confirmation wait mapped to BLOCKED | Retry conflated with hard gate failure |
| Dual HITL workflow | Validate complete but Publish paused — neither success nor failure |
| Operator "defer" action | No honest state — forced into BLOCKED misrepresents intent |
| Pipeline orchestration | Cannot distinguish **wait** from **deny** for scheduling and retry |

DEFERRED preserves **lifecycle honesty**: preconditions may be satisfied on R5 side while R4 attempt is **incomplete**, not **forbidden**. Retry emits a **new** PublishResult — prior DEFERRED record remains immutable audit history.

## Boundary rules (mandatory)

PublishResult contract **MUST NOT**:

| Prohibition | Owner preserved |
|-------------|-----------------|
| Substitute for ValidationResult as certification authority | **R5.1** |
| Substitute for PublishEligibilityRecommendation as advisory authority | **R5.6** |
| Embed or reuse PublishedSnapshot as outcome record | **R4.1** |
| Assign or upgrade certified quality level | **R5.3** |
| Re-run Validate or emit Validate findings | **R5** |
| Emit Publish Eligibility Recommendation | **R5.6** |
| Mutate snapshot, evidence, quarantine, or Store | **R3** / **R2** / **R1.8** |
| Imply consumer intake without SUCCESS + separate Consume | **Consumer programs** |
| Conflate BLOCKED with ValidationResult FAIL | **R5** vs **R4** separation |

PublishResult **MAY**:

| Permission | Constraint |
|------------|------------|
| Reference R5 artefacts | Via mandatory refs — not embedded objects |
| Reference R4 outputs on SUCCESS | Via `published_snapshot_ref`, `publish_metadata_ref` |
| Record gate and HITL context | In `notes[]` and `audit_ref` |
| State SUCCESS / BLOCKED / DEFERRED | Exactly three states |
