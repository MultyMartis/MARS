## Purpose

Define the canonical **Publish Engine** architecture — the future R4 orchestrator that coordinates EAR Publish execution flow, gate verification, promotion assembly, and outcome emission.

**Architecture layer only:** no `ear_publish_engine.py`, no CLI (`--publish-snapshot`), no Store adapter, no persistence, no builders, no gate automation product, no consumer program integration.

**Critical disambiguation (mandatory):**

| Artefact | Role | Publish Engine? |
|----------|------|-----------------|
| **Publish Engine** | Orchestration — entry gate, eligibility verification, HITL verification, promotion assembly, outcome emission | **Yes** — this document |
| **Publish Flow gates G1–G6** | Ordered fail-closed gate semantics per R4.6 | **Implements** — Stages 1–7 map to G1–G6 |
| **Published Snapshot model** | Consumer-visible promotion aggregate per R4.1 | **Assembles** — Stage 4 (promotion citation only) |
| **Publish Metadata model** | R4-owned publication facts per R4.4 | **Attaches** — Stage 5 |
| **Consumer Visibility model** | Logical visibility grant per R4.3 | **Grants** — Stage 6 |
| **PublishResult contract** | R4 attempt outcome per R4.5 | **Emits** — Stage 7 |
| **ValidationResult** | R5 authoritative certification outcome | **Consumes** — Stage 2; **never re-emits** |
| **ValidateReport** | R5 operator audit companion | **Consumes** — Stage 2 context; **never regenerates** |
| **PublishEligibilityRecommendation** | R5 advisory Publish gate | **Consumes** — Stage 2; **never emits** |
| **R5 Validate Engine** | Contract certification orchestrator | **Forbidden** — upstream only |
| **R3 snapshot assembly** | OpenCart section population from evidence | **Forbidden** |
| **Consumer intake execution** | OCPilot Run 5 / consumer programs | **Forbidden** |

**Rule (PE-INV-R4-01):** Publish Engine **orchestrates** R4 Publish. It **owns execution flow, gate verification, promotion assembly orchestration, and outcome emission**. It **does not own** validation categories, quality possession concepts, snapshot section assembly, evidence lifecycle, consumer program execution, or recommendation state definitions — those remain owned by R5, R3, R2, and consumer programs respectively.

```text

        ↓
R5 Validate (R5.7 Validate Engine — future)
        ↓
ValidationResult + ValidateReport + PublishEligibilityRecommendation
        ↓
Operator HITL #1 — Validate sign-off (mandatory pilot)     ← PRECONDITION
        ↓
Store — stored-unpublished validated snapshot (R1.8)
        ↓
╔═══════════════════════════════════════╗
║  Publish Engine (R4.7 architecture)    ║
║  Stage 1–7 orchestration                ║
║  NO Validate, NO assembly, NO evidence  ║

PublishResult + on SUCCESS: PublishedSnapshot + visibility grant
```

**PublishResult (Stage 7) answers:** *What was the Publish attempt outcome?*

## Canonical stages

Seven stages — ordered execution. Stages **must not** be skipped on the default path. Stages 1–3 may early-exit to Stage 7 with **BLOCKED** or **DEFERRED** without entering Stages 4–6.

```text
Stage 1  Preconditions
    ↓
Stage 2  Eligibility Verification
    ↓
Stage 3  HITL Verification
    ↓
Stage 4  Publish Assembly
    ↓
Stage 5  Metadata Attachment
    ↓
Stage 6  Visibility Grant
    ↓
Stage 7  Publish Result Emission   ← terminal for every attempt
```

### Stage → Publish Flow gate crosswalk

| Engine stage | Publish Flow gate | R4.6 authority |
|--------------|-------------------|----------------|
| **Stage 1** | **G1** Validated Snapshot Available | PF G1 definition |
| **Stage 2** | **G2** ValidationResult + **G3** Publish Eligibility | PF G2, G3 |
| **Stage 3** | **G4** Operator HITL Publish Approval | PF G4 |
| **Stages 4–6** | **G5** Publish Execution (decomposed) | PF G5 |
| **Stage 7** | **G6** PublishResult Emission | PF G6 |

### Stage 1 — Preconditions

| Field | Value |
|-------|-------|
| **Purpose** | Entry gate — verify Publish may proceed; confirm validated snapshot availability, R5 bundle presence, and lifecycle preconditions |
| **Owner** | **R4** owns orchestration verification; **R3** owns snapshot content; **R1.8** / **operator** owns Store placement; **R5** owns validated marker semantics |
| **Inputs** | Validated `SnapshotPackage` (PE-I-01); `snapshot_id`, `site_id`, `acquisition_id` (PE-I-06); Store path or in-memory flag (PE-I-07); R5 bundle refs linkable to same `snapshot_id` (PE-I-02–04); optional Validate sign-off ref (PE-I-11) |
| **Outputs on pass** | `PreconditionContext` (conceptual) — gate satisfaction record; flow may proceed to Stage 2 |
| **Fail-closed behavior** | **Stop** — Stages 2–6 not entered. Route to Stage 7 with **PublishResult** **BLOCKED** (candidate-only, missing snapshot, id mismatch, mock `snapshot_id` on production path, missing R5 bundle) or **DEFERRED** (Store placement in progress) |

**Checks (orchestration only):**

| Check | Mandatory? | Fail-closed behavior |
|-------|------------|----------------------|
| Validated snapshot present — not candidate-only | **Yes** | BLOCKED — no Publish |
| R5 bundle present (`ValidationResult`, `PublishEligibilityRecommendation`; `ValidateReport` when policy requires) | **Yes** | BLOCKED |
| `snapshot_id` matches across snapshot, Store, and R5 refs | **Yes** | BLOCKED |
| `publish_state` is **stored_unpublished** (R4.2) or equivalent pre-Publish | **Yes** (default production) | BLOCKED or DEFERRED |
| Mock `snapshot_id` on production path | **Reject** | BLOCKED |
| Validate HITL sign-off ref present (pilot policy) | **When required** | DEFERRED or BLOCKED per operator policy — **SAFE UNKNOWN** |
| In-memory validated path | **Pilot flag only** | Allowed when explicitly flagged; production default requires Store |

**Non-goals:** Does not validate snapshot content (R5); does not write Store (R1.8); does not assemble OpenCart sections (R3).

### Stage 2 — Eligibility Verification

| Field | Value |
|-------|-------|
| **Purpose** | Confirm R5 certification outcome and advisory Publish gate permit Publish consideration on the default path — consumption only, no re-Validate |
| **Owner** | **R5** owns `ValidationResult`, `ValidateReport`, `PublishEligibilityRecommendation`; **R4** consumes and verifies — **never substitutes or regenerates** |
| **Inputs** | `ValidationResult` (PE-I-02); `ValidateReport` (PE-I-03); `PublishEligibilityRecommendation` (PE-I-04); optional NOT_ELIGIBLE override audit (PE-I-12) |
| **Outputs on pass** | Eligibility verification record; gate G2/G3 satisfaction; flow may proceed to Stage 3 |
| **Fail-closed behavior** | **Stop** at Stage 2 on default path when `ValidationResult` status is **FAIL** or recommendation is **NOT_ELIGIBLE** without audited override. Route to Stage 7 — **PublishResult** **BLOCKED**. R5 artefacts **unchanged** |

**Default accept criteria:**

| R5 artefact | Accept (default path) | Block |
|-------------|----------------------|-------|
| `ValidationResult.summary.status` | `PASS` or `PASS_WITH_NOTES` | **FAIL** |
| `PublishEligibilityRecommendation.recommendation_state` | `ELIGIBLE` or `ELIGIBLE_WITH_NOTES` | **NOT_ELIGIBLE** without override |
| `ValidateReport` | Present when policy requires; coherent with `ValidationResult` | Broken ref / incoherent bundle |

**Rules:**

| ID | Rule |
|----|------|
| PE-MAP-R4-01 | ValidationResult **FAIL** → default **BLOCKED** — Publish blocked, not re-recording Validate (PR-INV-R4-05) |
| PE-MAP-R4-02 | **NOT_ELIGIBLE** → default **BLOCKED** — override requires separate audited operator action (PE-INV-R5-01) |
| PE-MAP-R4-03 | **ELIGIBLE** / **ELIGIBLE_WITH_NOTES** **≠** Publish approval — Stage 3 still mandatory |
| PE-MAP-R4-04 | Engine **reads** certified level from ValidationResult — does **not** assign or upgrade |

**Non-goals:** Does not re-run Validate; does not emit ValidationResult or recommendation; does not treat ValidateReport as re-validation authority.

### Stage 3 — HITL Verification

| Field | Value |
|-------|-------|
| **Purpose** | Require explicit operator Publish approval — distinct from Validate sign-off (HITL #1) and distinct from R5 ELIGIBLE signal |
| **Owner** | **Operator** owns decision; **R4** records approval ref in attempt audit — not embedded as certification |
| **Inputs** | Stages 1–2 satisfied; `operator_publish_approval_ref` (PE-I-08); `consumer_target` declared (PE-I-09); on ELIGIBLE_WITH_NOTES: operator note acknowledgment recorded |
| **Outputs on pass** | Approval ref captured in audit context; flow may proceed to Stage 4 |
| **Fail-closed behavior** | **Stop** without Stages 4–6 when approval absent or declined. Route to Stage 7 — **PublishResult** **BLOCKED** (declined / terminal absent) or **DEFERRED** (approval pending) |

**Non-goals:** Does not auto-approve from ELIGIBLE; does not substitute Validate sign-off; does not execute promotion (Stages 4–6).

**Critical:** Stage 3 is **Publish HITL only**. Validate sign-off is a **precondition** checked at Stage 1 — mandatory before Publish entry, **not** a substitute for Stage 3 (PF-INV-R4-04).

### Stage 4 — Publish Assembly

| Field | Value |
|-------|-------|
| **Purpose** | Compose **`PublishedSnapshot` promotion aggregate** — cite validated snapshot read-only, set `publish_state` to **published**, wire identity and publication refs — **no OpenCart section mutation** |
| **Owner** | **R4** owns promotion assembly orchestration; **R3/R5** own frozen section content; **forbidden:** R3 section writers, evidence generators |
| **Inputs** | Stages 1–3 satisfied; validated `SnapshotPackage` read-only citation; R4.1 contract field requirements; certified quality level **read** from R5 (freeze at Stage 5); `operator_publish_approval_ref`; R5 bundle opaque refs |
| **Outputs on pass** | In-memory `PublishedSnapshot` skeleton — identity, cited `snapshot`, publication block with `publish_state: published`, opaque R5 refs |
| **Fail-closed behavior** | Assembly error or forbidden mutation detected → abort Stages 5–6; route to Stage 7 — **PublishResult** **BLOCKED** — no partial publish state (PR-INV-R4-04) |

**Terminology (mandatory):**

| Term | Meaning | Owner |
|------|---------|-------|
| **R3 snapshot assembly** | Populate OpenCart sections from evidence | **R3 — FORBIDDEN** at Publish Engine |
| **Publish assembly (Stage 4)** | Compose R4.1 `PublishedSnapshot` promotion aggregate from **existing** validated tree | **R4 — ALLOWED** orchestration only |

**Stage 4 does not:** populate sections; repair snapshot content; read quarantine as publish source; re-validate; assign certified quality.

### Stage 7 — Publish Result Emission

| Field | Value |
|-------|-------|
| **Purpose** | Emit the sole authoritative R4 **Publish attempt outcome** — always after attempt boundary (executed, blocked before execution, or deferred) |
| **Owner** | **R4** owns PublishResult emission per R4.5; **R5** artefacts remain unchanged |
| **Inputs** | Gate satisfaction record for Stages 1–6 path taken; mandatory refs: `validation_result_ref`, `publish_recommendation_ref`; `audit_ref` with HITL and gate checklist; on SUCCESS: `published_snapshot_ref`, `publish_metadata_ref` |
| **Outputs** | `PublishResult` with exactly one of **SUCCESS**, **BLOCKED**, **DEFERRED** per R4.5 |
| **Fail-closed behavior** | Engine **must not** skip PublishResult emission. Every Publish **attempt** produces exactly one result — including blocked and deferred paths. Stage 7 is **terminal** |

**Non-goals:** Does not embed full PublishedSnapshot in PublishResult; does not substitute ValidationResult; does not trigger consumer Consume.

**Why terminal:** PublishResult records *what happened* at the attempt boundary. Stages 1–6 produce intermediate promotion artefacts; Stage 7 is the **only** authoritative outcome record for the attempt (see § Mandatory answers #6).

## Mandatory answers

### 1. Why Publish Engine cannot validate

| Reason | Authority |
|--------|-----------|
| **Ownership** — Contract certification, category dispatch, quality possession assessment, redaction review — **R5 exclusive** | R5-CHARTER § Quality Ownership; VB-R5-07 |
| **Artefact stage** — Engine consumes **already emitted** `ValidationResult`; re-validation at Publish duplicates R5 and blurs boundaries | R3.6 VB-R3-01; R5.8 VB-R5-01 |
| **Program label** — **R5 EAR Validate** certifies; **R4 Publish** promotes — distinct orchestrators | N-R3R-08; PE-INV-R4-01 |
| **Mandatory refs** — PublishResult requires `validation_result_ref` — engine confirms, does not regenerate | PR-INV-R4-02 |
| **Fail closed at wrong layer** — Validate failure blocks at Stage 2; Publish must not re-run certification | PF G2; ST-R4-01 |
| **No R2/R3 pass substitution** — Structural or assembly pass ≠ R5 certification | VAL-INV-01; VB-R3-01 |

### 2. Why Publish Engine cannot certify quality

| Reason | Authority |
|--------|-----------|
| **Certification vs promotion** — Quality possession assessed at Validate (R5); Publish **freezes** certified claim only | R5.3; R4-CHARTER § Why R4 does not own quality |
| **Inflation prevention** — Only R5 assigns certified L0–L3; Stage 5 matching validated level allowed; upgrade **forbidden** | Q-INV-R5-01–05 |
| **Semantic stages** — R3 candidate L0 ≠ R5 certified L0 ≠ R4 published L0 (frozen claim) | R5.3 § Candidate vs certified |
| **Possession rules live in R5** — Section adequacy, safe-unknown completeness, downgrade paths | R5.2 Quality/Possession categories |
| **Stage 5 action** — Engine **reads** `certified_quality_level` from ValidationResult; does not re-run possession checks | PE-MAP-R4-04; ST-IC-R4-05 |

### 3. Why Publish Engine cannot assemble snapshots (R3 sense)

| Reason | Authority |
|--------|-----------|
| **R3 ownership** — OpenCart section population from evidence is **R3 Candidate Snapshot Generator** scope | R3-CHARTER § Scope; R3.3 assembly rules |
| **Lifecycle freeze** — Validated snapshot section tree is **immutable** at Publish — R4 read-only citation | R4.1 PS-INV-R4-03; ST-R4-06 |
| **Terminology disambiguation** — Stage 4 **Publish Assembly** composes R4.1 **promotion aggregate** — not R3 evidence→section assembly | This document § Stage 4 |
| **Evidence forbidden** — Engine must not read quarantine as publish target or repackage evidence | R2.6 HO-FORBID-07; R4-CHARTER non-inputs |
| **No repair path** — Corrections require new acquisition → new `snapshot_id` | R1.8B immutability |

**Note:** Stage 4 **may** orchestrate assembly of the **`PublishedSnapshot` object** from existing validated content. Stage 4 **must not** orchestrate **R3 snapshot assembly** (section writers, evidence mapping, safe-unknown population from evidence).

### 4. Why Publish Engine cannot bypass HITL

| Reason | Authority |
|--------|-----------|
| **Stage 3 mandatory** — Stages 4–6 **must not** run without `operator_publish_approval_ref` | PF-INV-R4-04; SC-R4.6-03 |
| **Advisory ≠ execution** — ELIGIBLE recommendation informs Stage 2 only; does not authorize promotion | PE-INV-R5-01; PE-MAP-R4-03 |
| **Dual HITL** — Validate sign-off (precondition) and Publish approval (Stage 3) are **distinct** | R4.6 § Dual HITL |
| **Backlog non-goal** — Unattended auto-Publish **forbidden** | ST-IC-R4-10; EAR-RUNTIME-BACKLOG-v1 § R4 |
| **Audit honesty** — Distinct refs for Validate sign-off vs Publish approval required in audit trail | R4.4 PublishMetadataAudit |

### 5. Why Publish Engine cannot emit consumer objects directly

| Reason | Authority |
|--------|-----------|
| **R4 boundary** — Engine emits **PublishedSnapshot reference** and **visibility grant** — logical permission only | R4.3 CB-R4-01–05; O-R4-07 |
| **Consumer ownership** — OCPilot Run 5, baseline diff, intake reports — **consumer program** execution | R4-CHARTER non-goals; CB-R4-04 |
| **No credential handoff** — Visibility grant ≠ consumer credentials or deployment command | R4.3 visibility grant contract |
| **No bulk copy mandate** — Whether R4 copies contract slice to consumer path vs reference only — **SAFE UNKNOWN**; consumer owns intake mechanics | R1.8B OQ-04 |
| **Consume is downstream** — Publish completes before Consume; engine stops at Stage 7 | EAR-SNAPSHOT-LIFECYCLE-v1 |

### 6. Why PublishResult is final stage

| Reason | Authority |
|--------|-----------|
| **Outcome record** — PublishResult documents *what happened* — cannot precede attempt boundary | R4.5 Purpose; PF G6 |
| **Three honest states** — SUCCESS, BLOCKED, DEFERRED all require post-attempt emission | PR-INV-R4-03 |
| **Audit trail** — Every attempt — including blocked at Stages 1–3 — produces receipt | PR-INV-R4-01; PF-INV-R4-06 |
| **Separation from promotion** — PublishedSnapshot exists only after successful Stages 4–6; PublishResult **always** emitted at Stage 7 | R4.5 § PublishResult ≠ PublishedSnapshot |
| **Retry semantics** — New attempt → new PublishResult; prior immutable | DEFERRED definition R4.5 |
| **Terminal orchestration** — No Stage 8; consumer intake is **outside** engine scope | PE-INV-R4-01 |
