## Purpose

Define the canonical **Validate Report** contract — the operator-facing structured review artefact produced by R5 EAR Validate and consumed by operator, HITL review, and future Publish decision processes.

**Contract layer only:** no `validate_report_models.py`, no Validate Engine, no validators, no scoring, no report serialization format (JSON/Markdown/HTML), no CLI rendering, no filesystem emit path, no Store writes.

**Critical disambiguation (mandatory):**

| Artefact | Role | Validate Report? |
|----------|------|------------------|
| **`ValidationResult`** | Authoritative R5 certification outcome — PASS / PASS WITH NOTES / FAIL | **No** — referenced, not duplicated as substitute |
| **`ValidateReport`** | Human-readable audit output by review section | **Yes** — this contract |
| **`PublishEligibilityRecommendation`** | R5 advisory Publish gate input — ELIGIBLE / ELIGIBLE WITH NOTES / NOT ELIGIBLE | **No** — referenced in Readiness section only; defined at **R5.6** |
| **R2 `{valid, errors}`** | Evidence structural gate | **No** — precondition note only |
| **R3 `{valid, errors}`** | Assembly eligibility | **No** — precondition note only |
| **Validate Engine** | Future orchestrator (R5.7) | **No** — produces bundle including report |

**Rule (VR-INV-R5-01):** Validate Report **records** validation outcomes. It **never performs** validation, **never assigns** certified quality, **never executes** Publish, **never mutates** snapshot, evidence, quarantine, or Store.

## ValidateReport top-level contract

```text
ValidateReport
├── report_id                          → stable report identifier (generation algorithm: SAFE UNKNOWN)
├── result_ref                         → ValidationResult.result_id (mandatory linkage)
├── generated_at                       → ISO 8601 timestamp (conventional)
├── target_certify_level               → int | None — operator-declared target (I-R5-11)
├── sections                           → exactly eleven canonical sections (below)
│   ├── summary                        → Section 1 — Summary
│   ├── identity_review                → Section 2 — Identity Review
│   ├── structure_review               → Section 3 — Structure Review
│   ├── possession_review              → Section 4 — Possession Review
│   ├── quality_assessment             → Section 5 — Quality Assessment
│   ├── redaction_review               → Section 6 — Redaction Review
│   ├── readiness_review               → Section 7 — Readiness Review
│   ├── consistency_review             → Section 8 — Consistency Review
│   ├── blockers                       → Section 9 — Blockers
│   ├── warnings                       → Section 10 — Warnings
│   └── audit_trail                    → Section 11 — Audit Trail
└── boundary_declaration               → fixed text: report is record-only; no side effects
```

**Invariant:** All eleven sections **must exist** on every Validate Report. Sections may contain empty finding lists when a category produced no items, but the section shell is **required**.

**Lifecycle (conceptual):**

```text
R5 Validate run completes
        ↓
ValidationResult + ValidateReport emitted together (future R5.7)
        ↓
Operator / HITL review (mandatory pilot)
        ↓
Publish decision process (R4 + operator — future)
```

Validate Report **may exist before Publish** — it is a **pre-Publish** operator artefact. Post-Publish retention policy is **SAFE UNKNOWN** (see § Persistence).

## Information policy

### Must appear (report-wide)

| Field / content | Source | Notes |
|-----------------|--------|-------|
| Link to `ValidationResult` | R5.1 `result_id` | Outcome authority remains on ValidationResult |
| Aggregate validation status | R5.1 `ValidationSummary.status` | PASS / PASS_WITH_NOTES / FAIL |
| Certified quality level (when assigned) | R5.1 `ValidationSummary.certified_quality_level` | Record only — assignment logic R5.3 |
| Target certify level (when declared) | Operator input I-R5-11 | May differ from certified — downgrade noted in Quality |
| Snapshot identity refs | R3.2 — `snapshot_id`, `site_id`, `acquisition_id`, contract ids | Identity Review + Audit Trail |
| Category-organized findings | R5.1 `ValidationFinding[]` + R5.4 `RedactionReview` summary | Mapped to sections 2–8 |
| Blocker aggregation | Findings at BLOCKER severity + redaction BLOCKED | Section 9 — fail-closed list |
| Warning aggregation | Findings at WARNING severity + non-blocking notes | Section 10 — PASS WITH NOTES support |
| Validate run audit metadata | R5.1 `ValidationAudit` + preconditions | Section 11 |
| Publish Eligibility Recommendation **reference** | R5.1 `ValidationRecommendation` or R5.6 artefact | Readiness section — **reference only** |
| Precondition status (when supplied) | R2 structural pass; R3 assembly pass | Summary — not re-validation |

### Must never appear

| Excluded content | Reason |
|------------------|--------|
| Raw credentials, passwords, tokens, API keys | Redaction contract; finding policy |
| PII values | R5.4 — risk representation only |
| Filesystem paths to quarantine bulk or operator secrets | Internal path leakage risk |
| Publish execution commands or consumer path writes | R4 ownership |
| `published_at`, publish metadata, consumer reference | R4 ownership |
| Quality certification algorithms or scores | R5.3 concept layer; no scoring in R5 |
| Validator rule implementations (R5-V-*) | Post-R5.6 implementation |
| Evidence or snapshot mutation instructions that imply side effects | Record-only contract |
| Implicit Publish approval | HITL mandatory; recommendation ≠ Publish |
| R2/R3 pass substituted for R5 outcome | VAL-INV-01; VB-R3-01 |

## Section definitions

Each section defines: **purpose**, **ownership**, **required vs optional content**, **inputs**, **non-goals**.

---

### Section 1 — Summary

| Field | Value |
|-------|-------|
| **Purpose** | Operator-first overview of the Validate run: aggregate outcome, certified level vs target, precondition flags, and pointer to blockers/warnings |
| **Ownership** | **R5.5** (report assembly); outcome authority **R5.1** |
| **Required** | `validation_status` (PASS / PASS_WITH_NOTES / FAIL); `result_ref`; `snapshot_id`; `finding_count`; `blocker_count`; `warning_count`; precondition flags when supplied (R2 pass, R3 assembly pass — boolean or SAFE UNKNOWN) |
| **Optional** | `target_certify_level`; `certified_quality_level`; one-line operator note slot; downgrade indicator when target > certified |
| **Inputs** | `ValidationResult.summary`; I-R5-11 target level; R2/R3 precondition artefacts when supplied at Validate entry |
| **Non-goals** | Does not perform validation; does not assign certified level (records R5.1/R5.3 outcome); does not substitute for Blockers or Warnings sections; no Publish action |

---

### Section 2 — Identity Review

| Field | Value |
|-------|-------|
| **Purpose** | Human-readable presentation of **Identity** category ([R5.2](R5.2-VALIDATION-CATEGORY-MODEL-v1.md) `identity`) findings — snapshot identity adequacy for certification |
| **Ownership** | Category **R5.2**; section presentation **R5.5** |
| **Required** | Section header bound to category `identity`; list of identity findings (title, description, severity); `snapshot_id`, `site_id`, contract id refs |
| **Optional** | `acquisition_id` correlation notes; identity continuity sidecar ref (I-R5-09) |
| **Inputs** | R5.1 findings where `category == identity`; R3.2 snapshot identity fields; optional Identity Continuity Record |
| **Non-goals** | Does not create or mutate `snapshot_id`; does not perform R2 evidence identity gate; does not Publish |

---

### Section 3 — Structure Review

| Field | Value |
|-------|-------|
| **Purpose** | Presentation of **Structure** category findings — contract structure adequacy vs OpenCart spec for certification target |
| **Ownership** | Category **R5.2**; section **R5.5** |
| **Required** | Section bound to category `structure`; structure findings list; high-level section skeleton adequacy statement (record of assessment outcome) |
| **Optional** | Per-section structure notes referencing OpenCart section ids (conceptual refs — not filesystem paths) |
| **Inputs** | R5.1 findings where `category == structure`; R3.1 OpenCart section tree; architecture spec refs |
| **Non-goals** | Does not assemble or populate sections (R3); does not duplicate R3-V-12 skeleton enforcement as certification |

---

### Section 4 — Possession Review

| Field | Value |
|-------|-------|
| **Purpose** | Presentation of **Possession** category findings — section-level possession adequacy vs target certify level; safe-unknown completeness review |
| **Ownership** | Category **R5.2**; possession concepts **R5.3**; section **R5.5** |
| **Required** | Section bound to category `possession`; possession findings; gap summary vs target level (record only) |
| **Optional** | Per-section possession notes; safe-unknown cross-reference (I-R5-02) |
| **Inputs** | R5.1 possession findings; R3.4 safe-unknown section; R5.3 `QualityPossessionAssessment` (future); target certify level |
| **Non-goals** | Does not assign L0–L3 certified level (Quality section); does not populate sections (R3) |

---

### Section 5 — Quality Assessment

| Field | Value |
|-------|-------|
| **Purpose** | Record of **Quality** category outcome — certified `package_quality_level` rationale, downgrade notes, inflation prevention statement |
| **Ownership** | Quality certification concepts **R5.3**; category **R5.2**; section **R5.5** |
| **Required** | Section bound to category `quality`; `certified_quality_level` (int or explicit none on FAIL); statement that R3 candidate L0 placeholder ≠ R5 certified L0 (VB-R3-06) |
| **Optional** | `target_certify_level`; downgrade rationale; quality findings list |
| **Inputs** | R5.1 `ValidationSummary.certified_quality_level`; R5.3 level registry; quality findings; I-R5-11 |
| **Non-goals** | Does not **assign** quality — records outcome from Validate run; no scoring; no Publish level freeze (R4) |

**Clarification:** Validate Report **does not certify quality**. It **documents** the certified level already determined by R5 Validate (R5.3 concepts + future R5.7 engine). Certification authority remains **R5.3 / ValidationResult**, not the report artefact alone.

### Section 6 — Redaction Review

| Field | Value |
|-------|-------|
| **Purpose** | Presentation of **Redaction** category findings and `RedactionReview` summary — publication safety without sensitive values |
| **Ownership** | Redaction model **R5.4**; category **R5.2**; section **R5.5** |
| **Required** | Section bound to category `redaction`; redaction status summary (CLEAR / REVIEW_REQUIRED / BLOCKED — record from R5.4); redaction findings without sensitive values; blocked count when applicable |
| **Optional** | Per-category redaction finding breakdown (credentials, secrets, pii, etc.); operator recommendation text from R5.4 |
| **Inputs** | R5.4 `RedactionReview`; R5.1 findings where `category == redaction`; candidate snapshot serializations (assessed upstream — not embedded in report) |
| **Non-goals** | No scanners; no stored secret/PII values; does not manage quarantine (R2.5); does not perform automated redaction |

### Section 8 — Consistency Review

|-------|-------|

### Section 9 — Blockers

| Field | Value |
|-------|-------|
| **Purpose** | Aggregated mandatory failures — fail-closed operator list supporting FAIL outcome and NOT ELIGIBLE recommendation |
| **Ownership** | **R5.5** aggregation; finding authority **R5.1** / **R5.4** |
| **Required** | Section present on every report; ordered list of blockers (finding_id, category, title, description — no secrets/paths); `blocker_count`; explicit empty list allowed on PASS |
| **Optional** | Cross-ref to originating section; redaction BLOCKED entries |
| **Inputs** | R5.1 findings where `severity == BLOCKER`; R5.4 blocked redaction findings; precondition failures when recorded |
| **Non-goals** | Does not create new blockers beyond recorded findings; does not auto-remediate; does not block Publish by itself (recommendation + R4 + HITL) |

---

### Section 10 — Warnings

| Field | Value |
|-------|-------|
| **Purpose** | Non-blocking notes supporting PASS WITH NOTES and ELIGIBLE WITH NOTES paths |
| **Ownership** | **R5.5** aggregation; finding authority **R5.1** |
| **Required** | Section present on every report; warning list (finding_id, category, title, description); `warning_count`; explicit empty list on bare PASS |
| **Optional** | Downgrade notes; REVIEW_REQUIRED redaction items that did not block |
| **Inputs** | R5.1 findings where `severity == WARNING`; non-blocking R5.4 REVIEW_REQUIRED items when policy maps to warning |
| **Non-goals** | Warnings do not imply Publish approval; do not suppress blockers |

---

### Section 11 — Audit Trail

| Field | Value |
|-------|-------|
| **Purpose** | Validate run provenance for audit — who, when, what snapshot, which contract, evidence correlation refs |
| **Ownership** | **R5.5**; audit fields aligned with R5.1 `ValidationAudit` |
| **Required** | `report_id`; `result_ref`; `validated_at`; `validated_snapshot_id`; `validator_version`; `contract_ref`; `operator_ref` (identity ref — not credential) |
| **Optional** | `acquisition_id`; evidence package ref (read-only); R2/R3 precondition timestamps; HITL review placeholder (reviewed_by, reviewed_at — **SAFE UNKNOWN** workflow) |
| **Inputs** | R5.1 `ValidationAudit`; report generation metadata; I-R5-07 evidence ref |
| **Non-goals** | Does not write Store validated marker; does not persist publish metadata; does not embed evidence content |

| Upstream artefact | Report use |
|-------------------|------------|
| `ValidationResult` (R5.1) | **Primary outcome source** — summary, findings, audit, recommendation ref |
| `ValidationCategory` registry (R5.2) | Section 2–8 category binding |

**Mapping rule (VR-MAP-R5-01):** Category findings appear in their **category section** (2–8) **and** may be **aggregated** into Blockers (9) or Warnings (10) by severity. Blockers/Warnings are **views**, not alternate finding stores.

## Boundary rules (mandatory)

Validate Report **MUST NOT**:

| Prohibition | Owner preserved |
|-------------|-----------------|
| Perform validation | Findings produced upstream (R5.7) |
| Perform publishing | **R4** |
| Assign certified quality | **R5.3** / **ValidationResult** |
| Change snapshot content or metadata | **R3** / Store |
| Modify evidence or quarantine | **R2** |
| Modify Store layout or validated marker | **R1.9** / **SAFE UNKNOWN** marker |
| Execute Publish or write consumer paths | **R4** |
| Substitute for ValidationResult as outcome authority | **R5.1** |
| Substitute for Publish Eligibility Recommendation | **R5.6** |

Validate Report **only records outcomes** of a completed (or failed) Validate run.

## Validation answers

| Question | Answer |
|----------|--------|
| **What is the difference between ValidationResult, Validate Report, and Publish Eligibility Recommendation?** | **ValidationResult** is the authoritative machine-oriented R5 certification outcome (status, findings, certified level field, advisory recommendation). **Validate Report** is the human-oriented structured audit document organizing those outcomes into eleven review sections for operator/HITL. **Publish Eligibility Recommendation** is the narrow advisory gate signal (ELIGIBLE / ELIGIBLE WITH NOTES / NOT ELIGIBLE) for R4 — referenced in Readiness, defined at R5.6, **not** equivalent to either artefact alone. |
| **Can a report exist with PASS WITH NOTES?** | **Yes** — required capability. Warnings section populated; Summary reflects PASS_WITH_NOTES. |
| **Can a report exist with FAIL?** | **Yes** — required capability. Blockers section populated; Summary reflects FAIL; certified level may be absent. |
| **Can a report exist before Publish?** | **Yes** — **expected**. Validate Report is a pre-Publish operator artefact (VB-R3-02; R3.6 lifecycle table). |
| **Must a report survive after Publish?** | **Should be retained for audit** — conceptual **yes**; **persistence mechanism SAFE UNKNOWN** (no Store contract at R5.5). |
| **Can a report certify quality?** | **No** — report **documents** certified level from Validate; certification authority is R5 Validate (**R5.3** concepts + **ValidationResult**), not the report in isolation. |
| **Can a report execute Publish?** | **No** — forbidden. R4 executes Publish after operator HITL. |
