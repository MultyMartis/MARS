## Rationale

1. **Distinct artefact** — Validate Report documented separately from `ValidationResult` and Publish Eligibility Recommendation per N-R5-03, N-R5I-03, VR-INV-R5-01.
2. **Eleven sections chartered** — Summary, Identity Review, Structure Review, Possession Review, Quality Assessment, Redaction Review, Readiness Review, Consistency Review, Blockers, Warnings, Audit Trail — each with purpose, ownership, required/optional content, inputs, non-goals (SC-R5.5-01).
3. **Blockers vs warnings** — Sections 9–10 aggregate by severity; empty lists allowed on PASS (SC-R5.5-02).
4. **Quality and possession recorded** — Summary, Possession Review, Quality Assessment include certified level and gap/downgrade semantics without assigning quality in the report layer (SC-R5.5-03).
5. **Readiness references recommendation** — Publish Eligibility Recommendation referenced with explicit *recommendation only — not Publish* label; R5.6 completes recommendation contract (SC-R5.5-04).
6. **Upstream alignment** — R5.1 findings/audit; R5.2 categories; R5.3 possession concepts; R5.4 redaction summary mapping documented.
7. **Boundary clean** — Report MUST NOT validate, publish, assign quality, or mutate snapshot/evidence/quarantine/Store — record-only (VR-INV-R5-01).
8. **Lifecycle** — Report may exist with PASS WITH NOTES, FAIL, and before Publish; post-Publish retention noted as audit expectation with persistence **SAFE UNKNOWN**.

**PASS WITH NOTES** (not bare **PASS**): no dataclass module yet (deferred R5.7+); Publish Eligibility Recommendation full contract deferred **R5.6**; report persistence and HITL audit fields **SAFE UNKNOWN**; Redaction REVIEW_REQUIRED → Warning mapping deferred R5.7.

**FAIL** would apply if report contract performed Publish, substituted for ValidationResult, omitted mandatory sections, or included quality assignment authority in the report layer — **none apply**.
