## Rationale

1. **Orchestration-only scope** — Engine owns execution flow, gate verification, promotion assembly orchestration, outcome emission — not validation, quality concepts, R3 section assembly, evidence lifecycle, or consumer execution (PE-INV-R4-01; SC-R4.7-04).
2. **Inputs chartered** — Validated Snapshot mandatory; R5 bundle (`ValidationResult`, `ValidateReport`, `PublishEligibilityRecommendation`) consumed read-only; operator Publish approval ref mandatory for Stages 4–6 (SC-R4.7-01, SC-R4.7-03).
3. **Output bundle complete** — `PublishResult` always (Stage 7); `PublishedSnapshot` + visibility grant on SUCCESS only; linkage invariants PE-LINK-01–06 (SC-R4.7-02).
4. **Seven stages** — Preconditions → Eligibility Verification → HITL Verification → Publish Assembly → Metadata Attachment → Visibility Grant → Publish Result Emission (SC-R4.7-05).
5. **Gate alignment** — Stages map to R4.6 G1–G6 without namespace collision; fail-closed stops preserved (SC-R4.7-06).
6. **Mandatory answers** — Six disambiguation questions answered; Stage 4 vs R3 assembly terminology explicit (SC-R4.7-07).
7. **Boundaries clean** — No Validate re-run, no quality certification, no R3 assembly, no evidence writes, no HITL bypass, no consumer object emission (SC-R4.7-09).
8. **Upstream alignment** — R4.1–R4.6 and R5.1–R5.6 contracts referenced; R5.7 pattern followed; R5.8 VB-R5-01 preserved at consumption boundary.
9. **PublishResult terminal** — Stage 7 mandatory for every attempt; no Stage 8 (SC-R4.7-11).

**PASS WITH NOTES** (not bare **PASS**): no implementation code (deferred post-R4.9); Store metadata persist encoding **SAFE UNKNOWN**; BLOCKED vs DEFERRED on pending Stage 3 — operator policy; atomic failure recovery **SAFE UNKNOWN**; consumer registry pointer write **SAFE UNKNOWN**.

**FAIL** would apply if engine executed Validate, assembled R3 sections, certified quality, bypassed HITL, emitted consumer intake objects, or omitted PublishResult — **none apply**.
