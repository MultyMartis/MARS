## Task 2 — PC-03: External Root Charter

### Evidence evaluated

| Candidate | Verdict | Evidence |
|-----------|---------|----------|
| **Repository only** (`C:\AI MARS`) | **Rejected** for bulk | EAR-STORAGE-MODEL — bulk and secrets external; OCPilot registry |
| **`C:\AI MARS STORAGE` root (no subfolder)** | **Rejected** | mars-storage-family-note — "No dumping at root" |
| **`C:\AI MARS STORAGE\ocpilot\`** | **Rejected** for EAR Store | OCPilot registry is consumer system; C-03 conflict — EAR Store ≠ OCPilot intake at Store stage |
| **`C:\AI MARS STORAGE\ear\`** | **Selected** | mars-storage-family-note illustrative table; R1.8A recommendation to mirror OCPilot registry pattern; placement ADR — external for artefacts |
| **Operator-arbitrary path outside MARS family** | **Allowed only by explicit operator override** | `output_root` binding — must document deviation from default |

### Authoritative recommendation

| Scope | Canonical path | Status |
|-------|----------------|--------|
| **MARS bulk root** | `C:\AI MARS STORAGE` | **Defined** — infrastructure reality v1 |
| **EAR system bulk root** | `C:\AI MARS STORAGE\ear\` | **Chartered** (R1.8C — documentation only; on-disk creation is operator action) |
| **Default EAR Store binding (`output_root`)** | `C:\AI MARS STORAGE\ear\store\` | **Recommended default** — binds operator JSON to chartered subtree |
| **Secrets** | External — **outside** snapshot package; not under snapshot tree | EAR-SECURITY-MODEL, storage model |
| **Repo metadata** | `C:\AI MARS\projects\ear-runtime\` | Placement ADR |

### Binding rules

1. **`output_root`** in operator JSON **must** resolve to a path under `C:\AI MARS STORAGE\ear\` unless operator documents an explicit override in run charter.
2. **Default value** for new configs: `C:\AI MARS STORAGE\ear\store\` (recommended — not enforced until R1.8 writers).
3. **EAR must not** use `C:\AI MARS STORAGE\ocpilot\` for Store-stage writes — OCPilot paths are **consumer registry** territory ([external-storage-registry.md](../ocpilot/external-storage-registry.md)).
4. **Registry pattern:** EAR follows OCPilot Run 3.7 precedent — system-specific subfolder under MARS bulk root with documented subfolder contract (this charter).
5. **On-disk READMEs** at external folders — operator responsibility when folders are created; **not** part of R1.8C scope.

### Relationship to existing conventions

| System | Bulk root | Relationship to EAR |
|--------|-----------|---------------------|
| **MARS family** | `C:\AI MARS STORAGE` | Parent — shared bulk root |
| **OCPilot** | `...\ocpilot\` | **Downstream consumer** — Publish handoff only (R4); not EAR Store target |
| **EAR** | `...\ear\` | **Upstream producer** — Store and evidence quarantine |

## Task 3 — PC-04: Persistence Layout Charter

### Conceptual layer model

Physical encoding is **logical folder tree** at charter level. ZIP packaging, sidecar index files, and checksum registries remain **future layers** unless R1.8 model specifies otherwise.

```
MARS bulk root
    └── ear/                          ← EAR system root (PC-03)
            ├── store/                ← default output_root zone
            │     └── {acquisition_id}/
            │           ├── evidence/           ← Evidence Package quarantine
            │           └── snapshots/
            │                 └── {snapshot_id}/
            │                       ├── metadata/
            │                       ├── file-manifest/
            │                       ├── theme-info/
            │                       ├── extension-inventory/
            │                       ├── ocmod-inventory/
            │                       ├── database-metadata/
            │                       ├── seo-structure/
            │                       ├── environment/
            │                       ├── safe-unknown/
            │                       └── acquisition-log/
            ├── archive/              ← optional functional zone
            └── temp/                 ← optional functional zone
```

### Layer classification

#### Required layers (R1.8 Store scope)

| Layer | Purpose | Key |
|-------|---------|-----|
| **MARS bulk root** | Out-of-git bulk family | `C:\AI MARS STORAGE` |
| **EAR system root** | EAR-owned bulk namespace | `ear\` |
| **Store zone** | Default `output_root` target | `store\` |
| **Acquisition** | Session grouping; evidence + snapshot correlation | `{acquisition_id}` |
| **Evidence quarantine** | Pre-contract acquisition artefacts | `evidence\` under acquisition |
| **Snapshot container** | Immutable Store target | `snapshots\{snapshot_id}\` |
| **OpenCart sections** | Contract slice per [R1.8B](R1.8B-SNAPSHOT-STORAGE-CONTRACT-v1.md) | Section folders under `{snapshot_id}\` |

#### Optional layers (operator / future)

| Layer | Purpose | When |
|-------|---------|------|
| **`archive\`** | Superseded or retired snapshots re-tiered from `store\` | Archive stage; operator policy |
| **`temp\`** | Short-lived extracts during acquisition | Active work only — mirror OCPilot `temp\` semantics |
| **Acquisition registry sidecar** | Index of sessions at store root | Operator choice — location **SAFE UNKNOWN** for format |
| **Small metadata copy in repo** | Traceability | Operator policy — not required |

#### Future layers (not R1.8 without charter)

| Layer | Purpose |
|-------|---------|
| **Published pointer / registry** | Consumer-visible "latest published" per site — R4 |
| **Checksum sidecar** | Package integrity — Phase 4 candidate |
| **ZIP archive encoding** | Alternative to folder tree — physical encoding **SAFE UNKNOWN** until R1.8 model |
| **Central MARS snapshot catalog** | Cross-system index — not claimed v1 |
| **Hybrid merge subfolders** | Multiple connector legs under one `acquisition_id` |

### Path composition (conceptual — no creation)

| Artifact | Conceptual path |
|----------|-----------------|
| Evidence bulk | `{output_root}/{acquisition_id}/evidence/` |
| Stored snapshot | `{output_root}/{acquisition_id}/snapshots/{snapshot_id}/` |
| Section file | `{output_root}/{acquisition_id}/snapshots/{snapshot_id}/{section}/` |
| `bulk_root` metadata field | Opaque reference to `{snapshot_id}` root or external bulk subpath |

**`output_root` default:** `C:\AI MARS STORAGE\ear\store\`

### Store state representation

| State | Layout implication |
|-------|-------------------|
| **Stored-unpublished** | Full tree under `snapshots\{snapshot_id}\`; `publish_state: stored` in metadata (encoding **SAFE UNKNOWN**) |
| **Published** | Same Store path retained; publish metadata in `acquisition-log/`; consumer receives **reference** via `bulk_root` — no mandatory relocation at Store |
| **Archived** | Operator may re-tier to `ear\archive\{snapshot_id}\` or retain in place with archive flag — physical move **operator policy** |

### Conflicts resolved

| ID | Resolution |
|----|------------|
| **C-03** EAR Store vs OCPilot `project-sites\` | EAR Store writes to `ear\store\` only; OCPilot `project-sites\` is Publish-stage consumer intake (R4) |
| **G-02** Physical layout | Folder tree chartered; ZIP alternative deferred |

## Task 4 — PC-08: Evidence Retention Charter

### Architecture baseline (evidence only)

| Source | Statement |
|--------|-----------|
| EAR-EVIDENCE-PACKAGE-v1 | Evidence is temporary; may delete or archive after successful publish; retention period **SAFE UNKNOWN** until storage charter |
| EAR-STORAGE-MODEL-v1 | Post-Store snapshot immutability; archive deletion = operator policy |
| EAR-SNAPSHOT-LIFECYCLE-v1 | Archive ≠ delete; archived snapshots citeable |
| EAR-SNAPSHOT-PUBLISHING-v1 | Stored-but-unpublished is valid; consumers see published only |
| R1.8B | Stored-never-published may archive or delete per operator policy |

### Retention policy by artifact class

#### Evidence Package

| Phase | Minimum rule | Owner |
|-------|--------------|-------|
| **Acquire → Validate** | **MUST retain** — required for validation gate | Operator + EAR |
| **Validate pass → Store complete** | **MUST retain** until snapshot Store succeeds | Operator + EAR |
| **Post-Store, pre-Publish** | **MAY retain or archive** — operator policy; default **recommend retain** until Publish confirmed | Operator |
| **Post-Publish** | **MAY delete or move to archive** — operator policy; EAR does not automate | Operator |
| **Fixed duration / legal hold** | **SAFE UNKNOWN** — operator legal review | Operator |

**Minimum architecture-compatible rule:** Evidence **must not** be deleted before Validate pass and successful Store of derived snapshot. Post-Store disposition is operator policy with **recommended default: archive under `{acquisition_id}/evidence/` or move to `ear\archive\` rather than immediate delete** until Publish is recorded.

#### Snapshot Package (stored-unpublished)

| Rule | Detail |
|------|--------|
| **Retention** | **MUST retain** while stored — immutability convention |
| **Deletion** | Operator policy only; **discouraged** before Publish decision documented |
| **Supersession** | New `snapshot_id` — prior retained until archive transition |

#### Published Snapshot

| Rule | Detail |
|------|--------|
| **Retention** | **MUST retain** for consumer citeability |
| **Supersession** | Prior published snapshot moves toward **Archive** — not deleted by default |
| **Consumer reports** | Must cite `snapshot_id` — archived ids remain valid references |

#### Archive Snapshot

| Rule | Detail |
|------|--------|
| **Purpose** | Long-term retention after supersession or audit closure |
| **Mutability** | Not active publish target |
| **Deletion** | Operator policy only — EAR does not automate |
| **Citeability** | **MUST remain citeable** from historical reports |
| **Physical location** | `ear\archive\` or in-place with archive metadata — operator choice |

### Retention summary matrix

| Artifact | Min retain | Default after Publish | Delete authority |
|----------|------------|----------------------|------------------|
| **Evidence Package** | Through Store | Archive recommended | Operator |
| **Snapshot (stored-unpublished)** | Indefinite while stored | N/A until Publish | Operator policy |
| **Published Snapshot** | Indefinite | Move to archive on supersession | Operator policy |
| **Archive Snapshot** | Until operator policy elapsed | — | Operator policy |

**G-07 status:** Minimum policy **defined**; fixed time periods and legal hold remain **SAFE UNKNOWN**.

## Task 5 — OCPilot relationship

### Flow (architecture — no implementation)

```
EAR Store (ear\store\)
        ↓  reference in bulk_root / metadata
EAR Publish (R4 — out of R1.8 scope)
        ↓  published reference
OCPilot intake (project-sites\ + repo metadata)
        ↓
OCPilot Consume → reports cite snapshot_id
```

### Handoff dimensions

| Dimension | R1.8C charter |
|-----------|---------------|
| **Ownership at Store** | **EAR / operator** — artefacts under `C:\AI MARS STORAGE\ear\store\` |
| **Ownership at Consume** | **OCPilot** — reports and analysis outputs in `projects/ocpilot/`; bulk refs in `project-sites\` |
| **Reference vs copy** | **Reference-first** at Publish — `bulk_root` points to EAR store path; operator **may copy** bulk to `ocpilot\project-sites\{site_slug}\` per OCPilot registry at Publish (R4) |
| **Publish** | Explicit gate — stored-unpublished **not** OCPilot intake ([EAR-OCPILOT-INTEGRATION-v1.md](../../shared/external-access-runtime/EAR-OCPILOT-INTEGRATION-v1.md)) |
| **EAR writes to OCPilot paths at Store** | **Forbidden** — resolves C-03 |
| **OCPilot invokes connectors** | **Forbidden** — consumer-only |
| **Re-acquisition** | New EAR cycle → new `snapshot_id` — not consumer live pull |

### OCPilot registry alignment

| OCPilot path | EAR relationship |
|--------------|------------------|
| `project-sites\` | **Publish-stage** consumer bulk — reference or operator-supervised copy from EAR store |
| `incoming\` | OCPilot baseline dropzone — **not** EAR evidence quarantine |
| `backups\` | Operator backup copies — separate from EAR archive semantics |
| `temp\` | OCPilot scratch — **not** EAR store |

Repo-side OCPilot metadata (`projects/ocpilot/sites/`, passports) records external path + checksum per [external-storage-registry.md](../ocpilot/external-storage-registry.md) — EAR does not write consumer repo metadata at Store stage.

## Authoritative recommendations (summary)

1. **Charter** `C:\AI MARS STORAGE\ear\` as canonical EAR system bulk root — mirror OCPilot family pattern.
2. **Bind** default `output_root` to `C:\AI MARS STORAGE\ear\store\`.
3. **Layout:** `{output_root}/{acquisition_id}/evidence/` + `{output_root}/{acquisition_id}/snapshots/{snapshot_id}/{sections}/`.
4. **Retain** evidence through Store; post-Store/post-Publish disposition = operator policy with archive recommended over delete.
5. **Separate** EAR Store paths from OCPilot `project-sites\` — Publish (R4) handles consumer handoff via reference or operator copy.
6. **Do not** create folders, writers, or registry files in R1.8C — charter only.
