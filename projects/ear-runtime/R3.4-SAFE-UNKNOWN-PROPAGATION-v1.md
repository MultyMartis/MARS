## Purpose

Define the **authoritative contract** governing how uncertainty, gaps, missing evidence, partial acquisition, scope limitations, and unresolved conditions are represented inside **candidate** OpenCart Snapshot Packages.

This document is normative for:

| Downstream | Use |
|------------|-----|
| **R3.5** HandoffContract + Candidate Snapshot Generator | `SafeUnknownPropagator` entry construction |
| **R3.6** Assembly Eligibility | Fail closed when gaps suppressed |
| **R5** Validate | Honesty review; quality possession vs gaps |
| **R4** Publish | Consumer disclosure boundary (read-only of R3 output) |
| **Future consumer trust model** | Typed gap semantics |

**Explicit exclusions:** generator, assembly execution, persistence, Store changes, Validate, Publish, OCPilot, SITE-001, network.

## Safe Unknown taxonomy (Task 3)

Every snapshot entry carries an implicit or documented **category** (see Entry Semantics — category is **future** field; R3.5 may prefix `reason` with category slug).

| Category ID | Category | Definition | Typical evidence sources |
|-------------|----------|------------|--------------------------|
| **SU-CAT-01** | **Missing Evidence** | Required artifact or signal absent from evidence index or expansion | No manifest ref; artifact `status: missing`; empty expansion |
| **SU-CAT-02** | **Partial Acquisition** | Connector completed with incomplete scope or partial artifact set | `connector_status: partial`; partial manifest; `partial_run` |
| **SU-CAT-03** | **Failed Acquisition** | Connector or leg did not achieve success outcome | `connector_status: failed`; terminal errors |
| **SU-CAT-04** | **Scope Limitation** | Approved or attempted scope excludes data needed for section | Scope echo delta; excluded paths; operator-declared exclusions |
| **SU-CAT-05** | **Unverified Claim** | Field present but not corroborated by possession evidence | Platform/version claim without version proof files |
| **SU-CAT-06** | **Unsupported Capability** | Channel or mode cannot supply section at current engineering scope | SFTP-only without DB access; Mode 0 declaration-only |
| **SU-CAT-07** | **Deferred Expansion** | Artifact ref exists but expansion not performed or deferred to future level | L2+ sections at R3 L1 target; `extension-inventory`, `ocmod-inventory` |
| **SU-CAT-08** | **Validation Pending** | Assembly produced candidate; R5 possession not yet evaluated | **R3 must not emit** — reserved for R5 overlay or consumer docs only |
| **SU-CAT-09** | **Contract Gap** | Shape, parser, or handoff contract cannot map evidence to section | Unexpanded manifest ref; parser failure; `artifact_type: safe-unknown` |
| **SU-CAT-10** | **Other** | Residual honesty topic not fitting above — requires human-readable `reason` | Cross-channel timestamp conflict; tooling limitations |

**R3 assembly rule:** R3 **must not** emit **SU-CAT-08** entries — candidate assembly is pre-Validate; use **SU-CAT-01**–**07** or **10** only.

## Entry semantics (Task 5)

### Current model (`SnapshotSafeUnknownEntry`)

```text
SnapshotSafeUnknown
└── entries[] → SnapshotSafeUnknownEntry
        ├── topic: str          (required)
        ├── reason: str         (required)
        ├── impact: str         (required)
        └── unblock_hint: str   (optional, default "")
```

### Field contract

| Field | Status | Semantics | Constraints |
|-------|--------|-----------|-------------|
| **`topic`** | **Required** | Stable concern identifier — prefer canonical registry; section slugs match OpenCart logical paths without trailing slash | Non-empty; no secrets; max practical length **256** chars (implementation guidance) |
| **`reason`** | **Required** | Human-readable why data is missing, partial, unverified, or deferred | Non-empty; non-secret; may prefix with `[category]` until `category` field exists |
| **`impact`** | **Required** | Consumer phase or capability blocked (e.g. "baseline diff blocked", "extension risk phase blocked") | Non-empty; non-secret; align with EAR-OPENCART-SNAPSHOT-SPEC impact examples |
| **`unblock_hint`** | **Optional** | Procedure id, charter ref, or channel name — **not** implementation steps or credentials | Empty string = omitted in JSON; use stable ids e.g. `proc:db-readonly-pma`, `level:2-acquisition` |

### Forbidden fields (R3 candidate entries)

| Forbidden | Why |
|-----------|-----|
| Credentials, API keys, connection strings | SU-FORBID-05; AR-R3-16 |
| `package_quality_level` override | SU-FORBID-04 |
| `connector_status` raw enum as sole payload | Must transform to honesty narrative — HO-INV-09 |
| `evidence_id` | HO-FORBID-15 |
| Quarantine absolute paths as consumer-facing unblock | HO-FORBID-07; AR-R3-09 |
| Fabricated section payload embedded in entry | SU-FORBID-02 |

### Future fields (not in R3.1 — do not implement at R3.4)

| Field | Purpose | Owner |
|-------|---------|-------|
| **`category`** | Machine-readable SU-CAT-01–10 | R3.5 optional model bump or R5 consumer index |
| **`source_ref`** | Link to `artifact_ref`, HO rule id, or evidence warning index | R3.5 |
| **`severity`** | `blocking` / `informational` for consumer halt rules | R5 consumer contract |
| **`created_at`** | Entry emission timestamp | R3.5 persist |
| **`resolved_at`** | Operator resolution — post-candidate only | R5 / operator |

### Serialization notes

| Topic | Normative |
|-------|-----------|
| R3.1 `to_dict()` keys | `topic`, `reason`, `impact`, `unblock_hint` |
| R1.8B on-disk `unblock` alias | Persist layer may map `unblock_hint` ↔ `unblock` at R3.5 — **C-R3.4-02** |
| Empty entries list | Allowed **only** if assembly certifies all targeted sections populated **and** no residual gaps — R5 validates; R3 L0 **never** empty if sections unpopulated |

## Propagation rules (Task 6)

### Core honesty rules

| ID | Rule | Authority |
|----|------|-----------|
| **SU-R3-01** | **Unknowns must be explicit** — every gap that affects section completeness or trust must have a `safe-unknown/` entry | EAR-CHARTER; EAR-OPENCART-SNAPSHOT-SPEC |
| **SU-R3-02** | **No silent omission** — empty L1-target section without corresponding entry is a contract violation | HO-FORBID-10; AR-R3-03 |
| **SU-R3-03** | **No fabricated replacement** — assembly must not invent section payloads to avoid an entry | SU-FORBID-02; AR-R3-02 |
| **SU-R3-04** | **Missing L1 evidence becomes safe-unknown** — absent artifact or empty expansion → section topic, not empty claim of possession | HO-ALLOW-08; AR-R3-03 |
| **SU-R3-05** | **Failed acquisition never becomes success** — `connector_status: failed` → `acquisition_outcome` topic; does not clear per-section gaps | HO-ALLOW-04; AR-R3-11 |
| **SU-R3-06** | **Connector success ≠ section completeness** — `connector_status: success` does not suppress per-section entries for missing L1 data | HO-INV-09; AR-R3-10 |
| **SU-R3-07** | **Scope delta explicit** — attempted ≠ approved → `scope_delta` topic plus acquisition-log scope tuples | HO-ALLOW-03; AR-R3-12 |
| **SU-R3-08** | **Per-artifact status honored** — `missing` / `unknown` → entry per HO-ALLOW-09; not quality inflation | AR-R3-13 |
| **SU-R3-09** | **Candidate quality stays L0** — `package_quality_level: 0` at assembly; gaps never justify ≥1 | HO-FORBID-06; AR-R3-05 |
| **SU-R3-10** | **L2 placeholders honest** — at R3 L1 target, `extension-inventory` and `ocmod-inventory` entries required when not populated | AR-R3-17 |
| **SU-R3-11** | **L0 lists all non-acquired sections** — each unpopulated section → topic entry | EAR-OPENCART-QUALITY-MAPPING L0 |
| **SU-R3-12** | **One concern per entry** — do not merge unrelated gaps into single vague entry | A-R3.4-02 |
| **SU-R3-13** | **Transform, do not copy** — evidence `errors`/`warnings` become snapshot topics; not verbatim secret-bearing paste | HO-ALLOW-04; AR-R3-16 |
| **SU-R3-14** | **Manifest ref ≠ section** — unexpanded ref → `file-manifest` Contract Gap entry | AR-R3-14 |
| **SU-R3-15** | **Environment UNKNOWN allowed** — `environment_class: UNKNOWN` is valid; optional `environment` topic for narrative | HO-ALLOW-07 |
| **SU-R3-16** | **Unverified claims flagged** — metadata claims without proof → Unverified Claim topic | AR-R3-15 |
| **SU-R3-17** | **No Validation Pending entries from R3** — R3 does not emit SU-CAT-08 | R3/R5 boundary |
| **SU-R3-18** | **Dedup policy** — same `topic` + equivalent `reason` must not duplicate; different concerns same section → multiple entries allowed | A-R3.4-02 |
| **SU-R3-19** | **Acquisition-log correlation** — `partial_run`, scope tuples, and tooling notes must align with safe-unknown topics | AR-R3-11/12 |
| **SU-R3-20** | **Handoff inputs only** — propagation sources limited to H-IN-01–H-IN-10 and assembly detection | AR-R3-06 |

### Prohibitions (retained)

| ID | Prohibition |
|----|-------------|
| **SU-FORBID-01** | Silent omission when section empty due to partial/failed evidence |
| **SU-FORBID-02** | Fabricating section content to avoid safe-unknown entry |
| **SU-FORBID-03** | Treating `connector_status: success` as section completeness |
| **SU-FORBID-04** | Setting `package_quality_level` ≥ 1 to mask gaps |
| **SU-FORBID-05** | Copying secrets into safe-unknown entries |
