### Design principles (frozen — do not change in this review)

1. **Snapshots are evidence packages**, not live connections ([EAR-STORAGE-MODEL-v1.md](../../shared/external-access-runtime/EAR-STORAGE-MODEL-v1.md)).
2. **Three-way separation:** what may appear in git (contracts, references, small manifests) vs what must stay external (bulk, secrets) vs what consumers read (published references only).
3. **Pipeline position:** Config → Listing → Manifest → Evidence → Snapshot — all currently in-memory at runtime; persistence applies at **Store** stage per lifecycle.
4. **Evidence ≠ Snapshot:** Evidence Package is acquisition-internal, temporary, pre-contract; Snapshot Package is consumer-facing after Validate ([EAR-EVIDENCE-PACKAGE-v1.md](../../shared/external-access-runtime/EAR-EVIDENCE-PACKAGE-v1.md)).
5. **Publish ≠ Store:** Stored but unpublished snapshots are **not** consumer input ([EAR-SNAPSHOT-PUBLISHING-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-PUBLISHING-v1.md)).
6. **Immutability:** Post-Store artifacts for a `snapshot_id` are not overwritten; corrections require new `snapshot_id` ([EAR-STORAGE-MODEL-v1.md](../../shared/external-access-runtime/EAR-STORAGE-MODEL-v1.md)).
7. **Physical encoding** (folder tree vs ZIP, sidecar index) — **SAFE UNKNOWN** until storage charter ([EAR-SNAPSHOT-CONTRACT-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-CONTRACT-v1.md), [EAR-OPENCART-SNAPSHOT-SPEC-v1.md](../../shared/external-access-runtime/EAR-OPENCART-SNAPSHOT-SPEC-v1.md)).
8. **No secrets in git-bound copies** — credential boundary preserved ([EAR-SECURITY-MODEL-v1.md](../../shared/external-access-runtime/EAR-SECURITY-MODEL-v1.md)).

### Logical snapshot structure (architecture — OpenCart)

```
Snapshot/
├── metadata/
├── file-manifest/
├── theme-info/
├── extension-inventory/
├── ocmod-inventory/
├── database-metadata/
├── seo-structure/
├── environment/
├── safe-unknown/
└── acquisition-log/
```

Generic contract uses `access-log`; OpenCart uses `acquisition-log` — cross-walk **SAFE UNKNOWN** until Phase 4 unification.

### Storage role diagram (architecture)

```
Repository (MARS git)     → specs, indexes, reports, optional small metadata copies
        ↓ references
External storage          → bulk payloads, contract slices, acquisition registry (optional)
        ↓ published reference
Consumer workspace        → published contract slice + bulk refs; analysis outputs
        ↓ supersession / policy
Archive tier              → retired snapshots; citeable from historical reports
```

### Runtime models today (in-memory only)

| Layer | Model | Fields persisted today (mock) | Architecture sections mapped |

## Task 5 — Retention assessment

### Architecture says

| Topic | Definition | Source |
|-------|------------|--------|
| **Post-Store immutability** | Artifacts for `snapshot_id` not overwritten | [EAR-STORAGE-MODEL-v1.md](../../shared/external-access-runtime/EAR-STORAGE-MODEL-v1.md) |
| **Fix errors** | New acquisition → new `snapshot_id` | Storage model, lifecycle |
| **In-place edit after Publish** | Discouraged; prefer superseding snapshot | Storage model |
| **Archive purpose** | Long-term retention after supersession or audit closure | Storage model |
| **Archive mutability** | Not active publish target | Storage model |
| **Archive deletion** | Operator policy only — not EAR-automated | Storage model |
| **Archive triggers** | Newer snapshot supersedes; site audit closed; retention elapsed | Lifecycle, workflow, readiness gates |
| **Archive ≠ delete** | Operator policy governs destruction | Lifecycle |
| **Historical citeability** | Archived snapshots remain citeable from reports | Lifecycle |
| **Consumer default** | Use latest published; may read archived if reference retained | Storage model |
| **Evidence after publish** | May move to archive or delete per policy | [EAR-EVIDENCE-PACKAGE-v1.md](../../shared/external-access-runtime/EAR-EVIDENCE-PACKAGE-v1.md) |
| **Evidence retention period** | **SAFE UNKNOWN** | Evidence package |
| **Legal hold / GDPR erasure** | **SAFE UNKNOWN** — operator legal review | Lifecycle |
| **WORM / encryption** | **SAFE UNKNOWN** | Storage model |
| **Central catalog on archive** | EAR optional — not implemented v1 | Lifecycle |

### Replacement behavior

- Supersession is **logical**: new `snapshot_id` replaces active consumer use; prior moves toward archive ([EAR-SNAPSHOT-LIFECYCLE-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-LIFECYCLE-v1.md)).
- Example: `snap-…-p2` replaces `p1` when higher quality published ([EAR-SITE-001-WORKFLOW-EXAMPLE-v1.md](../../shared/external-access-runtime/EAR-SITE-001-WORKFLOW-EXAMPLE-v1.md)).
- No automated supersession pointer — **SAFE UNKNOWN** ([EAR-OCPILOT-INTEGRATION-v1.md](../../shared/external-access-runtime/EAR-OCPILOT-INTEGRATION-v1.md)).

### Historical snapshots

- Must remain citeable; consumer reports tied to archived id ([EAR-SNAPSHOT-LIFECYCLE-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-LIFECYCLE-v1.md)).
- OCPilot `backups\` folder exists for operator backup copies — separate from EAR archive semantics ([external-storage-registry.md](../ocpilot/external-storage-registry.md)).

## Recommendations (design only — no implementation decisions)

1. **Adopt hybrid storage** as frozen persistence model — repo for code/docs/metadata references; external for all snapshot bulk and evidence quarantine.
2. **Charter EAR external root** under `C:\AI MARS STORAGE\` before R1.8 writers — mirror OCPilot registry pattern; bind to `output_root`.
3. **Separate Store from Publish** in persistence design — support stored-but-unpublished state per architecture.
4. **Define snapshot_id generator** aligned with OpenCart spec (`snap-{YYYYMMDD}-{site_id}-{sequence}`) — replace mock format at persistence boundary only.
5. **Persist acquisition_id** alongside snapshot for session correlation — per contract mapping.
6. **Reconcile R1-IMPLEMENTATION-TASKS-v1.md** with executed R1.4–R1.8 phase sequence before coding.
7. **Do not persist secrets** — enforce redaction at write boundary per credential boundary.
8. **Evidence retention policy** — resolve G-07 in R1.8 charter (keep quarantine copy vs delete after snapshot store).
9. **R1.8 scope boundary** — persistence model and layout contract only; publishing remains R4; full section population remains R3/live acquisition.
