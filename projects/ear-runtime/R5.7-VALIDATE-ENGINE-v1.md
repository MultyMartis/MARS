## Purpose

Define the canonical **Validate Engine** architecture — the future R5 orchestrator that coordinates EAR Validate execution flow, category dispatch, outcome aggregation, and artefact emission.

**Architecture layer only:** no `ear_validate_engine.py`, no R5-V-* rules, no category assessor implementations, no CLI (`--validate-snapshot`), no Store writes, no Publish execution, no snapshot mutation.

**Critical disambiguation (mandatory):**

| Artefact | Role | Validate Engine? |
|----------|------|------------------|
| **Validate Engine** | Orchestration — entry gate, dispatch, aggregation, emission | **Yes** — this document |
| **Validation categories** | Ownership contracts per R5.2 | **Reads registry** — does not redefine |
| **Quality possession concepts** | L0–L3 certification semantics per R5.3 | **Consumes registry** — assignment at Stage 3 |
| **Redaction review model** | Risk representation per R5.4 | **Consumes model** — review at Stage 4 |
| **Validate Report contract** | Operator audit layout per R5.5 | **Assembles** — Stage 6 |
| **Publish Eligibility contract** | Advisory gate per R5.6 | **Assembles** — Stage 7 |
| **ValidationResult** | Authoritative outcome per R5.1 | **Produces** — Stage 5 |
| **R5-V-* rules** | Future per-category checks | **Dispatches to** — not defined here |
| **R4 Publish** | Consumer promotion execution | **Forbidden** |

**Rule (VE-INV-R5-01):** Validate Engine **orchestrates** R5 Validate. It **owns execution flow, orchestration, aggregation, and outcome production**. It **does not own** quality concepts, category definitions, report section semantics, or recommendation state definitions — those remain owned by R5.1–R5.6.

## Canonical stages

Seven stages — ordered execution. Stages **must not** be skipped except Stage 1 early-exit on hard precondition failure (still emits FAIL bundle when policy requires).

```text
Stage 1  Preconditions
    ↓
Stage 2  Category Evaluation
    ↓
Stage 3  Quality Assessment
    ↓
Stage 4  Redaction Review
    ↓
Stage 5  Outcome Aggregation
    ↓
Stage 6  Validate Report Assembly
    ↓
Stage 7  Publish Recommendation Assembly
```

---

### Stage 1 — Preconditions

| Field | Value |
|-------|-------|
| **Purpose** | Entry gate — verify Validate may proceed; reject invalid inputs fail closed |
| **Engine owns** | Entry decision; precondition flag recording; early FAIL bundle trigger |
| **Engine does not own** | R3 assembly rules; R2 structural rules |

**Checks (orchestration only — no rule IDs):**

| Check | Mandatory? | Fail-closed behavior |
|-------|------------|----------------------|
| Candidate Snapshot Package present | **Yes** | Reject run — no candidate, no Validate |
| Candidate is R3.1 contract path (not R1.7 legacy) | **Yes** | Reject run |
| R3 assembly eligibility supplied and passed | **When supplied** | FAIL precondition — VB-R3-01 |
| R3 assembly eligibility not supplied | **Allowed** | Record SAFE UNKNOWN precondition; policy at implementation |
| R2 structural result supplied and failed | **When supplied** | FAIL precondition or forced NOT_ELIGIBLE at Stage 7 |
| Target certify level in 0–3 when supplied | **When supplied** | Reject invalid target |
| Evidence Package when supplied | Read-only attach | Does not re-run R2 validator |

**Stage 1 outputs:** `PreconditionContext` (conceptual) — flags for Summary/Audit sections; may short-circuit to Stage 5 with FAIL if hard gate policy requires.

Assessors **read** candidate snapshot read-only. No section mutation. No evidence writes.

## Outcome mapping principles

### ValidationResult status derivation (VE-MAP-R5-01)

**No scoring. No thresholds. No weighted indexes.** Status derives from **presence of mandatory blockers** and **precondition failures** — exact rule IDs deferred to R5-V-* implementation.

| Condition (conceptual) | `ValidationStatus` |
|------------------------|------------------|
| No BLOCKER findings; no hard precondition failure; certified level assignable | `PASS` |
| No BLOCKER findings; WARNING findings and/or downgrade notes present | `PASS_WITH_NOTES` |
| Any BLOCKER finding; redaction BLOCKED mandatory; contract breach; precondition fail | `FAIL` |

**Invariants:**

| ID | Rule |
|----|------|
| VE-MAP-R5-02 | R2 pass does **not** imply PASS |
| VE-MAP-R5-03 | R3 assembly pass does **not** imply PASS |
| VE-MAP-R5-04 | PASS or PASS_WITH_NOTES does **not** imply Publish approval — HITL mandatory |
| VE-MAP-R5-05 | FAIL implies `NOT_ELIGIBLE` recommendation by default (fail closed) |

### ValidationResult → PublishEligibilityRecommendation (VE-MAP-R5-06)

Default one-way advisory mapping — per R5.6 PE-MAP-R5-01:

| `ValidationStatus` | Default `recommendation_state` |
|--------------------|-------------------------------|
| `PASS` | `ELIGIBLE` |
| `PASS_WITH_NOTES` | `ELIGIBLE_WITH_NOTES` |
| `FAIL` | `NOT_ELIGIBLE` |

**Rules:**

| ID | Rule |
|----|------|
| VE-MAP-R5-07 | Recommendation **must not** upgrade status (FAIL → ELIGIBLE forbidden) |
| VE-MAP-R5-08 | Departure from default mapping (e.g. PASS → ELIGIBLE_WITH_NOTES) is **operator policy** — **SAFE UNKNOWN** at architecture layer |
| VE-MAP-R5-09 | `blocking_reasons` and `notes` are **views** of findings — not alternate finding stores |
| VE-MAP-R5-10 | HITL required on **all** recommendation states before R4 acts |
