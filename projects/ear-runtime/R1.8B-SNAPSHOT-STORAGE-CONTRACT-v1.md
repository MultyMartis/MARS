## Task 1 — What a persisted snapshot MUST contain

Sources: [EAR-SNAPSHOT-CONTRACT-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-CONTRACT-v1.md), [EAR-OPENCART-SNAPSHOT-SPEC-v1.md](../../shared/external-access-runtime/EAR-OPENCART-SNAPSHOT-SPEC-v1.md), [EAR-SNAPSHOT-LIFECYCLE-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-LIFECYCLE-v1.md), [EAR-STORAGE-MODEL-v1.md](../../shared/external-access-runtime/EAR-STORAGE-MODEL-v1.md).

### Required (architecture — must be persistable for a governed OpenCart snapshot)

| Category | Artifacts | Source |
|----------|-----------|--------|
| **Package identity** | `snapshot_id`, `snapshot_contract` (`ear-opencart-snapshot-v1`), `parent_contract` (`ear-snapshot-v1`), `site_id`, `created_at`, `ear_mode`, `operator_approval` | OpenCart spec § Package identity |
| **Environment** | `environment/` section with `environment_class` | OpenCart spec — always required |
| **Honesty** | `safe-unknown/` — entries for every missing or unverified required section at declared quality level | Contract + OpenCart spec |
| **Audit trail** | `acquisition-log/` (OpenCart name; maps to generic `access-log`) | OpenCart spec |
| **Quality gate** | `package_quality_level` (0–3) in metadata | OpenCart spec quality levels |
| **Contract sections per declared level** | Level 0: metadata min set; L1+: file-manifest, database-metadata, seo-structure, theme-info; L2+: extension-inventory, ocmod-inventory; L3: comprehensive coverage per spec | OpenCart spec § Snapshot quality levels |
| **Storage reference** | `bulk_root` or equivalent opaque external path in metadata | Storage model |
| **Immutability convention** | Write-once per `snapshot_id`; corrections = new id | Storage model, lifecycle |
| **Store state** | Persisted snapshot must record whether it is **stored-only** or **published** (see § Store vs Publish) | Publishing spec, G-09 resolution |

### Optional (architecture — may be omitted or referenced externally)

| Artifact | Notes |
|----------|-------|
| Inline path list with hashes in `file-manifest/` | **OR** `archive_ref` + sidecar manifest |
| Bulk payload (full trees, SQL exports) | External reference only; not required at L1–2 |
| `theme-info/`, `seo-structure/` detail beyond L1 minimum | Populated when acquisition permits |
| Prior snapshot reference in metadata | Lineage for partial runs (`p1` → `p2`) |
| `bulk_root` when no bulk exists | May be absent at Level 0 |
| Small metadata copies in git repo | Operator policy — not required |
| `acquisition_id` in snapshot package | Session correlation — **not** consumer-facing contract field; see § acquisition_id |
| Checksum of entire package | Recommended Phase 4 — **SAFE UNKNOWN** |
| Acquisition registry entry | Outside git — **SAFE UNKNOWN** location |
| Publish metadata (`published_at`, `published_by`, `consumer_target`) | Required only after Publish gate — R4 ownership for automation |

### Future (not R1.8 scope without charter)

| Artifact | Notes |
|----------|-------|
| Full OpenCart section population from live acquisition | R3 / live connector path |
| JSON Schema / official schema files | Not in v1 foundation |
| WORM, encryption, checksum registry | **SAFE UNKNOWN** |
| Central MARS snapshot catalog | Not claimed |
| Consumer notification webhooks | Not in v1 |
| Evidence Package long-term retention policy | **SAFE UNKNOWN** (G-07) |

## Task 3 — G-04 resolution: `acquisition_id` contract

Sources: [EAR-CONNECTOR-CONTRACT-v1.md](../../shared/external-access-runtime/EAR-CONNECTOR-CONTRACT-v1.md), [EAR-EVIDENCE-PACKAGE-v1.md](../../shared/external-access-runtime/EAR-EVIDENCE-PACKAGE-v1.md), [R1-CONTRACT-MAPPING-v1.md](R1-CONTRACT-MAPPING-v1.md).

### Contract definition

| Property | Definition |
|----------|------------|
| **Purpose** | Correlate one acquisition **session** across Request, Connector Input/Output, Evidence Package quarantine, validation, and eventual snapshot assembly. Enables audit trail and folder grouping without exposing session internals to consumers. |
| **Ownership** | **Runtime-generated** at session start — not operator JSON field ([R1-CONTRACT-MAPPING-v1.md](R1-CONTRACT-MAPPING-v1.md)). Operator supplies `site_id`, `pilot_id`, approval refs; runtime assigns `acquisition_id`. |
| **Uniqueness scope** | Unique per acquisition session. Hybrid Coordinator may share one `acquisition_id` across multiple connector legs ([EAR-EVIDENCE-PACKAGE-v1.md](../../shared/external-access-runtime/EAR-EVIDENCE-PACKAGE-v1.md) § Hybrid merge). Never reused across unrelated sessions. |
| **Lifecycle** | **Born:** session start (before connector execution). **Active:** Acquire → Validate. **Referenced:** Store (folder grouping, acquisition-log). **Retired:** after successful snapshot store and/or per evidence retention policy — **SAFE UNKNOWN** duration ([R1.8A](R1.8A-PERSISTENCE-DESIGN-REVIEW-v1.md) G-07). |
| **Relationship to `snapshot_id`** | **1:1 default** — one validated acquisition session produces one `snapshot_id`. **1:N allowed** for Hybrid ordered package set under one `acquisition_id` — each leg may still get its own `snapshot_id` unless merge policy chartered (**SAFE UNKNOWN** for automated merge). `acquisition_id` is **not** a consumer citation id; consumers cite `snapshot_id` only ([EAR-SNAPSHOT-PUBLISHING-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-PUBLISHING-v1.md)). |
| **Consumer visibility** | **Not consumer-facing.** May appear in `acquisition-log/` for audit. Must not replace `snapshot_id` in consumer reports. |
| **Evidence Package** | Required identity field ([EAR-EVIDENCE-PACKAGE-v1.md](../../shared/external-access-runtime/EAR-EVIDENCE-PACKAGE-v1.md)). Runtime R1.6 model does **not** yet carry it — gap is expected; assign at translation layer before evidence persist. |
| **Format** | Architecture does **not** mandate syntax. [R1-CONTRACT-MAPPING-v1.md](R1-CONTRACT-MAPPING-v1.md) suggests UUID or structured id — **implementation choice deferred to R1.8 charter**. Illustrative structured form: `acq-{YYYYMMDD}-{site_id}-{short_seq}` — **not normative** until chartered. |
| **Persistence placement** | Evidence quarantine root keyed by `acquisition_id`; snapshot stored under or referencing same session — exact folder layout **SAFE UNKNOWN** (PC-04). `acquisition_id` recorded in `acquisition-log/`; optional sidecar index at store root. |

### Rules (contract only — no generator)

1. Generated once per session; echoed in Connector Output.
2. Never equal to `snapshot_id` (distinct namespaces).
3. Mock pipeline must use deterministic mock prefix (e.g. `acq-mock-…`) analogous to `snap-mock-…` — forbidden outside dry-run.
4. Fail closed: no connector execution without `acquisition_id` at translation boundary.

## Task 4 — G-05 resolution: production `snapshot_id` contract

Sources: [EAR-SNAPSHOT-CONTRACT-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-CONTRACT-v1.md), [EAR-OPENCART-SNAPSHOT-SPEC-v1.md](../../shared/external-access-runtime/EAR-OPENCART-SNAPSHOT-SPEC-v1.md), [EAR-SNAPSHOT-LIFECYCLE-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-LIFECYCLE-v1.md), [R1.7-SNAPSHOT-PACKAGE-MODEL-v1.md](R1.7-SNAPSHOT-PACKAGE-MODEL-v1.md).

### Canonical format (OpenCart path — locked for R1.8)

```
snap-{YYYYMMDD}-{site_id}-{sequence}
```

| Part | Required | Description |
|------|----------|-------------|
| Prefix | Yes | Literal `snap-` |
| `{YYYYMMDD}` | Yes | Acquisition date in operator timezone (date of Validate pass or Store — **SAFE UNKNOWN** which event anchors date; recommend Store date at persist charter) |
| `{site_id}` | Yes | Consumer registry id, e.g. `SITE-001` — lowercase normalization **SAFE UNKNOWN** |
| `{sequence}` | Yes | Partial-run sequence: `p1`, `p2`, … or monotonic run id per site audit |

**Generic contract alternate** (includes run label): `snap-20260601-site-001-run5-p1` — valid in architecture; OpenCart spec uses shorter form without `run5`. **R1.8 OpenCart path uses shorter form**; optional `run_label` may live in metadata, not id string.

### Optional parts (metadata — not in id string)

| Part | Location |
|------|----------|
| `run_label` / charter id | `metadata/` or `acquisition-log.hitl_reference` |
| `acquisition_id` | `acquisition-log/` — cross-reference only |
| Prior snapshot | `metadata.prior_snapshot_ref` |

### Examples

| Example | Meaning |
|---------|---------|
| `snap-20260604-SITE-001-p1` | First partial snapshot for SITE-001 on 2026-06-04 |
| `snap-20260604-SITE-001-p2` | Second partial — supersedes p1 for active consumer use when published |
| `snap-mock-SITE-001-mock` | **Mock only** — R1.7 dry-run; **forbidden** in production store or publish |

### Immutability rules

| Rule | Source |
|------|--------|
| Once **Stored**, artifacts for `snapshot_id` are not overwritten | Storage model |
| Corrections require new acquisition → new `snapshot_id` | Lifecycle, publishing |
| In-place metadata edit after Publish discouraged; prefer supersession | Storage model |
| Published `snapshot_id` is consumer citation key | Publishing, OCPilot integration |

### Supersession rules

| Situation | Behavior |
|-----------|----------|
| Higher quality partial run | New `snapshot_id` (e.g. `p2`); prior moves toward Archive when superseded |
| Same-day re-acquisition | New sequence suffix — never reuse id |
| Validate failure | No `snapshot_id` assigned for publish; candidate may remain operator-held without consumer id |
| Store without Publish | `snapshot_id` exists and is immutable; consumer **must not** intake until Publish |

### Mock vs production boundary

| Context | Id format |
|---------|-----------|
| R1.7 in-memory mock | `snap-mock-{site_id}-{source}` |
| R1.8+ production persist | `snap-{YYYYMMDD}-{site_id}-{sequence}` |
| Transformation | At persist boundary only — mock ids **never** written to production storage paths |

**No generator implementation in R1.8B** — policy only.

## Task 5 — G-09 resolution: Store vs Publish

Sources: [EAR-SNAPSHOT-LIFECYCLE-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-LIFECYCLE-v1.md), [EAR-SNAPSHOT-PUBLISHING-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-PUBLISHING-v1.md), [EAR-STORAGE-MODEL-v1.md](../../shared/external-access-runtime/EAR-STORAGE-MODEL-v1.md).

### Lifecycle placement

```
Acquire → Validate → Store → Publish → Consume → Archive
```

([EAR-SNAPSHOT-LIFECYCLE-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-LIFECYCLE-v1.md) omits Publish in diagram; [EAR-SNAPSHOT-PUBLISHING-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-PUBLISHING-v1.md) and [EAR-STORAGE-MODEL-v1.md](../../shared/external-access-runtime/EAR-STORAGE-MODEL-v1.md) insert Publish between Store and consumer access. **Normative union:** both Store and Publish are distinct gates after Validate.)

### Precise distinction

| Dimension | **Store** | **Publish** |
|-----------|-----------|-------------|
| **Purpose** | Immutable placement of validated snapshot artifacts in operator-controlled storage | Explicit consumer visibility gate — intake may begin |
| **Audience** | Operator, EAR, backup policy | Registered consumers (OCPilot, future) |
| **Prerequisite** | Validate pass | Validate pass **and** Store complete |
| **Consumer visibility** | **None** by default — stored-unpublished is valid state | **Required** for Consume stage |
| **Primary owner** | Operator (bulk placement); EAR (metadata references) | Operator (HITL publish approval); EAR (records publish in log/metadata) |
| **Outputs** | Immutable artifact tree/index keyed by `snapshot_id`; `bulk_root` reference | Consumer-visible identity + reference to stored location; `published_at`, `consumer_target` in acquisition-log/metadata |
| **Failure modes** | Wrong tier, mutable overwrite, secrets in package | Skipped Validate, credential leak, quality level misclaim |
| **R1.8 scope** | **In scope** — persist stored-unpublished snapshots | **Out of scope** — R4 Snapshot Publisher |
| **R4 scope** | — | Publish workflow automation and consumer registry pointer |

### Minimum state transition requirements

| Transition | Requirements |
|------------|--------------|
| Validate → Store | Contract version declared; quality level honest; `safe-unknown` covers gaps; no secrets in package; `snapshot_id` assigned |
| Store → Publish | Operator HITL publish approval; storage placement confirmed; acquisition-log records `published_by` / `published_at`; `consumer_target` set |
| Store (held) | Valid **terminal state for R1.8** — snapshot persisted with `publish_state: stored` (conceptual field — exact encoding **SAFE UNKNOWN**) |
| Publish → Consume | Consumer reads **published reference only** |
| Supersession → Archive | Newer published snapshot replaces active consumer default; prior `snapshot_id` retained in archive tier |

### Ownership

| Stage | Operator | EAR | Consumer |
|-------|----------|-----|----------|
| Store | Bulk placement, retention policy | Write metadata refs, acquisition-log | No access |
| Publish | Publish approval | Record publish metadata | Intake after publish only |
| Archive | Retention, re-tier bulk | Optional catalog — not v1 | Historical cite only |

### Archive implications

- Stored-but-never-published snapshots may be archived or deleted per operator policy — **SAFE UNKNOWN** ([R1.8A](R1.8A-PERSISTENCE-DESIGN-REVIEW-v1.md) G-07).
- Published snapshots move to archive tier when superseded; remain citeable from reports.
- Archive is **not** active publish target.

### Combined operator action

Store + Publish in one operator action is **allowed** if both gate checklists satisfied ([EAR-SNAPSHOT-PUBLISHING-v1.md](../../shared/external-access-runtime/EAR-SNAPSHOT-PUBLISHING-v1.md)). R1.8 implements Store only; combined action remains manual/R4.
