## Purpose

Define the canonical **Consumer Visibility Model** — authoritative R4 visibility semantics for who may access what after Publish and what remains forbidden before Publish. Frozen dataclass models in `runtime/shared/consumer_visibility_models.py`.

Model layer only: no Publish Engine, no CLI, no persistence, no consumer registry implementation, no access control implementation.

**Critical disambiguation (mandatory):**

| Concept | Owner | In R4.3 registry? |
|---------|-------|-------------------|
| **Visibility semantics** | **R4** | **Yes** — states, rules, targets |
| **publish_state lifecycle** | **R4.2** | **Referenced** — mapped to visibility states |
| **Consumer intake execution** | **Consumer programs** | **No** — target definition only |
| **Access control / credentials** | **Consumer / operator** | **No** — forbidden paths documented |
| **Quality certification** | **R5** | **No** — visibility does not imply quality |
| **Snapshot content** | **R3** / **R5** freeze | **No** — read via published reference only |
| **Evidence quarantine** | **R2** | **No** — never consumer-visible |

R4.3 registry covers **consumer visibility semantics** only — not publish_state transitions (R4.2), not quality possession (R5), not consumer registry physical encoding.

## Model hierarchy

```text
ConsumerVisibilityRegistry
├── visibility_states[]            → ConsumerVisibilityState
│   ├── not_visible
│   ├── visible
│   ├── restricted
│   └── historical
├── visibility_rules[]             → ConsumerVisibilityRule
│   ├── CB-R4-01 … CB-R4-05       (charter consumer boundary)
│   └── CV-R4-01 … CV-R4-07       (visibility invariants)

    ├── operator
    ├── ocpilot
    └── registered_consumer
```

## Canonical visibility states

| State | Meaning | publish_state binding | Intake permitted | Active default | Owner |
|-------|---------|----------------------|------------------|----------------|-------|
| **not_visible** | No consumer visibility grant — pre-Publish | `stored_unpublished` (+ pre-Validate stages) | **No** | **No** | **R4** |
| **visible** | Publish executed; grant for registered `consumer_target` | `published` | **Yes** — registered consumers | **Yes** | **R4** |
| **restricted** | Policy-limited visibility — archive tier, governance | `archived` | **No** — policy-dependent cite | **No** | **Operator** policy |
| **historical** | Superseded published snapshot — cite-only | `superseded` | **No** — historical cite when policy permits | **No** | **R4** records |

## Mandatory answers

### 1. What makes a snapshot visible

A snapshot is **visible** when **all** of the following are true:

| # | Condition | Owner |
|---|-----------|-------|
| 1 | R4 Publish gate executed — `publish_state` is **published** (R4.2) | **R4** |
| 2 | R4 consumer visibility grant issued — `PublishedSnapshotConsumerVisibility.visibility_state` is `granted` | **R4** |
| 3 | Registered `consumer_target` declared and matched (e.g. `ocpilot`) — CV-R4-05 | **R4** / operator |
| 4 | Operator Publish HITL approval recorded — distinct from Validate sign-off | **Operator** |
| 5 | Gate G4 (Publish → Consume) satisfied | **R4** |
| 6 | Consumer intake references published `snapshot_id` — CB-R4-01 | Consumer programs |
| 7 | Snapshot is **not** superseded as active default — if superseded, visibility becomes **historical** | **R4** |

**Critical invariant:** Visible means **logical permission to begin Consume** for the registered consumer — not intake execution, not credential handoff, not quality certification.

### 2. What makes a snapshot not visible

A snapshot is **not_visible** when **any** of the following apply:

| Condition | Why |
|-----------|-----|
| R3 candidate assembly only — no R5 Validate | Uncertified — pre-Validate |
| R5 validated — certification recorded, Publish not executed | No visibility grant |
| `publish_state` is **stored_unpublished** | Store audience only — CB-R4-02 |
| R5 Validate PASS without R4 Publish | Validate ≠ Publish (VAL-INV-02) |
| R5 ELIGIBLE recommendation without R4 Publish | Recommendation ≠ execution (PE-INV-R5-01) |
| Store persist without Publish gate | G3 ≠ G4 |
| `consumer_target` configured without Publish execution | Metadata without gate |
| Copy to consumer path without Publish | Lifecycle violation — CB-R4-01 |
| Evidence quarantine repackaged as snapshot | Not consumer target — CV-R4-04 |
| `consumer_target` mismatch — grant issued for different target | CV-R4-05 |
| Archived never-published snapshot | No grant ever issued |

**Valid design:** not_visible is **expected** for stored-unpublished — absence of visibility is not a Store defect.

### 3. What makes a snapshot restricted

A snapshot is **restricted** when:

| # | Condition | Owner |
|---|-----------|-------|
| 1 | `publish_state` is **archived** — retention tier applied | **Operator** |
| 2 | Operator retention or governance policy limits cite access | **Operator** |
| 3 | Snapshot removed from active operator/consumer default paths | Retention semantics |
| 4 | Physical tree may remain — access governed by policy, not R4 grant | **Operator** bulk |
| 5 | **Not** active publish or intake target — CV-R4-07 | Policy-dependent |

Restricted ≠ not_visible for all audiences: operator may retain read access per retention policy. Registered consumers **must not** treat restricted snapshots as active intake defaults.

### 4. What makes a snapshot historical

A snapshot is **historical** when:

| # | Condition | Owner |
|---|-----------|-------|
| 1 | Snapshot was previously **published** | Prior **R4** Publish |
| 2 | Newer R4 Publish for **same site** succeeded — `publish_state` → **superseded** | **R4** |
| 3 | Prior `snapshot_id` and immutable tree **retained** — not deleted | Architecture |
| 4 | **Not** active consumer registry default — CV-R4-06 | Consumer policy |
| 5 | Historical citation from reports and audit records **permitted** when policy allows | Governance |

Historical ≠ invalid. Historical = **no longer active default** for new consumer intake on that site; prior published `snapshot_id` citations remain honest audit records.

### 5. Why visibility begins only after Publish

| Reason | Authority |
|--------|-----------|
| **Architecture rule** — Consumers consume **published snapshots only** | EAR-SNAPSHOT-PUBLISHING-v1 § Core rules |
| **Audience separation** — Store audience is operator/EAR; consumer audience requires explicit Publish gate | R1.8B § Store vs Publish |
| **Secrets risk** — Pre-Validate candidate may carry uncertified content; quarantine never consumer input | EAR-EVIDENCE-PACKAGE-v1 |
| **Lifecycle** — Acquire → Validate → Store → **Publish** → Consume | EAR-SNAPSHOT-LIFECYCLE-v1 |
| **Registry rule** — CV-R4-01: no consumer path write before Publish completes | R4-CHARTER |
| **Gate semantics** — G3 (Store) satisfied ≠ G4 (Publish → Consume) executed | EAR-READINESS-GATES-v1 |

**Critical invariant:** Validate pass, Store placement, and ELIGIBLE recommendation **do not** grant visibility — only R4 Publish with operator approval does.

### 6. Why visibility does not imply currentness

| Reason | Authority |
|--------|-----------|
| **Supersession** — A **visible** snapshot at Publish time may later become **historical** when newer publish succeeds | R4.2 PST-R4-02; CV-R4-02 |
| **Active default pointer** — Visibility grant at Publish does not permanently bind site to this `snapshot_id` | Architecture **SAFE UNKNOWN** automation |
| **Separate concerns** — Visibility answers *may consumer intake begin?* not *is this the current site default?* | R4 mission |
| **Historical cite** — Superseded snapshots remain citeable — visibility state changes, id validity does not | R4.2 § superseded |
| **Archive transition** — Published → archived moves visibility to **restricted** — not currentness deletion | R4.2 PST-R4-03 |

### 7. Why visibility does not imply quality

| Reason | Authority |
|--------|-----------|
| **Certification vs promotion** — Quality possession assessed at Validate (R5); visibility granted at Publish | R5.3; CV-R4-03 |
| **Frozen claim only** — Consumer reads **published** `package_quality_level` — frozen from R5; R4 does not certify | R4.1; Q-INV-R5-01 |
| **Visibility answers access** — R4 answers *may this become consumer-visible?* not *what quality does it possess?* | R5.6 vs R4 mission |
| **Consumer-side validation distinct** — CB-R4-04: intake contract check ≠ EAR Validate | Consumer programs |
| **L0 published honesty** — Visible L0 snapshot is permitted — visibility does not upgrade quality | R5.3 three-stage semantics |

| Access | Allowed | Condition |
|--------|---------|-----------|

## Visibility ownership review

| Concern | R2 | R3 | R5 | R4 |
|---------|----|----|----|----|
| Evidence / quarantine visibility | **Owns** — never consumer | Reads | Reads (Validate) | **Forbidden** exposure |
| Snapshot section content | — | **Owns** write | Certifies freeze | **Read-only** via published cite |
| Quality certification | Forbidden | Placeholder | **Owns** | **No role** — freeze only at Publish |
| Validate / redaction | Policy | Avoid copy | **Owns** | **No role** |
| Store placement read (operator) | — | Candidate write | Validated marker | **Precondition** — not consumer grant |
| Consumer visibility semantics | — | — | — | **Owns** |
| Visibility grant emission | — | — | **Forbidden** | **Owns** |
| Consumer intake execution | — | — | — | **Forbidden** — consumer programs |
| Access control / credentials | — | — | — | **Forbidden** — consumer/operator |
| Archive retention policy | — | — | — | Pointer only; **Operator owns** |

**Verified:** R4 owns visibility semantics only. R4 does **not** own content, quality, validation, evidence, consumer implementation, or access control.

## Publish dependency

```text
R5 Validate bundle
        ↓
Store — stored_unpublished          visibility: not_visible
        ↓
Operator Publish HITL
        ↓
R4 Publish execution
        ↓
publish_state: published              visibility: visible (registered consumer_target)
        ↓
Newer Publish for same site
        ↓
publish_state: superseded             visibility: historical
        ↓
Operator archive policy
        ↓
publish_state: archived               visibility: restricted
```

| Stage | publish_state (R4.2) | visibility_state (R4.3) | Consumer intake |
|-------|------------------------|-------------------------|-----------------|
| Pre-Publish Store | `stored_unpublished` | `not_visible` | **Forbidden** |
| Active published | `published` | `visible` | **Permitted** — registered target |
| Superseded | `superseded` | `historical` | **Forbidden** as active default |
| Archived | `archived` | `restricted` | **Policy-dependent** |

## Store vs Visibility distinction

| Dimension | **Store (R1.8)** | **Visibility (R4.3)** |
|-----------|------------------|-------------------------|
| **Purpose** | Immutable validated placement | Consumer access permission semantics |
| **Audience** | Operator, EAR | Registered consumers |
| **Pre-Publish** | Valid terminal state | **not_visible** — by design |
| **Post-Publish** | Same tree — unchanged | **visible** grant for consumer_target |
| **Owner** | Operator bulk; R1.8 layout | **R4** semantics; operator retention for restricted |
| **Implies quality** | Records R5 certified level | **No** — CV-R4-03 |
| **Implies currentness** | N/A | **No** — CV-R4-02 |

Store satisfies G3; visibility grant satisfies G4. **Store ≠ Visibility.**

## Superseded and archived behaviour

### Superseded

| Behaviour | Detail |
|-----------|--------|
| Trigger | PST-R4-02 — newer R4 Publish for same `site_id` |
| visibility_state | `historical` |
| Active default | **Removed** — CV-R4-06 |
| `snapshot_id` validity | **Retained** — immutable citation key |
| Tree | **Retained** — no deletion |
| Quality claim | Frozen at time of original Publish |
| Consumer new intake | **Forbidden** as active default — historical cite when policy permits |

### Archived

| Behaviour | Detail |
|-----------|--------|
| Trigger | PST-R4-03 / PST-R4-04 / PST-R4-05 — operator retention policy |
| visibility_state | `restricted` |
| Active default | **Removed** |
| Deletion | **Not implied** — retention marker only (R4.2) |
| Reactivation | **Forbidden** — PST-R4-F04; new acquisition required |
| Consumer access | **Policy-dependent** — CV-R4-07 |
