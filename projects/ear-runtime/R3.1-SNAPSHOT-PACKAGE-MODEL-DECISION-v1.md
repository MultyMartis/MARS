---

## Rationale

1. **Spec-aligned structure** — `SnapshotPackage` mirrors EAR-OPENCART-SNAPSHOT-SPEC-v1 logical tree with all ten OpenCart sections plus separated identity block.
2. **Identity continuity** — `SnapshotIdentity` carries `snapshot_id` (R3), `acquisition_id` (R2 survival), `site_id` (site_ref transform), `snapshot_contract` — no evidence identity drift fields.
3. **Boundary respect** — No publish metadata, no R5 validation logic, no quality certification; `package_quality_level` on metadata only as candidate integer field.
4. **Safe-unknown support** — Dedicated section model with typed entries sufficient for R3.4 propagation rules.
5. **Serialization demonstrable** — `SnapshotPackage(...)` → `to_dict()` → `json.dumps()` succeeds locally.

**PASS WITH NOTES** (not bare **PASS**): R1.7 `snapshot_models.py` retained for mock pipeline; `parent_contract` on metadata not identity (documented split); section models are skeletal shells — population deferred to R3.3–R3.5; no wiring to CLI or builders yet.

**FAIL** would apply if model included publish fields, validation logic, or conflated evidence/snapshot identity — **none apply**.
