## Purpose

Define the canonical **Publish Metadata Model** — authoritative R4-owned publication facts assigned at Publish only — as frozen dataclass models in `runtime/shared/publish_metadata_models.py`.

Model layer only: no Publish Engine, no CLI, no persistence, no Store adapter, no metadata write implementation.

**Critical disambiguation (mandatory):**

| Concept | Owner | In R4.4 registry? |
|---------|-------|-------------------|
| **Publish metadata fields** | **R4** | **Yes** — five canonical fields |
| **Publication audit record** | **R4** | **Yes** — `PublishMetadataAudit` |
| **Snapshot identity / content** | **R3** / **R5** freeze | **No** — cited only via `snapshot_id` |
| **Quality certification** | **R5** | **No** — freeze on R4.1 aggregate only |
| **Validation artefacts** | **R5** | **No** — opaque audit citations only |
| **Consumer visibility grant** | **R4.3** | **No** — separate semantics |
| **Store placement metadata** | **R1.8** | **No** — precondition only |

Publish Metadata represents **publication facts only** — when promotion occurred, by whom, for which consumer target, why, and which audit record attests the gate.

## Model hierarchy

```text
PublishMetadataRegistry
├── metadata_fields[]              → PublishMetadataField
│   ├── published_at               (R4 assigns at Publish)
│   ├── published_by               (R4 records operator HITL ref)
│   ├── consumer_target            (operator declares; R4 records)
│   ├── publish_reason             (R4 records operator rationale)
│   └── publish_audit_ref          (R4 cites PublishMetadataAudit)
└── invariants[]                   → PublishMetadataInvariant
    └── PM-INV-R4-01 … PM-INV-R4-08

PublishMetadata                    → aggregate five canonical fields + snapshot_id citation
PublishMetadataReference           → lightweight pointer
PublishMetadataAudit               → gate satisfaction audit — not ValidationResult
```

All types are **frozen** `@dataclass` instances. Immutable collections use `tuple`; `to_dict()` emits JSON-safe lists.

## Mandatory answers

### 1. What metadata is added by Publish

| Added field | Model location | Owner | Meaning |
|-------------|----------------|-------|---------|
| `published_at` | `PublishMetadata` | **R4** | Publish execution timestamp |
| `published_by` | `PublishMetadata` | **R4** | Operator / HITL identity who approved Publish |
| `consumer_target` | `PublishMetadata` | **R4** records | Registered consumer program routing label |
| `publish_reason` | `PublishMetadata` | **R4** | Operator-facing rationale for promotion |
| `publish_audit_ref` | `PublishMetadata` | **R4** | Citation to gate satisfaction audit record |
| `PublishMetadataAudit` record | Audit layer | **R4** | Full gate satisfaction context — optional expand beyond ref |

**Absent before Publish:** All five canonical fields. Store and Validate stages carry **no** publish metadata per PM-INV-R4-02.

### 2. What metadata survives from snapshot

| Surviving element | Source owner | R4 publish metadata behaviour |
|-------------------|--------------|-------------------------------|
| `snapshot_id` | **R3.2** | **Cited** on `PublishMetadata` — not reassigned |
| `acquisition_id`, `site_id`, contract refs | **R3.2** | **Not** publish metadata fields — remain on snapshot / R4.1 identity |
| OpenCart section tree | **R3** / **R5** freeze | **Not** publish metadata — content unchanged |
| `package_quality_level` on snapshot metadata | **R5** certified | **Not** canonical publish metadata — frozen on R4.1 aggregate only |
| `bulk_root` | Store / snapshot | **Not** publish metadata — cited on R4.1 publication |
| Validate timestamps / outcomes | **R5** | **Not** publish metadata — opaque audit citations only |
| Evidence / quarantine refs | **R2** | **Not** publish metadata — never included |

**Rule:** Publish metadata adds **publication facts** around unchanged snapshot identity — it does not duplicate or replace snapshot metadata.

### 3. Why publish metadata is not validation metadata

| Dimension | **Validation metadata (R5)** | **Publish metadata (R4)** |
|-----------|-------------------------------|----------------------------|
| **Purpose** | Contract certification, possession, redaction | Publication facts — promotion gate |
| **When assigned** | At EAR Validate | At R4 Publish only |
| **Owner** | **R5** | **R4** |
| **Examples** | `ValidationResult.outcome`, `validated_at`, findings | `published_at`, `published_by`, `publish_reason` |
| **Artefact** | `ValidationResult`, `ValidateReport` | `PublishMetadata`, `PublishMetadataAudit` |
| **Consumer role** | Operator audit — not intake authority | Consumer routing and audit citation |

Per PM-INV-R4-04: R5 artefacts may appear as **opaque citations** in `PublishMetadataAudit` — they must **never** be embedded as publish metadata fields or substituted for publication facts.

Validate pass **≠** Publish approval (VAL-INV-02). Validate timestamps **≠** `published_at`.

### 4. Why publish metadata is not quality metadata

| Dimension | **Quality metadata (R5)** | **Publish metadata (R4)** |
|-----------|----------------------------|----------------------------|
| **Purpose** | Possession assessment — what level L0–L3 is honestly possessed | Record that promotion occurred — not reassess possession |
| **Owner** | **R5** certifies | **R4** assigns publication facts only |
| **Field** | `certified_quality_level` on `ValidationResult` | No quality field in canonical five |
| **R4.1 freeze** | R5 value copied to `frozen_package_quality_level` | Separate aggregate field — PM-INV-R4-05 |
| **Inflation** | R5 forbids upgrade without possession | R4 forbids any quality change at Publish |

Per [R5.3-QUALITY-POSSESSION-MODEL-v1.md](R5.3-QUALITY-POSSESSION-MODEL-v1.md): same numeric value at candidate, certified, and published stages carries **different semantic stages**. Publish metadata does not carry quality stage semantics — that lives on R4.1 `quality_claim_stage: published`.

### 5. Why publish metadata is immutable after Publish

| Reason | Authority |
|--------|-----------|
| **Audit honesty** — `published_at`, `published_by`, `publish_reason` are historical facts of the promotion event | R4-CHARTER immutability rules |
| **Non-reversible gate** — published → stored_unpublished **forbidden** (PST-R4-F03) | R4.2 |
| **Consumer citation integrity** — reports cite publish facts tied to immutable `snapshot_id` | R1.8B; R3.2 |
| **Correction path** — new acquisition → new `snapshot_id`; not in-place metadata repair | R4-CHARTER § Published Snapshot Definition |
| **Discouraged in-place edit** — architecture explicitly discourages post-Publish metadata mutation | R1.8B; PM-INV-R4-03 |

Immutability is **policy and lifecycle semantics** at model layer — physical Store encoding of immutability is **SAFE UNKNOWN** until adapter implementation.

### 6. Why consumer_target does not imply visibility by itself

| Reason | Authority |
|--------|-----------|
| **Routing label only** — `consumer_target` names intended consumer program (e.g. `ocpilot`) | I-R4-09 |
| **Publish gate required** — visibility begins only after R4 Publish + operator HITL | CV-R4-01; R4.3 |
| **Visibility is separate model** — R4.3 `ConsumerVisibilityRegistry` owns grant semantics | R4.3 CVM-INV-R4-01 |
| **Config without Publish forbidden** — setting target in config without Publish does not publish | R4 Implementation Charter § What does not make a snapshot published |
| **Target mismatch rule** — grant must match registered target at visibility emission | CV-R4-05 |
| **publish_state binding** — `consumer_target` without `publish_state: published` remains `not_visible` | R4.2 + R4.3 mapping |

**Critical invariant:** `consumer_target` answers *for which registered consumer is this publish intended?* — not *may the consumer intake begin?* Visibility requires **published** state + visibility grant + matching target + Publish HITL.

## Publication ownership review

| Concern | R2 | R3 | R5 | R4 |
|---------|----|----|----|----|
| Evidence / quarantine metadata | **Owns** | Reads | Reads (Validate) | **No role** |
| Snapshot identity fields | — | **Owns** create | Cites | **Cites** `snapshot_id` only |
| Snapshot section metadata | — | **Owns** | Certifies freeze | **No role** |
| Validate timestamps / outcomes | — | — | **Owns** | **No role** — audit cite only |
| Quality certification metadata | Forbidden | Placeholder | **Owns** | **No role** — R4.1 freeze separate |
| Store placement metadata | — | Candidate write | Validated marker | **Precondition** — not publish metadata |
| **Publish metadata fields** | — | — | — | **Owns** |
| Publish audit record | — | — | — | **Owns** |
| Consumer visibility grant | — | — | **Forbidden** | **R4.3** — not metadata |
| Operator HITL refs | — | — | Validate sign-off | Publish approval in audit |

**Verified:** R4 owns publish metadata only. R4 does **not** own quality certification, validation results, evidence, or snapshot content.

## Relationship review

### R4.1 Published Snapshot

| R4.1 component | R4.4 binding |
|----------------|--------------|
| `PublishedSnapshotMetadata.published_at` | Same semantic field — R4.4 canonical registry |
| `PublishedSnapshotMetadata.published_by` | Same semantic field |
| `PublishedSnapshotMetadata.consumer_target` | Same semantic field — PM-INV-R4-06 applies |
| `PublishedSnapshotMetadata.frozen_package_quality_level` | **Not** publish metadata — PM-INV-R4-05 |
| `PublishedSnapshotPublication.operator_publish_approval_ref` | Lives on `PublishMetadataAudit` — not canonical field |
| `PublishedSnapshotPublication.validation_result_ref` | Audit precondition cite — PM-INV-R4-04 |

R4.1 aggregate embeds publish metadata subset; R4.4 registry is the **authoritative field contract** for publication facts.

### R4.2 Publish State

| publish_state | Canonical publish metadata |
|---------------|------------------------------|
| `stored_unpublished` | **Absent** — PM-INV-R4-02 |
| `published` | **Present** — all five fields required |
| `superseded` | **Immutable** — original publish facts retained |
| `archived` | **Immutable** — publish facts retained for audit |

### R4.3 Consumer Visibility

| Dimension | Publish metadata | Consumer visibility |
|-----------|------------------|---------------------|
| `consumer_target` field | Routing label recorded at Publish | Must match grant recipient |
| Visibility grant | **Not** a metadata field | R4.3 `visible` state |
| PM-INV-R4-06 | consumer_target alone ≠ visibility | CV-R4-01 requires Publish |

### R5 Validation

| R5 artefact | Publish metadata relationship |
|-------------|------------------------------|
| `ValidationResult` | Precondition — opaque `validation_result_ref` in audit only |
| `ValidateReport` | Operator context — not publish metadata |
| `PublishEligibilityRecommendation` | Gate input — `publish_eligibility_at_gate` in audit only |
| Validate timestamps | **Not** `published_at` |

### Store (R1.8B)

| Dimension | **Store metadata** | **Publish metadata** |
|-----------|-------------------|----------------------|
| When written | At validated snapshot persist | At R4 Publish only |
| Audience | Operator / EAR | Publication audit + consumer routing |
| Consumer fields | None | `consumer_target` — still requires Publish for visibility |
| Terminal state | stored_unpublished valid without Publish | Canonical fields **absent** until Publish |

**Store ≠ Publish metadata.** Store satisfies G3; publish metadata assignment satisfies publication record at G4.

## Invariants (PM-INV-R4)

| ID | Invariant |
|----|-----------|
| PM-INV-R4-01 | Publish metadata records **publication facts only** — not validation, quality, evidence, or content |
| PM-INV-R4-02 | Canonical fields assigned **at Publish only** — absent pre-Publish |
| PM-INV-R4-03 | Publish metadata **immutable after Publish** — in-place edit discouraged |
| PM-INV-R4-04 | Publish metadata **≠** validation metadata — R5 owns Validate artefacts |
| PM-INV-R4-05 | Publish metadata **≠** quality metadata — quality freeze on R4.1 aggregate only |
| PM-INV-R4-06 | `consumer_target` **does not imply visibility** by itself |
| PM-INV-R4-07 | **Store vs Publish** — Store persist does not assign publish metadata |
| PM-INV-R4-08 | R4 owns publish metadata **only** — boundary preserved |
