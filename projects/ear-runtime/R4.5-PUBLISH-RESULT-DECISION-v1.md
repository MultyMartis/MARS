## Rationale

1. **Distinct artefact** — PublishResult documented separately from `ValidationResult`, `PublishEligibilityRecommendation`, and `PublishedSnapshot` per N-R4-03, PR-INV-R4-01.
2. **Three states chartered** — SUCCESS, BLOCKED, DEFERRED — each with meaning, upstream relationship, output ref rules, and non-goals (SC-R4.5-01).
3. **Fail closed on gate violations** — NOT_ELIGIBLE and ValidationResult FAIL map to BLOCKED on default path (SC-R4.5-02; PR-MAP-R4-01).
4. **Validation boundary preserved** — BLOCKED ≠ validation failure explicitly documented (PR-INV-R4-05; SC-R4.5-03).
5. **SUCCESS honesty** — Promotion execution only; no quality certification (PR-INV-R4-06; SC-R4.5-04).
6. **DEFERRED required** — Pending HITL and incomplete attempts distinguished from hard block (PR-INV-R4-07).
7. **Contract fields reviewed** — All nine requested fields plus audit convenience fields; output refs SUCCESS-only (PR-INV-R4-04).
8. **Ownership clean** — R4 owns PublishResult; no absorption of R2 evidence, R3 assembly, R5 validation/quality.

**PASS WITH NOTES** (not bare **PASS**): no dataclass module yet (deferred R4.7+); result builder deferred R4.7; persistence and expanded audit schema **SAFE UNKNOWN**; R4.6 publish flow consumes this contract next.

**FAIL** would apply if PublishResult substituted ValidationResult, embedded PublishedSnapshot, omitted DEFERRED, or certified quality on SUCCESS — **none apply**.
