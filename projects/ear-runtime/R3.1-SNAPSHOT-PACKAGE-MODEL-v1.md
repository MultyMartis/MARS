## Model structure

```text
SnapshotPackage
├── identity              → SnapshotIdentity
├── metadata              → SnapshotMetadata
├── environment           → SnapshotEnvironment
├── file_manifest         → SnapshotFileManifest
│   ├── path_entries[]    → SnapshotManifestPathEntry
│   └── file_counts[]     → SnapshotFileCount
├── theme_info            → SnapshotThemeInfo
├── extension_inventory   → SnapshotExtensionInventory
│   └── installed_extensions[] → SnapshotExtensionEntry
├── ocmod_inventory       → SnapshotOcmodInventory
│   └── modifications[]   → SnapshotOcmodEntry
├── database_metadata     → SnapshotDatabaseMetadata
├── seo_structure         → SnapshotSeoStructure
├── safe_unknown          → SnapshotSafeUnknown
│   └── entries[]         → SnapshotSafeUnknownEntry
└── acquisition_log       → SnapshotAcquisitionLog
```

**Rationale for structure:** Matches normative logical tree in [EAR-OPENCART-SNAPSHOT-SPEC-v1.md](../../shared/external-access-runtime/EAR-OPENCART-SNAPSHOT-SPEC-v1.md) § Logical package structure and [R3-IMPLEMENTATION-CHARTER-v1.md](R3-IMPLEMENTATION-CHARTER-v1.md) § Snapshot Package Model. Identity block is separated from `metadata/` section per R2.6 identity continuity rules — `snapshot_id` is R3-created and must not appear on evidence identity.

All model types are **frozen** `@dataclass` instances. Immutable collections use `tuple` internally; `to_dict()` emits JSON-safe lists.

## Identity model (`SnapshotIdentity`)

| Field | Type | Notes |
|-------|------|-------|
| `snapshot_id` | `str` | **Created by R3** at Store boundary |
| `acquisition_id` | `str` | **Survives** from R2 `EvidenceIdentity` — folder correlation |
| `site_id` | `str` | **Transforms** from evidence `site_ref` per OpenCart contract |
| `snapshot_contract` | `str` | Normative: `ear-opencart-snapshot-v1` |

**Explicit exclusions (identity block):**

- **No `package_quality_level`** — lives on `SnapshotMetadata` as candidate default; R5 certifies possession.
- **No `parent_contract`** — lives on `SnapshotMetadata` (parent link to `ear-snapshot-v1`).
- **No publish metadata** — `published_at`, `published_by` are **Future** / **R4**.

## Charter alignment review

| Question | Answer |
|----------|--------|
| Does model support identity continuity? | **Yes** — `acquisition_id` on `SnapshotIdentity`; `site_id` separate from evidence `site_ref` naming; `snapshot_id` R3-owned |
| Does model support safe-unknown? | **Yes** — dedicated `SnapshotSafeUnknown` with typed entries (`topic`, `reason`, `impact`, `unblock_hint`) |
| Does model avoid quality ownership? | **Yes** — `package_quality_level` is candidate field on metadata only; no certification logic; default L0 at assembly (R3.3+) |
| Does model avoid publish ownership? | **Yes** — no `published_at`, `published_by`, or consumer reference fields |
| Does model avoid validation ownership? | **Yes** — no validator, no eligibility result, no R5 quality possession checks |

## Serialization

Every model exposes `to_dict()` returning plain `dict` with stable snake_case keys. Nested models recurse via child `to_dict()`. Tuples serialize as lists. `None` allowed on optional numeric fields (`size_bytes`, `table_count`) for JSON compatibility.

**Demonstration:** `SnapshotPackage(...)` → `to_dict()` → `json.dumps()` — **PASS** (local model serialization only).
