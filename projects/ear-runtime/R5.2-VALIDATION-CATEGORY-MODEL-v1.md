## Purpose

Define the canonical **Validation Category** ownership model — what categories exist, what each category owns, and what each explicitly excludes — as frozen dataclass models in `runtime/shared/validation_category_models.py`.

Category layer only: no Validate Engine, no R5-V-* rules, no category scoring, no weights, no redaction scanners, no Publish execution.

**Critical disambiguation (mandatory):**

| Artefact | Role | Category model? |
|----------|------|-----------------|
| **ValidationCategory** | Ownership contract per R5 category | **Yes** — authoritative registry |
| **ValidationCategoryRef** (R5.1) | Lightweight finding pointer | **Compatible** — `category` string matches `category_id` |
| **R3 assembly eligibility** | Precondition | **Not represented** — excluded from all categories |
| **R5-V-* rules** | Future per-category checks | **Not in scope** — deferred post-R5.6 |

## Category hierarchy

```text
ValidationCategoryRegistry
└── categories[]                    → ValidationCategory
    ├── category_id                 → str (canonical constant)
    ├── description                 → ValidationCategoryDescription
    │   ├── title
    │   └── purpose
    ├── ownership                   → ValidationCategoryOwnership
    │   ├── owner                   → "R5"
    │   ├── owns[]
    │   └── does_not_own[]
    ├── scope                       → ValidationCategoryScope
    │   ├── primary_inputs[]
    │   └── r5_owns_certification
    └── non_goals[]

ValidationCategoryReference         → lightweight pointer (category_id)
```

All types are **frozen** `@dataclass` instances. Immutable collections use `tuple`; `to_dict()` emits JSON-safe lists.

**Flat category set:** seven peer categories — no nested subcategories at R5.2. Future R5-V-* rules attach to a single parent category id.

## Per-category ownership

### Identity

| Owns | Does NOT own |
|------|--------------|
| Snapshot identity certification | Snapshot creation / `snapshot_id` generation |
| Contract identity consistency | Section assembly |
| `snapshot_id` ↔ `acquisition_id` correlation review | Evidence identity structural gate (**R2**) |
| `site_id` and contract id adequacy at Validate | Publish (**R4**) |

### Structure

| Owns | Does NOT own |
|------|--------------|
| Contract structure adequacy vs spec | Section assembly / population (**R3**) |
| Section presence adequacy for certification target | Candidate skeleton enforcement (**R3-V-12**) |
| Forbidden snapshot field absence review | Publish (**R4**) |

### Possession

| Owns | Does NOT own |
|------|--------------|
| Section-level possession adequacy for target level | Section assembly (**R3**) |
| `safe-unknown` completeness review for certify level | L0–L3 level assignment (**Quality**) |
| Corroboration where architecture mandates | Candidate `package_quality_level: 0` default (**R3**) |

### Quality

| Owns | Does NOT own |
|------|--------------|
| Certified `package_quality_level` on Validate pass | Section assembly (**R3**) |
| L0–L3 certification mapping | Section possession adequacy (**Possession**) |
| Downgrade policy; inflation detection | Candidate quality placeholder (**R3**) |
| | Published quality freeze (**R4**) |

### Redaction

| Owns | Does NOT own |
|------|--------------|
| Candidate redaction review | Evidence quarantine policy (**R2.5**) |
| Secret / credential / unsafe-publication findings | R2 evidence serialization policy |
| Fail-closed blockers on mandatory exposure | Assembly copy-avoidance (**R3**) |
| | Automated redaction engine product |

### Readiness

| Owns | Does NOT own |
|------|--------------|
| Gate G2–G4 semantic mapping | Publish execution (**R4**) |
| Publish Eligibility Recommendation **inputs** | Consumer delivery |
| Precondition status for operator report | Operator HITL workflow product |
| | Validated Store state marker persist |

### Consistency

| Owns | Does NOT own |
|------|--------------|
| Evidence ↔ snapshot provenance alignment | R2 structural re-validation |
| Identity continuity cross-check | Evidence generation (**R2**) |
| Acquisition-log correlation with evidence chain | Evidence quarantine writes (**R2**) |

## Ownership matrix

Classification: **R5 owns** = EAR Validate certification scope; **R5 reads** = read-only input, not certification; **Not R5** = owned elsewhere.

| Concern | R5 category | R5 owns? | R5 does NOT own |
|---------|-------------|----------|-----------------|
| Evidence Package structural shape | — | **No** | **R2** |
| Handoff / assembly eligibility | — | **No** (precondition) | **R3** |
| `snapshot_id` creation | Identity | **No** — certifies only | **R3** creates |
| Snapshot identity certification | Identity | **Yes** | Assembly, publish |
| Contract ids on candidate | Identity | **Yes** — adequacy | R3 sets values |
| Section skeleton presence | Structure | **Reads** R3 output | R3-V-12 owns presence |
| Section structure adequacy | Structure | **Yes** | Assembly |
| Section content possession | Possession | **Yes** | Population |
| `safe-unknown` shape | — | **No** | **R3** (R3-V-14) |
| `safe-unknown` completeness for level | Possession | **Yes** | Gap propagation |
| L0–L3 certified level | Quality | **Yes** | Candidate default 0 |
| Redaction on candidate | Redaction | **Yes** | Evidence-stage policy |
| Gate G2–G4 semantics | Readiness | **Yes** | Gate execution |
| Publish Eligibility Recommendation | Readiness | **Inputs only** | **R4** decides |
| Evidence ↔ snapshot alignment | Consistency | **Yes** — read-only | R2 re-run |
| Publish execution | — | **No** | **R4** |
| Consumer readiness delivery | — | **Partial** — cert artefact | **R4** + consumers |

### Overlap prevention (complementary checks)

| Boundary | R3 / R2 role | R5 category role | Invariant |
|----------|--------------|------------------|-----------|
| Identity presence | R3-V-01–05 presence + continuity | Identity certifies adequacy | R3 creates; R5 certifies |
| Section skeleton | R3-V-12 non-`None` attrs | Structure certifies spec adequacy | VB-R3-07 |
| Safe-unknown list | R3-V-13 non-empty honesty | Possession certifies level completeness | VB-R3-08 |
| Quality numeric field | R3-V-07 enforces `0` only | Quality assigns certified 0–3 | VB-R3-06 |
| Evidence shape | R2 structural gate | Consistency reads for alignment | VAL-INV-01 |

No category re-implements R2-V-* or R3-V-* as certification.

## Model alignment review

Reviewed `runtime/shared/validation_result_models.py` — **no code changes required**.

| R5.1 type | R5.2 alignment | Conflict? |
|-----------|----------------|-----------|
| `ValidationCategoryRef.category: str` | Matches `ValidationCategory.category_id` and registry constants | **No** — field name differs (`category` vs `category_id`); value domain identical |
| `ValidationFinding.category` | Findings reference one of seven ids via `ValidationCategoryRef` | **No** |
| `ValidationSummary` | No per-category summary fields yet — deferred R5.5/R5.7 | **No conflict** — N-R5.1-01 addressed at registry layer |
| `ValidationResult.findings[]` | Category ids must ∈ `CANONICAL_VALIDATION_CATEGORY_IDS` at engine layer (future) | **No model conflict** — not enforced at R5.2 |
| Category constants in both modules | Same string values — R5.2 registry is authoritative definition | **PASS WITH NOTES** — optional dedup at R5.7 |

### Observations

1. **ValidationCategoryRef** (R5.1) remains the finding-level wrapper; **ValidationCategoryReference** (R5.2) is the registry-level pointer — interoperable via shared id strings.
2. **ValidationSummary.certified_quality_level** aligns with **Quality** category ownership — field on result model; logic deferred R5.3.
3. **ValidationRecommendation** aligns with **Readiness** category — advisory output; not duplicated in category model.
4. No enum introduced — both modules use string constants per charter.
