## Purpose

Define the canonical **Publish Flow** contract — the ordered, fail-closed gate sequence from **validated snapshot availability** through **PublishResult emission** — distinct from R5 Validate flow, Store placement mechanics, and Publish Engine implementation.

**Contract layer only:** no Publish Engine, no CLI, no persistence adapter, no Store adapter, no gate automation product, no HITL UI, no flow orchestrator code.

**Critical disambiguation (mandatory):**

| Artefact | Role | Publish Flow? |
|----------|------|---------------|
| **R5 Validate bundle** | `ValidationResult` + `ValidateReport` + `PublishEligibilityRecommendation` — certification and advisory inputs | **Precondition** — consumed before G1; not owned by flow |
| **Validate HITL sign-off** | Operator certification review — mandatory pilot | **Precondition** — before Store / Publish entry; **not** G4 |
| **Store placement** | Immutable stored-unpublished snapshot at R1.8 layout | **Precondition** — satisfies G1; owned by R1.8 / operator |
| **Publish Flow gates G1–G6** | Ordered R4 orchestration checklist from validated snapshot to PublishResult | **Yes** — this contract |
| **Publish HITL approval** | Operator Publish decision — distinct from Validate sign-off | **G4** — mandatory pilot |
| **Publish Execution** | Metadata assignment, state transition, visibility grant (future R4.7) | **G5** — R4 scope; not defined here as code |
| **`PublishResult`** | R4 attempt outcome — SUCCESS / BLOCKED / DEFERRED | **G6 output** — [R4.5](R4.5-PUBLISH-RESULT-CONTRACT-v1.md) |

**Rule (PF-INV-R4-01):** Publish Flow **orchestrates gate order and fail-closed semantics only**. It **never** certifies quality, **never** emits ValidationResult, **never** emits PublishEligibilityRecommendation, **never** assembles snapshot content, **never** mutates evidence, and **never** substitutes for operator HITL authority.

## Position in the pipeline

```text
R2 Evidence → R3 Candidate Snapshot
        ↓
R5 Validate (future R5.7)
        ↓
ValidationResult + ValidateReport + PublishEligibilityRecommendation
        ↓
Operator HITL #1 — Validate sign-off (mandatory pilot)     ← PRECONDITION — not G4
        ↓
Store — stored-unpublished validated snapshot (R1.8)        ← satisfies G1
        ↓
┌───────────────────────────────────────────────────────────┐
│  PUBLISH FLOW G1 → G2 → G3 → G4 → G5 → G6  (THIS CONTRACT) │
└───────────────────────────────────────────────────────────┘
        ↓
PublishResult (R4.5) + on SUCCESS: PublishedSnapshot ref, PublishMetadata, visibility grant
        ↓
Consume (consumer programs — not R4)
```

**R5 answers:** *Is this snapshot certified and advisedly publishable?*  
**Publish Flow answers:** *In what order must gates be satisfied before and during a Publish attempt, and when must the flow stop?*  
**R4 Publish execution (G5, future R4.7) answers:** *Did promotion mechanics run?*  
**PublishResult (G6) answers:** *What was the attempt outcome?*

## Publish Flow gate sequence (mandatory)

Gates are **ordered**. Each gate must **pass** before the next gate is entered on the **default path**. Failure at any gate **stops** forward progress unless explicitly mapped to **DEFERRED** (pending, not denied).

| Gate | Name | One-line purpose |
|------|------|------------------|
| **G1** | Validated Snapshot Available | Confirmed validated snapshot exists at Store or flagged in-memory equivalent |
| **G2** | ValidationResult Acceptable | R5 certification outcome permits Publish consideration (default: not FAIL) |
| **G3** | Publish Eligibility Recommendation Acceptable | R5 advisory gate permits Publish consideration (default: not NOT_ELIGIBLE) |
| **G4** | Operator HITL Publish Approval | Operator explicitly approves Publish — distinct from Validate sign-off |
| **G5** | Publish Execution | R4 promotion mechanics execute — metadata, state, visibility |
| **G6** | PublishResult Emission | R4 emits attempt outcome record — always after G5 attempt boundary |

**Invariant (PF-INV-R4-02):** G1–G6 are **Publish Flow gates**. They are **not** identical to EAR Readiness Gates G0–G4 ([EAR-READINESS-GATES-v1.md](../../shared/external-access-runtime/EAR-READINESS-GATES-v1.md)) — see § EAR readiness crosswalk.

**Invariant (PF-INV-R4-03):** Skipping gates on the default path is **forbidden**. Candidate-only input, missing R5 bundle, or Publish without G4 approval **must** fail closed.

## Gate definitions

### G1 — Validated Snapshot Available

| Field | Definition |
|-------|------------|
| **Purpose** | Confirm a **validated** snapshot — not candidate-only — is available as the Publish target with stable `snapshot_id` and immutable section tree citation |
| **Owner** | **R4** confirms availability; **R3** owns assembly content; **R1.8** / **operator** owns Store placement; **R5** owns validated marker semantics |
| **Required inputs** | `snapshot_id`; validated `SnapshotPackage` or Store-resident tree at `{output_root}/{acquisition_id}/snapshots/{snapshot_id}/` per R1.8B **or** in-memory equivalent flagged for pilot; `publish_state` **stored_unpublished** (R4.2); R5 bundle refs linkable to same `snapshot_id` |
| **Outputs on pass** | Gate satisfaction record in Publish attempt audit; flow may proceed to G2 |
| **Fail-closed behavior** | **Stop** — no G2 entry. Typical **PublishResult**: **BLOCKED** (candidate-only, missing snapshot, id mismatch, mock `snapshot_id` on production path) or **DEFERRED** (Store placement in progress) |
| **Stop conditions** | Snapshot absent; candidate-only without Validate; `snapshot_id` mismatch between Store and R5 bundle; forbidden transition per R4.2 (e.g. candidate → published bypass) |

**Non-goals:** Does not validate snapshot content (R5); does not write Store (R1.8); does not assemble sections (R3).

---

### G2 — ValidationResult Acceptable

| Field | Definition |
|-------|------------|
| **Purpose** | Confirm R5 **authoritative certification outcome** is acceptable for Publish consideration on the default path |
| **Owner** | **R5** owns `ValidationResult`; **R4** consumes and confirms — **never substitutes** |
| **Required inputs** | `ValidationResult` via `validation_result_ref`; `ValidationSummary.status`; optional `ValidateReport` via `validate_report_ref` for operator context |
| **Default accept criteria** | `ValidationStatus.PASS` or `ValidationStatus.PASS_WITH_NOTES` — **not** `FAIL` |
| **Outputs on pass** | Gate satisfaction recorded; flow may proceed to G3 |
| **Fail-closed behavior** | **Stop** at G2 on default path when status is **FAIL**. **PublishResult**: **BLOCKED**. R5 artefacts **unchanged** |
| **Stop conditions** | Missing `ValidationResult`; status **FAIL**; broken `validation_result_ref`; R5 bundle absent |

**Non-goals:** Does not re-run Validate; does not upgrade status; does not embed ValidationResult in PublishResult (R4.5 ref-only).

**Rule (PF-MAP-R4-01):** G2 **FAIL** → default **BLOCKED**. This is **Publish blocked**, not a re-recording of Validate failure (PR-INV-R4-05).

---

### G3 — Publish Eligibility Recommendation Acceptable

| Field | Definition |
|-------|------------|
| **Purpose** | Confirm R5 **advisory Publish gate signal** permits Publish consideration on the default path |
| **Owner** | **R5** owns `PublishEligibilityRecommendation`; **R4** consumes and confirms — **never emits or overrides** recommendation artefact |
| **Required inputs** | `PublishEligibilityRecommendation` via `publish_recommendation_ref`; `recommendation_state`; `blocking_reasons[]`; `required_operator_actions[]` when present |
| **Default accept criteria** | `ELIGIBLE` or `ELIGIBLE_WITH_NOTES` — **not** `NOT_ELIGIBLE` without audited operator override **after** G3 stop |
| **Outputs on pass** | Gate satisfaction recorded; on **ELIGIBLE_WITH_NOTES**, note acknowledgment required before G4; flow may proceed to G4 |
| **Fail-closed behavior** | **Stop** at G3 on default path when state is **NOT_ELIGIBLE**. **PublishResult**: **BLOCKED**. Operator override is **separate audited action** — does not mutate R5 artefacts (PE-INV-R5-01; R5.6 Validation Answers) |
| **Stop conditions** | Missing recommendation; **NOT_ELIGIBLE** on default path; broken `publish_recommendation_ref`; ELIGIBLE_WITH_NOTES without operator note review |

**Non-goals:** Does not regenerate recommendation; does not treat ELIGIBLE as Publish approval (PE-INV-R5-01; VAL-INV-02).

---

### G4 — Operator HITL Publish Approval

| Field | Definition |
|-------|------------|
| **Purpose** | Require **explicit operator approval** to Publish — distinct from Validate sign-off (HITL #1) and distinct from R5 advisory ELIGIBLE signal |
| **Owner** | **Operator** owns decision; **R4** records approval ref in Publish attempt audit — not embedded as certification |
| **Required inputs** | G1–G3 satisfied; operator Publish approval ref (`operator_publish_approval_ref` per R4.4 audit semantics); `consumer_target` declared; on ELIGIBLE_WITH_NOTES: notes reviewed |
| **Outputs on pass** | Approval ref captured in `audit_ref`; flow may proceed to G5 |
| **Fail-closed behavior** | **Stop** without G5 entry when approval absent or declined. **PublishResult**: **BLOCKED** (declined) or **DEFERRED** (approval pending) |
| **Stop conditions** | Missing Publish HITL ref; operator decline; approval pending; combined workflow awaiting operator action |

**Non-goals:** Does not auto-approve from ELIGIBLE; does not substitute Validate sign-off; does not execute Publish (G5).

**Critical:** G4 is **Publish HITL only**. Validate sign-off (HITL #1) is a **precondition** documented in § Dual HITL — mandatory before Store/Publish entry, **not** a substitute for G4.

---

### G5 — Publish Execution

| Field | Definition |
|-------|------------|
| **Purpose** | Execute R4 promotion mechanics — assign publish metadata, transition `publish_state` to **published**, emit consumer visibility grant, cite PublishedSnapshot — **no section mutation** |
| **Owner** | **R4** owns execution scope (future R4.7); **forbidden:** Validate dispatch, evidence generators, section writers, quarantine writers |
| **Required inputs** | G1–G4 satisfied; `PublishedSnapshot` contract fields per R4.1; `PublishMetadata` per R4.4; `consumer_target`; certified quality level **read and frozen** from R5 — no upgrade |
| **Outputs on pass** | `published_snapshot_ref`; `publish_metadata_ref`; visibility grant per R4.3; publish_state **published** per R4.2; execution audit entries |
| **Fail-closed behavior** | Execution error or precondition violation during attempt → **PublishResult** **BLOCKED** — no partial publish state, no output refs (PR-INV-R4-04) |
| **Stop conditions** | Forbidden section mutation detected; metadata assignment failure; visibility grant failure; mock id on production path; quality inflation attempt |

**Non-goals:** No Validate re-run; no quality certification; no consumer intake execution; no evidence lifecycle changes.

**Note:** G5 is **conceptual at contract layer**. Implementation deferred **R4.7** Publish Engine. Flow contract defines **when** G5 may start, not **how** code runs.

---

### G6 — PublishResult Emission

| Field | Definition |
|-------|------------|
| **Purpose** | Emit the sole authoritative R4 **Publish attempt outcome** — always after the G5 attempt boundary (executed, blocked before execution, or deferred) |
| **Owner** | **R4** owns PublishResult emission per R4.5; **R5** artefacts remain unchanged |
| **Required inputs** | Gate satisfaction record for G1–G5 path taken; mandatory refs: `validation_result_ref`, `publish_recommendation_ref`; `audit_ref` with HITL and gate checklist |
| **Outputs** | `PublishResult` with exactly one of **SUCCESS**, **BLOCKED**, **DEFERRED** per [R4.5-PUBLISH-RESULT-CONTRACT-v1.md](R4.5-PUBLISH-RESULT-CONTRACT-v1.md) |
| **Fail-closed behavior** | Flow **must not** skip PublishResult emission. Every Publish **attempt** produces exactly one result record — including blocked and deferred paths |
| **Stop conditions** | N/A — G6 is terminal for the Publish Flow attempt. Retry emits a **new** PublishResult; prior record remains immutable audit history |

**Non-goals:** Does not embed PublishedSnapshot; does not substitute ValidationResult; does not trigger consumer Consume.

## Gate → PublishResult mapping (default path)

| Last gate evaluated | Condition | Default `publish_result_state` |
|---------------------|-----------|--------------------------------|
| G1 | Snapshot unavailable / candidate-only | **BLOCKED** or **DEFERRED** |
| G2 | ValidationResult **FAIL** | **BLOCKED** |
| G3 | **NOT_ELIGIBLE** (no override) | **BLOCKED** |
| G4 | Approval pending | **DEFERRED** |
| G4 | Approval declined / absent (terminal) | **BLOCKED** |
| G5 | Execution completes | Proceed to G6 → **SUCCESS** |
| G5 | Execution fails mid-attempt | **BLOCKED** |
| G6 | All gates satisfied + G5 complete | **SUCCESS** — output refs populated |

**Rule (PF-MAP-R4-02):** Mapping aligns with PR-MAP-R4-01 in R4.5. Exact dispatch deferred R4.7; contract layer defines **obligatory** stop semantics.

## Dual HITL requirements

| HITL | When | Purpose | Owner | Publish Flow gate |
|------|------|---------|-------|-------------------|
| **HITL #1 — Validate sign-off** | After R5 Validate bundle emission; before / concurrent with Store | Operator reviews certification artefacts — `ValidationResult`, `ValidateReport`, recommendation | **Operator** | **Precondition** — not G4 |
| **HITL #2 — Publish approval** | After G1–G3; before G5 | Operator approves consumer visibility promotion for declared `consumer_target` | **Operator** | **G4** |

**Invariant (PF-INV-R4-04):** Validate sign-off **≠** Publish approval. Either alone is **insufficient** for default Publish path. Unattended auto-Publish is **forbidden** (ST-IC-R4-10).

## Recommendation → Publish Flow decision (default path)

| `recommendation_state` (G3) | Default flow behavior after G3 | G4 / G5 |
|-----------------------------|--------------------------------|---------|
| **ELIGIBLE** | May proceed to G4 after G1–G2 pass | Publish HITL **mandatory** — then G5 |
| **ELIGIBLE_WITH_NOTES** | May proceed after operator reviews notes | Publish HITL **mandatory** + notes acknowledgment — then G5 |
| **NOT_ELIGIBLE** | **Stop at G3** — G4/G5 **not entered** | **BLOCKED** PublishResult; override requires separate audited operator action — R5 artefacts unchanged |

## NOT_ELIGIBLE override path (exception)

| Step | Behavior |
|------|----------|
| 1 | G3 stops default path — **BLOCKED** unless operator initiates override |
| 2 | Operator records **explicit override with audit** — acceptance of risk |
| 3 | Override **does not** change `ValidationResult` or `PublishEligibilityRecommendation` retroactively |
| 4 | G4 Publish HITL **still mandatory** — override ≠ auto-Publish |
| 5 | Re-Validate after remediation remains **default policy** per R5.6 |

## EAR readiness crosswalk

Publish Flow gates map to architecture readiness gates for operator clarity — **different namespaces**.

| Publish Flow gate | EAR Readiness gate | R4 confirmation role |
|-------------------|--------------------|-----------------------|
| **G1** (snapshot available) | **G3** Store complete (partial) | Confirms stored-unpublished placement or equivalent |
| **G2** (ValidationResult) | **G2** Validate passed (outcome cite) | Confirms R5 certification acceptable — does not re-validate |
| **G3** (recommendation) | **G2** / advisory extension | Confirms advisory gate — consumes R5.6 only |
| **G4** (Publish HITL) | **G4** Publish approved (approval half) | Records operator Publish approval ref |
| **G5** (execution) | **G4** Publish approved (execution half) | Executes promotion — metadata, visibility |

## Mandatory disambiguation review

### 1. Why Publish requires dual HITL / operator approval

| Reason | Authority |
|--------|-----------|
| **Certification ≠ promotion** — Validate sign-off approves *contract certification*; Publish approval approves *consumer visibility* — different risk surfaces | VAL-INV-02; R4-CHARTER |
| **Advisory ≠ execution** — ELIGIBLE recommendation informs; it does not authorize Publish | PE-INV-R5-01; SC-R5.6-04 |
| **Audience separation** — Store/operator audience vs consumer audience requires explicit second gate | R1.8B § Store vs Publish |
| **Fail closed** — Two independent human checkpoints prevent pipeline auto-promotion | ST-IC-R4-10; N-R4-04, N-R4-05 |
| **Audit honesty** — Distinct refs for Validate sign-off vs Publish approval in audit trail | R4.4 `PublishMetadataAudit` |

### 2. Why NOT_ELIGIBLE blocks default Publish

| Reason | Authority |
|--------|-----------|
| **Fail closed on certification blockers** — R5 FAIL maps to NOT_ELIGIBLE by default | PE-MAP-R5-01; SC-R5.6-02 |
| **Advisory authority** — R5 declares snapshot not advisedly publishable; R4 must not bypass on default path | PE-INV-R5-01; IAC-R4-04 |
| **Remediation path** — Forces re-Validate after fix rather than silent consumer exposure | R5.6 NOT_ELIGIBLE definition |
| **G3 stop** — Publish Flow halts before G4/G5 — no promotion mechanics run | PF-INV-R4-03 |
| **Override is exception** — Audited operator action only; not automatic | R5.6 Validation Answers |

### 3. Why ELIGIBLE still requires HITL

| Reason | Authority |
|--------|-----------|
| **Recommendation is advisory** — ELIGIBLE means *consideration permitted*, not *Publish approved* | PE-INV-R5-01; SC-R5.6-04 |
| **Business risk** — R5 certifies contract; operator accepts deployment to `consumer_target` | EAR-READINESS-GATES G4 |
| **G4 mandatory** — Publish Flow cannot enter G5 without Publish HITL ref | PF-INV-R4-04 |
| **No auto-Publish** — Pipeline must not treat ELIGIBLE as SUCCESS | VAL-INV-02; SC-R4.6-03 |
| **Notes path** — ELIGIBLE_WITH_NOTES adds review obligation — still requires G4 | R5.6 ELIGIBLE_WITH_NOTES |

### 4. Why Store must exist before Publish

| Reason | Authority |
|--------|-----------|
| **G1 precondition** — Publish targets validated **stored** snapshot — not floating candidate | R1.8B; PF G1 definition |
| **Immutability** — Store establishes immutable citation key for consumer promotion | R4.1; EAR-STORAGE-MODEL-v1 |
| **Lifecycle order** — Validate → Store → Publish → Consume — skipping Store breaks audit trail | EAR-SNAPSHOT-LIFECYCLE-v1 |
| **Audience gate** — stored-unpublished is operator/EAR visible only; Publish promotes same tree | R1.8B § Store vs Publish |
| **G3 ≠ G4** — Store placement (EAR G3) satisfied ≠ Publish executed (EAR G4) | R4-IMPLEMENTATION-CHARTER § Why Store ≠ Publish |
| **Pilot exception** — In-memory path **flagged** for contract/dev only — production default requires Store | R4.5 SUCCESS preconditions |

### 5. Why PublishResult is emitted after attempt

| Reason | Authority |
|--------|-----------|
| **Outcome record** — PublishResult documents *what happened* — cannot precede attempt boundary | R4.5 Purpose; G6 definition |
| **Three honest states** — SUCCESS, BLOCKED, DEFERRED all require post-attempt emission | PR-INV-R4-03 |
| **Audit trail** — Every attempt — including blocked at G2/G3/G4 — produces receipt | PR-INV-R4-01 |
| **Separation from promotion** — PublishedSnapshot exists only after successful G5; PublishResult always emitted at G6 | R4.5 § PublishResult ≠ PublishedSnapshot |
| **Retry semantics** — New attempt → new PublishResult; prior immutable | DEFERRED definition R4.5 |

### 6. Why R4 cannot bypass R5

| Reason | Authority |
|--------|-----------|
| **Ownership** — Quality certification, ValidationResult, recommendation emission — **R5 only** | R4-CHARTER § Why R4 does not own quality |
| **No re-Validate at Publish** — R4 consumes R5 bundle; forbidden to substitute R2/R3 pass for R5 | VAL-INV-01; VB-R3-01; ST-R4-01 |
| **Mandatory refs** — PublishResult requires `validation_result_ref` and `publish_recommendation_ref` — no orphan Publish | PR-INV-R4-02 |
| **G2/G3 hard gates** — Flow stops without acceptable R5 artefacts | PF-INV-R4-03 |
| **Inflation prevention** — Certified quality assigned at R5; R4 freezes only | Q-INV-R5-01–05 |
| **Program boundary** — R4 Publish **never** substitutes for R5 Validate | R4-CHARTER critical invariant |

## Boundary rules (mandatory)

Publish Flow contract **MUST NOT**:

| Prohibition | Owner preserved |
|-------------|-----------------|
| Emit or mutate ValidationResult | **R5.1** |
| Emit or mutate PublishEligibilityRecommendation | **R5.6** |
| Re-run Validate or assign certified quality | **R5** |
| Assemble or mutate snapshot sections | **R3** |
| Mutate evidence or quarantine | **R2** |
| Redesign Store adapter or persist layout | **R1.8** |
| Auto-Publish on ELIGIBLE without G4 | **Operator** / HITL |
| Skip PublishResult emission | **R4.5** |
| Bypass G2/G3 on default path | **R5 → R4 boundary** |
| Implement gate automation product | **Forbidden** |

Publish Flow **MAY**:

| Permission | Constraint |
|------------|------------|
| Define ordered gates G1–G6 | Fail-closed default |
| Map gates to PublishResult states | Per PF-MAP-R4-02 / PR-MAP-R4-01 |

| Crosswalk to EAR readiness gates | Namespace distinction preserved |
| Reference R4.1–R4.5 outputs at G5/G6 | Ref-only on PublishResult |
