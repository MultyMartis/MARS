## Purpose

Define the canonical **Publish Eligibility Recommendation** contract — the narrow advisory gate signal produced by R5 EAR Validate and consumed by operator HITL and future R4 Publish decision processes.

**Contract layer only:** no `publish_eligibility_models.py`, no Validate Engine, no recommendation builder, no gate automation, no CLI rendering, no filesystem emit path, no Store writes, no Publish execution.

**Critical disambiguation (mandatory):**

| Artefact | Role | Publish Eligibility Recommendation? |
|----------|------|-------------------------------------|
| **`ValidationResult`** | Authoritative R5 certification outcome — PASS / PASS WITH NOTES / FAIL | **No** — primary input; outcome authority remains R5.1 |
| **`ValidateReport`** | Human-readable operator audit by review section | **No** — optional companion; referenced when present |
| **`PublishEligibilityRecommendation`** | R5 advisory Publish gate input — ELIGIBLE / ELIGIBLE WITH NOTES / NOT ELIGIBLE | **Yes** — this contract |
| **`ValidationRecommendation`** (R5.1) | Inline value field on `ValidationResult` — same enum values | **Partial** — value only; full contract is **this artefact** |
| **R4 Publish command** | Execution — consumer path writes, `published_at` | **No** — R4 ownership |
| **Operator HITL decision** | Approve / defer / override with audit | **No** — mandatory gate between recommendation and R4 |

**Rule (PE-INV-R5-01):** Publish Eligibility Recommendation **advises** on Publish consideration. It **never executes** Publish, **never certifies** quality, **never mutates** snapshot, evidence, quarantine, or Store, and **never replaces** `ValidationResult` or `ValidateReport` as outcome authority.

## Position in the pipeline

```text
Candidate Snapshot (R3)
        ↓
R5 Validate (future R5.7)
        ↓
ValidationResult (R5.1) — authoritative certification outcome
        ↓
Validate Report (R5.5) — operator audit layout (emitted together)
        ↓
PublishEligibilityRecommendation (R5.6) — advisory gate signal
        ↓
Operator HITL (mandatory — pilot)
        ↓
R4 Publish (execution — future)
```

**R5 answers:** *Can this snapshot be considered publishable?*  
**R4 answers:** *Will it actually be published?*

Recommendation sits **between** R5 Validate outputs and R4 Publish. It is **not** a Publish command, **not** a Store operation, and **not** a deployment artefact.

## PublishEligibilityRecommendation top-level contract

```text
PublishEligibilityRecommendation
├── recommendation_id              → stable recommendation identifier (generation algorithm: SAFE UNKNOWN)
├── recommendation_state           → ELIGIBLE | ELIGIBLE_WITH_NOTES | NOT_ELIGIBLE (exactly one)
├── summary                        → operator-first one-line advisory statement
├── blocking_reasons[]             → ordered list of mandatory failure summaries (NOT_ELIGIBLE primary)
├── notes[]                        → non-blocking warnings / downgrade notes (ELIGIBLE_WITH_NOTES primary)
├── required_operator_actions[]    → explicit HITL action items before R4 may act
├── validation_result_ref          → ValidationResult.result_id (mandatory linkage)
├── validate_report_ref            → ValidateReport.report_id (optional — when report emitted)
├── derived_from_status            → ValidationSummary.status (record only — not substitute for result_ref)
├── snapshot_id                    → validated candidate snapshot id (audit convenience)
├── generated_at                   → ISO 8601 timestamp (conventional)
└── boundary_declaration           → fixed text: recommendation is advisory; no side effects
```

**Invariant (PE-INV-R5-02):** Every canonical recommendation **must** link to exactly one `ValidationResult` via `validation_result_ref`. Recommendation state is **derived from** ValidationResult outcomes — it does **not** re-run validation.

**Invariant (PE-INV-R5-03):** Exactly **three** recommendation states exist. No fourth state, no numeric score, no percentage, no implicit Publish approval.

## Recommendation state definitions

### ELIGIBLE

| Field | Definition |
|-------|------------|
| **Meaning** | R5 Validate found no mandatory blockers. Certified quality level and redaction review are acceptable for **Publish consideration**. Snapshot may proceed to operator HITL and, if operator approves, to R4 Publish execution. |
| **Ownership** | State semantics **R5.6**; derivation logic **R5.7** (future); outcome authority **R5.1** |
| **Expected ValidationResult relationship** | Default mapping: `ValidationStatus.PASS` → `ELIGIBLE`. No blockers; `blocker_count == 0`. Redaction not BLOCKED. Precondition failures (when recorded) force departure from ELIGIBLE. |
| **Publish implications** | **Advisory only.** Operator HITL **still mandatory** before R4 acts (SC-R5.6-04; ST-R5-04). R4 **may** proceed after explicit operator approval. Recommendation does **not** trigger Publish. |
| **Non-goals** | Does not execute Publish; does not bypass HITL; does not certify consumer readiness; does not freeze published quality level (R4); does not imply Store validated marker write |

---

### ELIGIBLE_WITH_NOTES

| Field | Definition |
|-------|------------|
| **Meaning** | R5 Validate passed with documented non-blocking concerns — warnings, downgrade notes, or REVIEW_REQUIRED redaction items that did not block certification. Publish **consideration** is allowed with explicit operator review of notes. |
| **Ownership** | State semantics **R5.6**; notes content from R5.1 findings + R5.5 Warnings section |
| **Expected ValidationResult relationship** | Default mapping: `ValidationStatus.PASS_WITH_NOTES` → `ELIGIBLE_WITH_NOTES`. `warning_count > 0` or downgrade from target certify level. No BLOCKER-severity findings. |
| **Publish implications** | Operator **must** review notes before R4 consideration. HITL **not bypassed**. R4 may proceed only after operator acknowledges notes. Notes do **not** auto-approve Publish. |
| **Non-goals** | Does not suppress warnings; does not substitute for Validate Report Warnings section; does not waive redaction BLOCKED (that forces NOT_ELIGIBLE); does not allow quality inflation |

---

### NOT_ELIGIBLE

| Field | Definition |
|-------|------------|
| **Meaning** | R5 Validate failed closed — mandatory blockers, redaction BLOCKED, contract breach, precondition failure, or possession/redaction uncertainty per fail-closed policy. Snapshot **must not** proceed to R4 Publish until issues are remediated and **re-Validate** produces a non-NOT_ELIGIBLE recommendation (default policy). |
| **Ownership** | State semantics **R5.6**; blocker list from R5.1 findings + R5.4 redaction BLOCKED |
| **Expected ValidationResult relationship** | Default mapping: `ValidationStatus.FAIL` → `NOT_ELIGIBLE` (**fail closed** — SC-R5.6-02). Any BLOCKER finding or redaction BLOCKED typically forces this state. |
| **Publish implications** | R4 **must not** Publish on NOT_ELIGIBLE alone. Operator **may** override with explicit audited decision (exception path — see Validation Answers) but that is **HITL**, not recommendation authority. Default: re-Validate after remediation. |
| **Non-goals** | Does not quarantine evidence; does not mutate snapshot; does not block operator from inspecting Validate Report; does not replace ValidationResult FAIL as outcome record |

## Default status → state mapping

| `ValidationStatus` (R5.1) | Default `recommendation_state` | Fail-closed |
|---------------------------|--------------------------------|-------------|
| `PASS` | `ELIGIBLE` | Departure only on recorded precondition/redaction override (R5.7 policy) |
| `PASS_WITH_NOTES` | `ELIGIBLE_WITH_NOTES` | — |
| `FAIL` | `NOT_ELIGIBLE` | **Yes** — SC-R5.6-02 |

**Rule (PE-MAP-R5-01):** Default mapping is **one-way advisory**. Recommendation state **must not** upgrade `ValidationStatus` (e.g. FAIL → ELIGIBLE). Downgrade of recommendation relative to status (PASS → ELIGIBLE_WITH_NOTES when policy requires) is **R5.7 operator policy** — **SAFE UNKNOWN** at contract layer.

**Rule (PE-MAP-R5-02):** R5.1 `ValidationRecommendation.value` constants align with recommendation states:

| R5.1 constant | Value | R5.6 state |
|---------------|-------|------------|
| `VALIDATION_RECOMMENDATION_ELIGIBLE` | `ELIGIBLE` | `ELIGIBLE` |
| `VALIDATION_RECOMMENDATION_ELIGIBLE_WITH_NOTES` | `ELIGIBLE_WITH_NOTES` | `ELIGIBLE_WITH_NOTES` |
| `VALIDATION_RECOMMENDATION_NOT_ELIGIBLE` | `NOT_ELIGIBLE` | `NOT_ELIGIBLE` |

Full contract fields live on **`PublishEligibilityRecommendation`**, not on the R5.1 inline `ValidationRecommendation` value wrapper alone.

## Boundary rules (mandatory)

Publish Eligibility Recommendation **MUST NOT**:

| Prohibition | Owner preserved |
|-------------|-----------------|
| Publish or emit Publish commands | **R4** |
| Modify snapshot content or metadata | **R3** / Store |
| Modify evidence or quarantine | **R2** |
| Modify Store layout or validated marker | **R1.9** / **SAFE UNKNOWN** |
| Certify quality or assign `package_quality_level` | **R5.3** / **ValidationResult** |
| Replace ValidationResult as outcome authority | **R5.1** |
| Replace Validate Report as audit layout | **R5.5** |
| Automate readiness gates G2–G4 | Operator / **R4** |
| Write consumer paths or deployment artefacts | **R4** |
| Bypass operator HITL | **HITL** (mandatory pilot) |

Publish Eligibility Recommendation **MAY**:

| Permission | Constraint |
|------------|------------|
| Reference `ValidationResult` | Via `validation_result_ref` — mandatory |
| Reference `ValidateReport` | Via `validate_report_ref` — optional |
| Record blockers | Derived from findings — no new validation |
| Record required operator actions | Advisory checklist — not enforced by recommendation alone |
| State ELIGIBLE / ELIGIBLE_WITH_NOTES / NOT_ELIGIBLE | Exactly three states |

## Canonical publish flow

```text
Candidate Snapshot
        ↓
R5 Validate (future R5.7)
        ↓
ValidationResult          ← authoritative R5 certification outcome (R5.1)
        ↓
Validate Report           ← operator audit document (R5.5)
        ↓
Publish Eligibility Recommendation  ← advisory gate signal (R5.6) — THIS CONTRACT
        ↓
Operator HITL             ← approve / defer / override-with-audit (mandatory)
        ↓
R4 Publish                ← execution only after operator decision (future)
```

**Lifecycle notes:**

- Recommendation is emitted **with** ValidationResult in the same Validate run (future R5.7).
- Validate Report is expected co-emission but recommendation **can exist** without report ref when report omitted (exception path — see Validation Answers).
- Recommendation **must not** exist as canonical artefact **without** ValidationResult on the standard Validate path.
- Post-Publish recommendation retention — **SAFE UNKNOWN** (audit expectation: retain).

## Validation answers

| Question | Answer |
|----------|--------|
| **Can NOT_ELIGIBLE be overridden by operator?** | **Yes — via HITL only**, not automatically. Operator may record explicit override with audit trail and accept risk (exception path). Default policy: **do not Publish** until re-Validate clears NOT_ELIGIBLE. Override does **not** change ValidationResult or recommendation retroactively — it is an operator decision **after** advisory signal. R4 **must not** auto-Publish on NOT_ELIGIBLE without operator action. |
| **Can ELIGIBLE automatically Publish?** | **No.** ELIGIBLE means Publish **consideration** is advisory-permitted. Operator HITL **mandatory** before R4 (VAL-INV-02; VB-R3-02; SC-R5.6-04). R4 executes Publish only after operator approval. |
| **Can ELIGIBLE_WITH_NOTES bypass HITL?** | **No.** Notes **require** operator review. HITL mandatory on all paths including ELIGIBLE and ELIGIBLE_WITH_NOTES. |
| **Can recommendation exist without Validate Report?** | **Yes.** Canonical recommendation derives from ValidationResult. Validate Report is companion artefact. `validate_report_ref` optional. Standard run emits both (R5.7). |
| **Can recommendation exist without ValidationResult?** | **No** on standard Validate path. Recommendation **requires** `validation_result_ref`. Standalone recommendation without outcome authority is **forbidden** (PE-INV-R5-02). |
| **Can recommendation certify quality?** | **No.** Quality certification authority is **R5.3** concepts + **ValidationResult** `certified_quality_level`. Recommendation may **reference** certified level in summary text only — does not assign or upgrade. |
| **Can recommendation modify snapshot state?** | **No.** Recommendation is read-only advisory. No snapshot, evidence, quarantine, or Store mutation. |
