## Decision

| Field | Value |
|-------|-------|
| **Question** | Is the **R4.2 Publish State Model** ready as the authoritative R4 publish lifecycle semantics contract? |
| **Outcome** | **PASS WITH NOTES** |
| **Scope of pass** | Frozen dataclass hierarchy; `PublishStateRegistry` with four canonical states and nine transitions; mandatory seven-question answers; R2/R3/R5/R4 ownership review; Store vs Publish distinction preserved |
| **Explicitly not passed by this decision** | Publish Engine; state transition execution; Store adapter; `publish_state` disk encoding; consumer visibility matrix (R4.3); `PublishResult` (R4.5); supersession automation |

---

## Rationale

1. **Registry scope correct** — Four canonical publish states (`stored_unpublished`, `published`, `superseded`, `archived`); candidate and validated excluded from registry per PSM-INV-R4-01.
2. **Transitions explicit** — Primary R4 path PST-R4-01 (stored_unpublished → published) with R5 bundle + HITL requirements; forbidden bypass transitions documented (PST-R4-F01–F04).
3. **Consumer access column** — Each state carries `consumer_access` semantics aligned with R4-CHARTER publish state model.
4. **Store vs Publish preserved** — stored_unpublished owned by Store precondition; published owned by R4; G3 ≠ G4 explicit.
5. **Mandatory answers complete** — All seven questions documented with authority citations.
6. **Ownership verified** — R4 owns publish state only; no absorption of R2 evidence, R3 content, R5 validation, or quality certification.
7. **R4.1 alignment** — `PUBLISH_STATE_PUBLISHED` constant matches R4.1 `published_snapshot_models.py` value.

**PASS WITH NOTES** (not bare **PASS**): Store `publish_state` physical encoding **SAFE UNKNOWN**; supersession automation **SAFE UNKNOWN**; transition enforcement deferred R4.7; R4.3 consumer visibility matrix not yet formalized.

**FAIL** would apply if registry included Validate execution, quality certification logic, section mutation semantics, or candidate→published as allowed — **none apply**.
