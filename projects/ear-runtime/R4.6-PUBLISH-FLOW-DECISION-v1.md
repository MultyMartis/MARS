## Rationale

1. **Ordered gate sequence** — G1 Validated Snapshot Available through G6 PublishResult Emission documented with mandatory ordering and fail-closed stops (PF-INV-R4-02, PF-INV-R4-03).
2. **Dual HITL preserved** — Validate sign-off as precondition; Publish approval as G4 — distinct gates, neither substitutes for the other (SC-R4.6-01; PF-INV-R4-04).
3. **R5 boundary intact** — G2/G3 consume R5 artefacts only; R4 cannot bypass R5 on default path (PF-INV-R4-07; mandatory answer #6).
4. **NOT_ELIGIBLE fail closed** — G3 stops default path; BLOCKED PublishResult; override is audited exception (SC-R4.6-02).
5. **ELIGIBLE ≠ auto-Publish** — G4 mandatory before G5 (SC-R4.6-03; PF-INV-R4-05).
6. **PublishResult placement** — G6 always after attempt boundary; aligns with R4.5 PR-INV-R4-04/06 (mandatory answer #5).
7. **Store precondition** — G1 requires validated snapshot at Store or flagged pilot path (mandatory answer #4).
8. **Ownership clean** — R4 owns flow orchestration only; no absorption of R2 evidence, R3 assembly, R5 certification, consumer implementation.

**PASS WITH NOTES** (not bare **PASS**): no Publish Engine (deferred R4.7); gate dispatch code deferred R4.7; expanded audit schema **SAFE UNKNOWN**; BLOCKED vs DEFERRED on pending G4 — operator policy at R4.7.

**FAIL** would apply if gates skippable on default path, ELIGIBLE auto-Published, Validate sign-off substituted G4, R4 bypassed R5, or PublishResult omitted — **none apply**.
