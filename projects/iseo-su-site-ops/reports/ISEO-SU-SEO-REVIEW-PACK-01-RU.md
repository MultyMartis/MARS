## 3. Canonical

### CANON-MISSING

**Что нашли:** у **162** content-like страниц с HTTP 200 нет `link rel=canonical`.

Примеры: `/`, `home.html`, `services.html`, `cases.html`, `contacts.html`, `about.html`, `reviews.html`, `partners.html` и другие статические/сервисные/кейс-страницы.

**Почему MARS не чинил:** на сайте есть twin/alias поверхности (`/` и `home.html`). Массовый self-canonical без политики preferred URL может закрепить неверный канонический адрес.

**Нужно от SEO:**

1. Добавлять ли self-canonical на все канонические публичные статические маркетинговые страницы?
2. Какой URL предпочтителен для twin-пар вроде `/` vs `home.html`?
3. Canonical глобально через шаблон/хелпер или только для выбранных семейств?
4. Есть ли семьи страниц, которым canonical **намеренно** не нужен?

До ответов внедрение не планируется.

### CANON-MISMATCH

**Что нашли:** **117** URL, где canonical не совпадает с текущим URL (или target неразрешён).

Основная семья: query-варианты блога — `?sort=…`, `?tags=…`, комбинации параметров. Пример: `https://i-seo.su/blog/?sort=date-asc`.

**Важно:** mismatch сам по себе **не** ошибка. Для сортировок/фильтров нормально, если canonical указывает на чистый URL архива блога.

**Нужно от SEO:** подтвердить политику для:

- вариантов сортировки;
- тегов/фильтров;
- комбинированных query;
- пагинации (если релевантно).

Ключевой вопрос: должны ли query-варианты канонизироваться на чистый parent/archive URL?  
Если **да** и текущее поведение уже так — класс можно считать ожидаемым. Если **нет** — SEO задаёт preferred targets.

## 4. Sitemap и индексируемость

### SM-NONINDEX

**Что нашли:** **52** URL из sitemap классифицированы как noindex / non-indexable.

Известные семьи: `tariff-calc`, `offers`, `offer/*`, тестовые/коммерческие КП.

Контекст: для `/offer/*` в текущей архитектуре уже есть намеренно ограниченная индексируемость.

**Почему это вопрос:** sitemap обычно рекламирует URL для индексации; sitemap + noindex — конфликтный сигнал. Но tools/offers могут **намеренно** оставаться вне индекса.

**Нужно от SEO по каждой семье:**

| Семья | INDEXABLE + оставить в sitemap | NOINDEX + убрать из sitemap | Текущее поведение намеренно |
|-------|:------------------------------:|:---------------------------:|:---------------------------:|
| `offers` | ☐ | ☐ | ☐ |
| `offer/*` | ☐ | ☐ | ☐ |
| `tariff-calc` | ☐ | ☐ | ☐ |
| прочие из evidence | ☐ | ☐ | ☐ |

До решения **не** меняем ни robots/noindex, ни состав sitemap.

### SM-MISSING-INDEXABLE (закрыто, для ясности)

Перепроверено после WAVE 01: исходный count **197** устарел; сырой остаток **161**; **eligible gap = 0**. В текущий SEO-обзор **не** входит.

## 5. Title

### TITLE-DUP

**Что нашли:** дублирующие `<title>`. Крупнейший кластер — title архива блога примерно на **~119** URL (пагинация/рубрики). Также: `/` и `home.html`, query-варианты report-hub.

**Важно:** дубль title **не** автоматический дефект для пагинации, category/archive и внутренних tool-поверхностей.

**Нужно от SEO:**

- Нужны ли уникальные title у пагинации блога?
- Нужны ли уникальные title у category/archive?
- Игнорировать ли query/tool/report-hub для этого требования?
- Для `/` vs `home.html` — какая страница должна быть основной поисковой?

Массово генерировать уникальные title **не** будем.

### TITLE-LONG

**Что нашли:** **24** URL с title длиннее примерно **70** символов (услуги SEO, длинные посты блога и др.).

**Важно:** 70 символов — эвристика отображения в SERP, **не** жёсткий лимит поисковика и не ошибка индексации.

**Нужно от SEO:**

- Хотите ли пересмотреть/укоротить эти title?
- MARS трогает только URL из явного списка SEO?
- Какая практическая политика длины title для сайта?

Рекомендация MARS: точечный разбор URL, не глобальная обрезка.

## 6. Meta description

### META-MISSING

**Что нашли:** **23** indexable 200 URL без meta description. Примеры: `blog.html`, glossary, report-hub и др.

**Важно:** отсутствие description — не ошибка индексации; поисковик может собрать сниппет сам.

**Нужно от SEO:** какие семьи реально требуют ручного description?

Возможные ориентиры (не навязываем):

- primary marketing — обязателен;
- blog/article — optional/template;
- tools/report-hub — можно игнорировать.

### META-DUP

**Что нашли:** примерно **137** URL вовлечены в дубли description (около 2 distinct duplicate-текстов в evidence). Примеры: blog variants, `/`, `home.html`, template-default поверхности.

**Нужно от SEO:** для каких семейств description обязан быть уникальным?

Автогенерацию description без вашего списка **не** делаем.

## 8. Изображения

### IMG-ALT

**Что нашли:** **445** страниц, где встречаются отсутствующие/пустые `alt`.

Это **не** значит «445 битых картинок». Пустой `alt=""` для декоративных изображений — нормальная и часто желательная практика.

Тяжёлые изображения (`IMG-HUGE`) уже закрыты отдельно (2 файла сжаты).

**Нужно от SEO / дизайна:**

1. Требовать alt только у контентно значимых изображений?
2. Какие семьи считать значимыми: кейс-скриншоты, иллюстрации услуг, картинки статей, логотипы, иконки, декоративный UI?
3. Оставлять ли иконкам/декоративным фонам `alt=""`?
4. Нужен ли SEO/контент-разбор **до** написания смысловых alt?

**Предупреждение:** механическая подстановка alt из имени файла — плохая практика; не используем.

### Тяжёлые изображения (уже исправлено)

`makita_01.png` / `maltipoo_01.png` сжаты; остаток >1,5 МБ по выборке аудита = **0**. Не предмет текущего SEO-обзора.

## 11. Что MARS специально не исправлял

Семантические SEO-решения **намеренно** не применялись автоматически:

- canonical (self / preferred / twin);
- уникальность и длина title;
- наличие и уникальность meta description;
- политика alt;
- состав sitemap vs noindex;
- внутренняя перелинковка «сирот»;
- scope Open Graph;
- H1 на tool-поверхностях.

Техническая волна 01 чистила только инфраструктурные пункты (sitemap gaps, redirect-links, вес изображений) **без** смены SEO-семантики.

## Три типа пунктов (итог для SEO)

### A. Вероятные SEO-изменения (нужно ваше решение до внедрения)

CANON-MISSING, CANON-MISMATCH (если политика иная), SM-NONINDEX, TITLE-DUP (где страницы действительно разные), TITLE-LONG (точечно), META-MISSING, META-DUP, ORPHAN-CRAWLER (где нужна discoverability), IMG-ALT (только значимые), OG-MISSING (по утверждённым шаблонам).

### B. Вероятно нормальное поведение

- H1 на tool/sibling (H1-MISSING);
- canonical mismatch для query-вариантов блога **если** политика = «на чистый архив»;
- декоративный `alt=""`;
- намеренный noindex у offers / `offer/*`;
- одинаковые title у пагинации/рубрик — **если** так решите.

### C. Не надо чинить автоматически

Canonical, titles, descriptions, alt, sitemap/noindex policy, orphan links, OG scope — только после явных ответов SEO и отдельного scoped implementation wave.

1. SEO возвращает ответы (этот отчёт и/или чек-лист `ISEO-SU-SEO-DECISION-CHECKLIST-01-RU.md`).  
2. Site Ops / MARS готовит **точную scoped** волну внедрения только по утверждённым пунктам.  
3. После внедрения — технический отчёт изменений для вашей проверки.  
4. Без ваших ответов semantic SEO-правки **не** выполняются.
