# WPilot Exact Match Safety Model v0

**Status:** CORE / PLANNED / DEV-ONLY.
**Scope:** deterministic exact replacement safety rules for WPilot Phase 2.

The MVP supports only exact deterministic replacement. Anything requiring interpretation, rewriting, fuzzy matching, or broad search is **EXCLUDED**.

## Supported Operation

**CORE / PLANNED:** replace one exact source string with one exact replacement string in one approved WordPress page content field.

The operation must:

- Match exactly one occurrence.
- Preserve all non-target content.
- Refuse ambiguous input.
- Use checksums before and after.
- Remain human-supervised.

## Exact String Matching Rules

Exact match means:

- Source string is compared directly against current content.
- No regex.
- No wildcard.
- No fuzzy matching.
- No case folding unless a future contract explicitly adds it. Default is case-sensitive.
- No semantic replacement.
- No translation or summarization.
- No search across multiple pages.

The source string must be non-empty. Empty source strings are refused.

## Normalization Rules

Default MVP behavior:

- Do not normalize content before matching.
- Do not trim source or replacement automatically.
- Do not collapse whitespace.
- Do not convert line endings for matching.
- Do not decode HTML entities for matching.
- Do not decode base64 or encoded builder blocks.

Allowed normalization is limited to safe input validation, such as confirming valid UTF-8 and rejecting unsafe encoding. Matching still uses the stored content representation.

If a future implementation introduces any normalization, it must be explicit in dry-run output and must not make multiple possible spans appear as one.

## UTF-8 Handling

Content and request strings must be valid enough for deterministic JSON and WordPress storage.

Refuse if:

- Source or replacement contains invalid UTF-8 that cannot be safely represented.
- Current content contains invalid byte sequences that make matching or JSON response unsafe.
- UTF-8 repair would change match positions.
- JSON encoding fails.

No hidden character repair is allowed before mutation.

## Whitespace Handling

Whitespace is content.

Rules:

- Spaces, tabs, newlines, and non-breaking spaces are matched exactly.
- Line ending differences are meaningful unless explicitly shown in preview.
- Leading and trailing spaces are preserved.
- The plugin must not auto-trim source or replacement.
- The plugin must not collapse repeated whitespace.

Operator should provide a narrower exact string if whitespace makes the match ambiguous.

## Occurrence Counting

Dry-run and execute must count occurrences in current content.

Accepted condition:

- Count is exactly one.

Refusal conditions:

- Count is zero: `ZERO_MATCHES`.
- Count is greater than one: `MULTIPLE_MATCHES`.
- Count differs between dry-run and execute: `CHECKSUM_MISMATCH` or `MUTATION_ABORTED`.
- Counting cannot complete safely: `SAFE_UNKNOWN`.

Counting must not stop early in a way that hides multiple matches.

## Multiple Match Refusal

Multiple matches are always refused in MVP.

The plugin must not:

- Choose the first match.
- Choose the last match.
- Choose a match by visual proximity.
- Ask AI to choose.
- Replace all matches.
- Use page-rendered position to disambiguate.

Operator may retry with a more specific exact source string.

## Zero Match Refusal

Zero matches are always refused.

The plugin must not:

- Guess a near match.
- Apply typo correction.
- Search rendered HTML instead of stored content.
- Try alternate encodings.
- Use browser automation to locate visible text.

Operator may refresh page-read output and retry with current stored content.

## Oversized Content Refusal

The MVP should define a maximum content size for safe scanning.

Refuse if:

- Content exceeds configured scan limit.
- Match counting would require unsafe memory or time.
- WPBakery structure analysis exceeds configured bounds.

Oversized refusal is safer than partial matching. The exact limit is **SAFE UNKNOWN** until implementation.

## Unsupported Content Refusal

Refuse if target content is:

- Non-page post type outside MVP allowlist.
- Binary, encoded, encrypted, or compressed content.
- Raw HTML block that cannot be classified safely.
- Script/style/PHP-like content.
- Builder data outside `post_content`.
- Content generated by theme/plugin runtime rather than stored target field.
- SAFE UNKNOWN.

## Replacement String Safety

Replacement must be plain deterministic text for MVP.

Refuse replacement that contains:

- Shortcode-like brackets intended to create or alter shortcode structure.
- `<script>`, `<style>`, iframe, form, PHP tags, or event-handler patterns.
- Encoded blocks intended to bypass zone validation.
- Content that would change HTML tag structure when target is not allowed HTML text.

## Execute Consistency

Execute must re-read current content and repeat exact-match checks.

Abort if:

- Current checksum differs from dry-run checksum.
- Source occurrence count is no longer exactly one.
- Match span differs from dry-run.
- Replacement result checksum differs from predicted checksum.

## SAFE UNKNOWN

- Maximum content scan size.
- Whether any bounded preview context is allowed.
- Whether future modes may support normalized matching.
- Whether exact matching should be byte-indexed or character-indexed in implementation internals.
