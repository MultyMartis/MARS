# WPilot WPBakery Live Validation Strategy v0

**Status:** CORE / PARTIALLY OPERATIONAL / DEV-ONLY.
**Scope:** safe read-only validation of WPBakery detection and structure signals in a live DEV WordPress site.

This strategy validates observation only. No live content mutation, backup creation, rollback execution, shortcode rewriting, or builder repair is allowed in this phase.

## Safe Test Pages

Use DEV-only pages that can be inspected without business risk:

1. **Plain page**: normal WordPress page with no WPBakery shortcodes.
2. **Simple WPBakery page**: one row, one column, one text block.
3. **Nested WPBakery page**: nested rows/columns if the site builder supports it.
4. **Raw block page**: page containing `vc_raw_html` or `vc_raw_js` if safe and already available on DEV.
5. **Malformed copy page**: a disposable page containing intentionally unbalanced copied shortcode text.

Do not test against production content or pages with private customer data.

## Shortcode Integrity Checks

For each safe test page:

1. Call `GET /wp-json/wpilot/v1/pages`.
2. Confirm `has_wpbakery` matches expectation.
3. Call `GET /wp-json/wpilot/v1/pages/{id}`.
4. Confirm `content_checksum` is present and stable across repeated reads when content is unchanged.
5. Call `GET /wp-json/wpilot/v1/pages/{id}/structure`.
6. Confirm `shortcode_counts` reflects known WPBakery shortcode names.
7. Confirm `basic_integrity.vc_row_balanced` matches expected row balance.
8. Confirm `warnings` are deterministic.

## Nested Shortcode Tests

Recommended nested cases:

- `vc_row` containing one `vc_column`.
- `vc_column` containing `vc_column_text`.
- Multiple sibling `vc_row` blocks.
- Nested builder sections if generated by WPBakery/The7 in normal UI.

Expected:

- `has_wpbakery = true`.
- `shortcode_counts` includes the detected shortcode names.
- Repeated reads produce the same counts.
- No endpoint attempts to normalize or repair content.

## Malformed Shortcode Refusal Tests

This phase has no write operation to refuse, so malformed shortcode behavior is observation-only.

Expected structure-read behavior:

- Return success only as read-only structural observation.
- Add warning such as `vc_row_shortcode_count_mismatch` when detectable.
- Do not claim content is safe to edit.
- Do not mutate, repair, reorder, or remove shortcode content.

Future write-phase expectation:

- Malformed or ambiguous structure becomes `STRUCTURE_SAFE_UNKNOWN` or another refusal before mutation.

## Structure-read Expectations

`GET /wp-json/wpilot/v1/pages/{id}/structure` should return:

- `id`
- `has_wpbakery`
- `shortcode_counts`
- `basic_integrity`
- `warnings`

The endpoint is PARTIALLY OPERATIONAL because it provides lightweight shortcode signals only. It is not a full WPBakery AST parser.

## The7 Compatibility Observations

Observe and record:

- Whether The7 pages use standard `vc_*` shortcodes.
- Whether The7 adds custom shortcodes not counted by the MVP detector.
- Whether raw HTML/JS blocks appear.
- Whether builder-generated nesting is balanced.
- Whether shortcode counts remain stable after normal WordPress page save.

SAFE UNKNOWN:

- Full The7 element coverage.
- The7-specific shortcode taxonomy.
- Encoded/escaped builder content semantics.
- Whether future write safety can be inferred from current read-only detection.

## Safe Failure Handling

If a page produces unexpected structure:

1. Stop validation for that page.
2. Record page type and observed warning/code only.
3. Do not repair automatically.
4. Do not use SQL or filesystem fallback.
5. Do not test mutation.
6. Use a disposable cloned DEV page for further observation.

Operational rule:

- SAFE UNKNOWN structure remains SAFE UNKNOWN until a human reviews the page and future parser rules are explicitly implemented.
