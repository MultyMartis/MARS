# Triumph Manipulator Landing V3 — Execution Boundaries

## 1. Purpose

This file defines what is allowed and forbidden during the V3 Forge battle test.

The boundary protects V3 from becoming a V2 continuation, a silent redesign, a governance performance, or an endless perfection loop.

## 2. Allowed

V3 allows:

- Reconstruction from the approved V1 source pack.
- Use of `projects/triumph-manipulator-landing/design/shared-assets/` as approved asset authority after inspection.
- Adaptive governance scaling.
- Proportional QA.
- Approximation disclosure.
- Responsive interpretation with disclosure.
- Survivable implementation decisions.
- Evidence-based review depth.
- SAFE UNKNOWN when authority, evidence, or confidence is incomplete.
- HITL when decisions exceed source authority or change strategic meaning.

## 3. Forbidden

V3 forbids:

- V2 patch inheritance.
- Silent redesign.
- Fake fidelity claims.
- Hidden approximation.
- Governance theater.
- Endless perfection loops.
- Uncontrolled scope growth.
- Treating checklist volume as quality proof.
- Treating V2 implementation convenience as V3 authority.
- Declaring required assets unknown before inspecting `design/shared-assets/`.
- Letting shared assets override V1 section order, hierarchy, composition, or visual intent.
- Claiming production readiness without evidence.

## 4. Implementation boundary

This preparation pack does not authorize implementation.

Before any rebuild begins, the operator must confirm:

- The exact V1 source pack boundary.
- The asset mapping from `design/shared-assets/` for the active reconstruction scope.
- The target V3 workspace path.
- The implementation stack and build scripts.
- The review cadence and reporting format.
- The minimum viewport/device evidence expected.

## 5. Scope control

V3 must stay focused on operational validation:

- Can the source be reconstructed?
- Can governance deploy without collapsing?
- Can responsive intent survive?
- Can QA remain honest?
- Can the result remain maintainable?
- Can future edits remain safe?

Requests that expand into new methodology, new governance layers, unrelated redesign, or production feature invention require explicit operator approval.

## 6. Russian HTML typography

V3 visible Russian HTML copy must keep short prepositions, conjunctions, and particles with the following word when a line break would damage reading logic.

Use `&nbsp;` for these non-breaking joins, including patterns such as `в&nbsp;Краснодаре`, `и&nbsp;краю`, `с&nbsp;НДС`, `от&nbsp;30&nbsp;минут`, `до&nbsp;10&nbsp;тонн`, `за&nbsp;1&nbsp;час`, `по&nbsp;Краснодару`, and `для&nbsp;юр.&nbsp;лиц`.

Apply the rule in headings, CTA text, benefits, trust strips, forms, and cards. Do not overuse `&nbsp;` in long phrases where normal wrapping remains readable.

## 7. Truth boundary

V3 is a battle test, validation exercise, and operational proof attempt.

It is **not** final production truth, a universal benchmark, a perfect frontend reconstruction proof, a runtime system, autonomous frontend intelligence, or automatic delivery approval.
