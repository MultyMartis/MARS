# V2 Visual Source Matrix

## 1. Purpose

Этот документ связывает **визуальную правду V2** (`design/v2/*.png`, композиция `full.png`) с **фактической реализацией** в `workspaces/triumph-manipulator-landing-v2/src/`: какой смысл несёт каждый экспорт макета, к какой секции он относится, какие файлы реализуют и стилизуют блок, и где есть риск семантического уезда или подмешивания V1.

**Критическое правило:** нумерация визуальных экранов (`01.png` … `07.png`) **не** задаёт автоматически:

- порядок `@@include` в `index.html`;
- порядок узлов в DOM;
- «номер секции» из старых freeze / section map;
- авторитет старых карточек landing-strip V1.

Сопоставление выполняется по **смыслу макета и роли блока на странице**, с фиксацией расхождений там, где визуальная последовательность и реализация расходятся.

**Следующий** цикл реализации фронтенда обязан **начинаться с** `design/v2/01.png` и идти **по порядку** до `07.png`, **экран за экраном**. **Не** опираться на устаревший DOM; **не** брать семантику из `design/v1/`; блок **`equipment-prices`** — **только** страница **`validation-equipment-prices.html`** (**карантин**), **не** часть главной; **не** выдумывать копирайт; **не** менять смысл секций без оператора.

Полная англоязычная формулировка: [V2-FRONTEND-SOURCE-OF-TRUTH.md](./V2-FRONTEND-SOURCE-OF-TRUTH.md) **NEXT IMPLEMENTATION RULE**.

## 4. Visual-to-implementation conflicts

1. **«Третий экран» (homepage — 2026-05-16)**  
   - **Третий файл макета** `03.png` — **«Отзывы и доверие» / кейсы**.  
   - **Третий блок `<main>` на главной** — `trust-cases-social-proof` (`id="keysy"`).  
   - Коллизия «3-й PNG ≠ 3-й `<main>` из-за `equipment-prices`» **снята с главной**: fleet-блок вынесен на `validation-equipment-prices.html`.  
   **Правило:** при любых правках по-прежнему явно различать **имя PNG**, **порядок в `full.png`**, **порядок `<main>`** и **якоря навигации**.

2. **Блок `equipment-prices` — карантин (validation-only)**  
   - В `design/v2` и `full.png` **нет** слайса «три карточки 5/7/10 т» между **02** и **03**.  
   - Блок **не** в `index.html`; живёт на **`validation-equipment-prices.html`** для изолированного просмотра / будущего fleet-mode.  
   **Риск:** вернуть include на главную «по привычке» — **запрещено** без нового письменного gate.

3. **Одно-машинная семантика vs три карточки (изолированно)**  
   - Мокапы 02, 03 (тексты кейсов), 04–06, 07 многократно опираются на **одну машину** / один исполнитель.  
   - `equipment-prices` по-прежнему вводит **три типа** машин — **только** на validation-странице; **не** смешивать с потоком главной `01`–`07`.  
   **Риск:** копирование fleet-карточек в каноничные секции при наполнении stubs.

4. **Заголовки и тип секции**  
   - Реализованный герой заполняет H1 строками из макета 01 (**хорошо по направлению**), но детальный список преимуществ **может расходиться** с PNG/PDF → не подменять «улучшенными» формулировками без оператора.

5. **Конфликт количества/структуры (problem–solution)**  
   - Визуал 05 задаёт **6×2** строки; partial содержит **3+3** заглушки → **видимая недокомплектованность каркаса** относительно макета.

6. **Legacy strip contamination (если использовать не туда)**  
   - В дереве есть `landing-strip-*.html`/`.scss`, **не** подключённые к homepage ([V2-SECTION-SOURCE-MATRIX.md](./V2-SECTION-SOURCE-MATRIX.md) §5).  
   **Риск:** копирование порядка/смысла strip в V2 при автогенерации.

7. **Старая section map / freeze**  
   - Любая «карта секций», унаследованная из V1 или старых handoff, **не** является порядком V2 после сверки с `design/v2` и `full.png`.

8. **full.png описание vs фактический макет**  
   - Автоматические описания длинной композиции иногда упрощают текст в trust-row героя; **единичный источник визуала** для спорных деталей — **отдельные** `01.png`…`07.png` и PDF, не вторичные пересказы.

## 7. Forge execution rules

**Цикл реализации:** сначала [NEXT IMPLEMENTATION RULE](#next-implementation-rule) — строго `01.png` → `07.png`, один экран за шаг, затем semantic + responsive QA и freeze.

1. **Следовать** смыслу блока в `design/v2`; **не** выстраивать структуру по памяти, по V1-strip, по текущему `index.html` без сверки с **активным** `NN.png`.
2. **Не выводить отсутствующие секции** из общих маркетинговых шаблонов; пустота в partial = **SAFE UNKNOWN / эскалация**, а не генерация.
3. **Не импортировать V1-семантику** (порядок strip, тексты V1, идею «демо-секций» без макета).
4. Любой **конфликт визуала и кода** (включая «лишний» или «ещё один» блок про парк техники) → **остановка и отчёт**, без скрытых правок.
5. **Нельзя** превращать one-machine повествование в fleet: множественные тоннажи, «выберите машину из ряда» и т.п. **без явного операторского разрешения** и без отдельного визуального источника.
6. **Нельзя** заменять утверждённые заголовки и ключевые формулировки «улучшенными» AI-вариантами.
7. **Нумерация PNG задаёт порядок работ** для **следующего** цикла — текущий порядок includes **не** доказателен, пока экраны не пройдены по циклу NEXT IMPLEMENTATION RULE; перед правкой всегда сверять **целевой** файл макета **и** фактический `index.html`.

## 8. SAFE UNKNOWN

Следующее **не** подтверждено без пиксельной/PDF-сверки, операторского sign-off или выравнивания с датой актуальных мокапов:

- Дословное совпадение **каждой** строки копирайта в `hero-conversion` с `01.png` и PDF (включая расхождения буллет vs нижняя полоса).
- Юридически значимые идентификаторы (ИНН, юрформулировки) в футере макета **07** против будущего наполнения `site-footer-v2`.

- Соответствие ссылок `header` (в т.ч. `https://t.me/` без конкретного канала) требованиям макета/оператора.
- Любые **nested** `partials/components/*`, не разобранные в этом документе построчно.
- Присутствие или отсутствие **VK** или иных социконок в финальном брифе: в описании `full.png` встречается упоминание VK, в считанном `header` — WA/Telegram/MAX; итог **только** по первичному дизайн-активу.
