# MARS Website Factory - Knowledge Compression & Context Survivability Governance

**Status:** **documented** - Website Factory context governance and human-supervised continuity methodology only.  
**Not:** autonomous memory AI, runtime persistence system, universal memory law, perfect continuity reconstruction, or replacement for human project authority.

**Core principle:** compressed context must preserve **operational meaning, governance continuity, checkpoint integrity, escalation visibility, strategic continuity, and freeze-state readability**.

## 1. Positioning

Knowledge Compression & Context Survivability Governance formalizes how Website Factory frontend work survives long sessions, chat compression, handoffs, summaries, checkpoint transfers, freeze-state reviews, and later reconstruction.

| This layer governs | This layer does not govern |
|--------------------|----------------------------|
| Context continuity, compression integrity, checkpoint persistence, governance memory, reconstruction readability, and long-chain operational continuity | Autonomous memory systems, vector stores, runtime persistence, agent memory products, or perfect recall |
| Human-supervised methodology for preserving what must survive summaries and compressed context | Token optimization, generic summarization, or "continue from previous chat" behavior |
| Drift vocabulary for summary hallucination, checkpoint amnesia, compression drift, hidden assumption persistence, memory contamination, and continuity reconstruction failure | Redesigning Triumph or any other project |
| Forge reporting discipline for `CONTEXT SURVIVABILITY FINDINGS` | A claim that compressed context is complete, authoritative, or self-validating |

The governance question is not "is the summary shorter?"  
The governance question is: **can a future operator reconstruct the operational state, authority chain, checkpoints, escalations, freeze posture, and unresolved unknowns without guessing?**

---

## 2. Canonical Definition

**Context survivability** is the ability of operational context to remain readable, traceable, and governable after compression, handoff, session interruption, reconstruction, or long-chain continuation.

It protects:

- **Context continuity** - the current operator can understand what happened before and what still governs the work.
- **Governance survivability** - governance findings, boundaries, and rules survive compression instead of collapsing into "done."
- **Checkpoint persistence** - checkpoints remain named, scoped, and tied to evidence after summaries are created.
- **Compression integrity** - compression reduces length without mutating operational meaning, authority, or uncertainty.
- **Freeze-state memory** - frozen, reopened, deferred, blocked, or superseded states remain readable.
- **Escalation memory** - HITL needs, stop conditions, waivers, contradictions, and unresolved decisions remain visible.
- **Reconstruction survivability** - future reconstruction can disclose evidence, unknowns, and ambiguity instead of inventing continuity.

A compressed context may look coherent, appear complete, preserve terminology, and seem operationally usable while still hiding ambiguity, losing checkpoints, mutating governance meaning, or eroding strategic continuity.

## 3. Required Vocabulary

| Concept | Meaning |
|---------|---------|
| **Context survivability** | Operational context remains usable after compression, handoff, interruption, and later reconstruction. |
| **Compression integrity** | A compressed record preserves meaning, authority, checkpoints, unknowns, and governance boundaries. |
| **Continuity reconstruction** | The act of rebuilding operational state from available artifacts, summaries, checkpoints, reports, and source records. |
| **Checkpoint persistence** | Checkpoints survive as named state records rather than vague progress notes. |
| **Governance memory** | Governance findings, stop conditions, approvals, deferrals, waivers, and unknowns remain visible across sessions. |
| **Summary contamination** | A summary adds, removes, smooths, or reinterprets facts until downstream work inherits distorted context. |
| **Implicit assumption persistence** | Unstated assumptions survive across sessions as if they were approved context. |
| **Compression drift** | Meaning, priority, scope, authority, or uncertainty changes during context reduction. |
| **Context erosion** | Operational detail is gradually lost until the current state depends on memory or guesswork. |
| **Operational continuity** | Work can continue with visible state, evidence, scope, risk, and next action. |
| **Freeze-state memory** | Current context preserves what is frozen, reopened, superseded, deferred, blocked, or unproven. |
| **Reconstruction survivability** | Reconstruction remains honest about what can and cannot be proven. |
| **Context readability** | The context record is human-readable enough for another operator to continue safely. |
| **Memory contamination** | Stale summaries, prior outputs, archive assumptions, or unrelated session memory influence active context. |
| **Continuity ambiguity** | It is unclear what state, checkpoint, source, decision, or finding should govern continuation. |

## 4. Core Rules

- **Checkpoints should survive compression.** If a checkpoint disappears from the compressed record, continuity is weakened.
- **Summaries reduce operational fidelity.** A summary is useful, but it should not be treated as full context authority.
- **Continuity reconstruction requires traceability.** Reconstruction must name the artifacts, reports, checkpoints, and unknowns it relies on.
- **Implicit assumptions are dangerous.** Unstated assumptions should not become inherited project truth.
- **Freeze-state memory matters.** Frozen or reopened states must remain visible after compression.
- **Escalation memory matters.** HITL needs, contradictions, unresolved ambiguity, and stop conditions must not be summarized away.
- **Compressed context should remain explainable.** A future operator should understand why the work can continue, pause, or escalate.
- **Governance continuity must survive long timelines.** Governance findings must remain comparable across sessions, not collapse into a generic progress summary.
- **SAFE UNKNOWN is healthier than fake completeness.** Missing context must be named, not reconstructed by confidence.
- **Compressed context is not stronger because it is cleaner.** Coherence is not proof of continuity.

---

## 5. Compression Review Questions

Before continuing from a summary, compressed context, handoff, or reconstructed state, ask:

- What original operational context does this compressed record claim to represent?
- Which checkpoints, freeze states, findings, deferrals, escalations, and unknowns survived?
- Which details were omitted, normalized, summarized, inferred, or reconstructed?
- Does the compressed record distinguish source fact, report conclusion, operator judgment, assumption, and unknown?
- Can the current state be traced to named artifacts rather than generic "previous work"?
- Did strategic intent, provenance, QA confidence, visual findings, workflow discipline, or human escalation lose specificity?
- Is continuation safe, checkpoint required, HITL required, blocked, or monitored risk?

## 6. Anti-Patterns

Forbidden drift:

| Anti-pattern | Why it is forbidden |
|--------------|---------------------|
| **Blind continuation from summaries** | Treats compressed text as complete operational state. |
| **Compression without checkpoints** | Loses the state anchors needed for safe continuation. |
| **Hidden assumption inheritance** | Lets unstated guesses become active governance memory. |
| **Governance erosion through summarization** | Collapses findings, deferrals, and stop conditions into generic progress. |
| **Continuity reconstruction guessing** | Fills missing context with plausible but unproven history. |
| **Fake context completeness** | Coherent summary language hides missing evidence or unknowns. |
| **Freeze-state forgetting** | Frozen, reopened, deferred, or blocked states disappear from compressed memory. |
| **Escalation memory loss** | HITL, contradictions, waivers, and unresolved decisions are omitted. |
| **Context laundering** | Repetition or compression makes weak, stale, or unknown claims appear canonical. |
| **Historical ambiguity accumulation** | Each continuation inherits slightly less traceability until history becomes unusable. |

Use [context-drift-taxonomy.md](context-drift-taxonomy.md) for full drift classification.

## 7. Forge Integration

When Forge is selected, context survivability becomes a pre-freeze, handoff, compression, and continuation concern:

- Run [`context-survivability-checklist.md`](../../agents/mars-forge/context-survivability-checklist.md) before continuing from compressed context, closing a long session, freezing after multi-session work, reconstructing prior state, or relying on summarized history.
- Record **CONTEXT SURVIVABILITY FINDINGS** for context survivability QA, checkpoint persistence QA, compression integrity QA, continuity reconstruction QA, freeze-memory QA, escalation-memory QA, and governance-memory QA.
- Use [context-compression-integrity-model.md](context-compression-integrity-model.md) to classify original operational context, compressed operational context, summary layer, checkpoint layer, freeze-state memory layer, escalation memory layer, and reconstruction layer.
- Use [context-drift-taxonomy.md](context-drift-taxonomy.md) to name summary hallucination, checkpoint amnesia, hidden assumption persistence, continuity collapse, governance compression loss, memory contamination, and related patterns.
- Keep **CONTEXT SURVIVABILITY FINDINGS** separate from `WORKFLOW DISCIPLINE FINDINGS`, `TEMPORAL EVOLUTION FINDINGS`, `SOURCE LINEAGE FINDINGS`, `QA CONFIDENCE FINDINGS`, and `HUMAN ESCALATION FINDINGS`, then summarize whether context is safe to continue from.
- Keep transfer source, compatibility decisions, rejected assumptions, and project-specific meaning visible for `CROSS-PROJECT TRANSFER FINDINGS` when compressed context carries lessons from other projects.
- Use [failure-recovery-governance.md](failure-recovery-governance.md) when context reconstruction is part of rollback, freeze restoration, trusted-state recovery, degraded-state handling, or recovery traceability; report `FAILURE RECOVERY FINDINGS` separately.
- Use [governance-minimalism.md](governance-minimalism.md) when compressed context cannot carry the governance stack without losing priority, readability, or next action; report `GOVERNANCE MINIMALISM FINDINGS` separately.
- Use [decision-transparency-governance.md](decision-transparency-governance.md) when compressed context must preserve reasoning path, assumptions, tradeoffs, prioritization rationale, escalation rationale, or traceable conclusions; report `REASONING VISIBILITY FINDINGS` separately.
- Use [organizational-memory-governance.md](organizational-memory-governance.md) when compressed context carries reusable lessons, historical decisions, operational wisdom, rediscovery-risk signals, or institutional continuity; report `ORGANIZATIONAL MEMORY FINDINGS` separately.
- Escalate **SAFE UNKNOWN** when the compressed record cannot prove checkpoint state, source authority, freeze posture, escalation state, strategic continuity, or unresolved risks.

This is human-supervised context methodology. It does not create runtime memory, automatic checkpoint storage, autonomous summarization validation, or guaranteed reconstruction.

## 8. Triumph V2 Lessons Captured

Triumph V2 exposed reusable Website Factory context survivability lessons:

- A V2 rebuild can accumulate many correct local findings while still becoming fragile if compressed context loses freeze state, source version, or unresolved ambiguity.
- Multi-session work needs checkpoint memory, not only "what was done" summaries.
- Visual, strategic, provenance, QA confidence, workflow, and escalation findings must survive compression as separate governance signals.
- A coherent compressed handoff can hide unresolved assumptions about active V2 sources, archived V1 contamination, responsive authority, or section freeze state.
- Long-chain continuation should preserve what changed since the last trusted state and what remains unsafe to infer.
- Context reconstruction should say when it is reconstructing from evidence and when it is facing SAFE UNKNOWN.

These are Website Factory governance lessons, not Triumph redesign instructions.

## 9. SAFE UNKNOWN

Record **SAFE UNKNOWN** when:

| Situation | Why it is unknown |
|-----------|-------------------|
| Original operational context is unavailable | Cannot prove what the compression omitted or mutated. |
| Checkpoint state is missing | Cannot prove current scope, evidence, findings, or next action. |
| Freeze-state memory is absent | Cannot claim frozen, reopened, deferred, blocked, or superseded status. |
| Escalation memory is missing | Cannot know whether HITL, contradiction, waiver, or stop condition still applies. |
| Summary source is unclear | Cannot determine whether text is source, report, inference, assumption, or reconstruction. |
| Continuity reconstruction depends on guesswork | Cannot continue as if history is proven. |
| Governance findings were flattened | Cannot know which layer passed, failed, deferred, or remained partial. |
| Strategic continuity is compressed away | Cannot prove business intent or conversion hierarchy survived. |

**Action:** state the missing context, identify what artifact or human decision would resolve it, and classify continuation as safe with disclosure, checkpoint required, HITL required, blocked, or monitored risk.
