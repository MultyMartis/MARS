Program design assigned **Wave W2** (`HEADER_NAV`, `FOOTER`, `LEGAL_LINKS`) to WF-R01.3.3. WF-R01.3.2 **bundled and completed** W2 partial implementation under Gate G1, producing the first published **global shell** on `LANDING_PAGE`. Without a dedicated WF-R01.3.3 charter, operators risk:

3. **Premature G2 claims** — treating shell policy as RPC/RSC increase.
4. **Blocking WF-R01.3.4** — catalog track depends on accepted shell and structural policy.

WF-R01.3.3 closes the **residual** shell-policy gap: global shell contract, navigation depth, BREADCRUMBS/PAGINATION disposition, scaffold depth specification, and handoff — **without** repeating completed partial work.

## 7. Global Shell Contract

### Canonical shell stack

```text
HEADER_NAV
MAIN
FOOTER
└── LEGAL_LINKS
```

### Binding rules

| Rule | Requirement |
|------|-------------|
| **Shell order** | `HEADER_NAV` **before** `MAIN`; `FOOTER` **after** `MAIN`; `LEGAL_LINKS` **compositionally inside** `FOOTER` (not a sibling site-level footer) |
| **Page content boundary** | Global shell is **not** page content — marketing/conversion blocks live inside `MAIN` only |
| **Site-level singularity** | Site-level shell **must not** be duplicated per page — one global header/footer pair per rendered page |
| **Nested semantics** | Local semantic `<header>` / `<footer>` inside cards, articles, or product tiles are **permitted** — they are **not** global shell replacements |
| **Cross page-type applicability** | Shell structure applies to all multi-page `page_type` scaffolds; slot population may vary (see §12) |
| **LANDING baseline** | [REFERENCE-COMPOSITION-v1.md](../../workspaces/website-factory-reference-v1/REFERENCE-COMPOSITION-v1.md) is the **reference implementation** of this contract for `LANDING_PAGE` |
| **HEADER ≠ HERO** | [layout-shell-governance.md](layout-shell-governance.md) — global navigation shell must not absorb hero content |

### Optional in-shell slots (page-type dependent)

Between `HEADER_NAV` and `MAIN` content, or within `MAIN` top zone:

- **BREADCRUMBS** — optional slot; see §9
- **PAGINATION** — optional slot at list bottom; see §10

These are **not** part of the immutable four-zone shell identity; they are **page-type shell extensions**.

## 8. Navigation Depth Policy

Navigation surfaces are **not** interchangeable. Do not collapse all navigation into `HEADER_NAV`.

### Depth levels

| Level | Role | Typical surfaces |
|-------|------|------------------|
| **L0** | Global primary navigation | `HEADER_NAV` — site-wide IA, logo, primary menu, utility actions |
| **L1** | Section / category navigation | Hub tabs, category mega-menu sections (HEADER_NAV variant), `CATEGORIES` block on hub pages |
| **L2** | Local / contextual navigation | In-page anchors, related links, sidebar section nav (future policy), facet chips inside PLP |
| **L3** | Utility / compliance navigation | `LEGAL_LINKS`, footer secondary links, account/help utilities |

### Surface assignment (binding)

| Surface | Depth | Owner block / policy | Notes |
|---------|-------|----------------------|-------|
| `HEADER_NAV` | **L0** | F3 Tier A `block_id` | Primary global nav; mega-menu = variant, not separate `block_id` |
| FOOTER navigation links | **L1–L3** | Inside `FOOTER` partial | Distinct from `LEGAL_LINKS` compliance cluster |
| `LEGAL_LINKS` | **L3** | F3 `block_id` nested in `FOOTER` | L1–L4 legal URLs; compliance, not primary IA |
| `BREADCRUMBS` | **L1–L2** | F3 Tier B layout-component | Hierarchical orientation; **not** L0 primary nav |
| `PAGINATION` | **L2** | F3 Tier B layout-component | List paging; **not** primary site IA |
| Sidebar navigation | **L1–L2** | Future page-type policy | **Not** `HEADER_NAV`; deferred explicit partial |
| `FILTERS` | **L2** | F3 Tier A `block_id` | PLP refinement — **WF-R01.3.4** |
| `SEARCH` | **L0–L2** | F3 Tier A `block_id` | Query entry (typically L0 header) + results context — **WF-R01.3.4** |

## 9. BREADCRUMBS Policy

### Family and registry disposition

```text
BREADCRUMBS = F3 Structural Block (layout-component policy, Tier B)
```

- Remains **Block Family F3 → Structural Subtype** per [foundry-vocabulary-canon-charter-v1.md](foundry-vocabulary-canon-charter-v1.md).
- **No** `block_id` registry row in v1.1 — per [wf-r01-2-structural-blocks-charter-v1.md](wf-r01-2-structural-blocks-charter-v1.md) Tier B.
- Future `block_id` waiver requires **separate** charter — **not** in WF-R01.3.3 v1 scope.

### Purpose

1. Show page position in site hierarchy.
2. Support navigation to parent levels.
3. Apply on **internal** multi-page routes — not on pure conversion LANDING primary surface.
4. **Not** global primary navigation (≠ `HEADER_NAV`).
5. **Not** an SEO Surface (F6) — structured data relationship is a **future composition concern** only.

### Page-type applicability

Legend: **O** = Obligatory on reference scaffold when page type is in scope · **R** = Recommended · **—** = Not required / often omitted

| `page_type` | Applicability | Notes |
|-------------|---------------|-------|
| `LANDING_PAGE` | **—** | Not obligatory; linear conversion surface |
| `HOME_PAGE` | **R** | Hub entry — shallow trail acceptable |
| `SERVICE_PAGE` | **R** | Money page — parent hub link |
| `CATEGORY_PAGE` | **O** | PLP — category tree orientation |
| `PRODUCT_PAGE` | **O** | PDP — category → product trail |
| `ABOUT_PAGE` | **O** | Internal corporate page |
| `CONTACT_PAGE` | **R** | Optional shallow trail |
| `FAQ_PAGE` | **R** | Help hub |
| `REVIEWS_PAGE` | **R** | Social proof hub |
| `LEGAL_PAGE` | **R** | Minimal trail; do not duplicate marketing stack |

`SEARCH_RESULTS` routing — **glossary / planned** (not in PAGE-TYPE-REGISTRY-v1 minimum 10); when scaffolded under WF-R01.3.4, BREADCRUMBS **R**.

### Minimum semantic contract (future T1+ partial)

| Requirement | Specification |
|-------------|---------------|
| Element | `<nav aria-label="Breadcrumb">` containing ordered list |
| List | `<ol>` preferred; `<ul>` acceptable if styled as trail |
| Current page | `aria-current="page"` on last item; **not** a self-link |
| Links | Ancestor items are anchors; hierarchy matches Blueprint IA |
| Placement | After `HEADER_NAV`, before page intro / MAIN content lead |
| SEO | No claim as SEO Surface; JSON-LD `BreadcrumbList` = **future composition** optional layer |

### Future T1+ partial acceptance criteria

A BREADCRUMBS implementation wave may count toward RPC **only if all apply**:

1. Dedicated reference partial (or documented layout-component module) with v1 naming discipline.
2. Matching SCSS in proper layer; scoped to block root.
3. Include or scaffold mapping on **≥1** non-LANDING `page_type` scaffold.
4. `npm run build` **PASS** with evidence REPORT.
5. Registry reference mapping update (layout-component row or future waiver `block_id`).
6. Wave execution REPORT published.

**Charter pass:** BREADCRUMBS implementation is **forbidden** in this charter pass.

## 10. PAGINATION Policy

### Family and registry disposition

```text
PAGINATION = F3 Structural Block (layout-component policy, Tier B)
```

Same Tier B / F3 subtype rules as BREADCRUMBS (§9). **No** v1.1 `block_id` row.

### Purpose

1. Navigate between pages of a **listing** (PLP, archive, search results).
2. Apply to multi-page list surfaces — **not** single-item PDP.
3. **Absent** on `LANDING_PAGE` conversion surfaces.
4. Distinct from **infinite scroll** (behavior policy — not PAGINATION partial).
5. Distinct from **carousel** navigation (Swiper/carousel owns that axis).
6. Distinct from **stepper / wizard** flows (`PROCESS` block owns step narrative).
7. Distinct from **filter** controls (`FILTERS` ≠ `PAGINATION`).

## 11. Shell Scaffold Contract

### Shell-ready scaffold definition

A reference scaffold is **shell-ready** when it documents and implements:

```text
page identity (page_type, title, route notes)
HEADER_NAV slot
MAIN content region (single <main>)
optional BREADCRUMBS slot
page-specific block sequence (per Reference Composition or wave charter)
optional PAGINATION slot
FOOTER slot
LEGAL_LINKS composition (nested in FOOTER)
asset and JS mapping (SCSS imports, init hooks)
build evidence requirement (npm run build PASS)
```

### Composition evidence

| Artifact | Requirement |
|----------|-------------|
| Scaffold page | `src/pages/{slug}.html` or documented equivalent |
| Manifest | `{PAGE_TYPE}-SCAFFOLD-MANIFEST-v1.md` stub-declaration per [wf-r01-3-1-coverage-model-charter-v1.md](wf-r01-3-1-coverage-model-charter-v1.md) |
| Reference Composition | Published doc for PC numerator when wave completes |
| Build REPORT | Wave REPORT with `dist/` evidence path |

### RSC accounting

| Rule | Policy |
|------|--------|
| Shell policy docs alone | **Do not** increase RSC |
| Scaffold specification without built page | **Do not** increase RSC |
| Built scaffold + manifest + build PASS | **May** increase RSC per page_type |
| Global shell contract publication (S1) | Documentation only — **no** RSC delta |

**Current RSC:** **1/10** global · **1/1** LANDING — unchanged at charter T0.
