### 6/7 name discrepancy decision

G2-R5 §15 lists **seven named rows** (CERTIFICATES, MAP, PARTNERS, DELIVERY, PAYMENT, CHECKOUT, CART) while G2-01 debt states **six remaining RPC gaps**. Programme design W7 lists **five** names (FEATURES, REVIEWS, CERTIFICATES, PARTNERS, MAP).

**Charter resolution (binding):**

1. **Six binding RPC gaps** — the only units that **increment RPC numerator** when closed in W6/W7 implementation waves:

   ```text
   CART · CHECKOUT · PAYMENT · DELIVERY · CERTIFICATES · PARTNERS
   ```

2. **MAP, FEATURES, REVIEWS** — **registry rows without dedicated partials** but **not counted in the six-gap register** at charter entry because **substitution credits** already satisfy the **26/32** snapshot:
   - **FEATURES** → planning substitute **BENEFITS** partial (G2-R2 SERVICE_PAGE constraint)
   - **REVIEWS** → planning substitute **TESTIMONIALS** partial (trust lane)
   - **MAP** → planning substitute **CONTACTS** geo region in contact surfaces

3. **W7 mandatory work** still includes dedicated **FEATURES**, **REVIEWS**, **MAP** partials for Template-Art honesty and CORPORATE/ECOMMERCE SC — implemented as **hygiene waves** that **do not change RPC numerator** unless a future **Coverage addendum** splits substitution policy (see §31).

4. G2-R5 seventh table row (**MAP**) is **scope documentation**, not an eighth RPC gap — **MAP** closure is **W7 hygiene**, not one of the **six binding gaps**.
