# i-SEO Report Hub — Visual / UX Review Criteria v0.1

**project_id:** `iseo-report-hub`  
**Wave:** App Pages Visual QA Preparation 01  
**Use:** чеклист «на что смотреть» при ручном проходе

---

## 1. Язык и тексты

- Интерфейс на **русском**.
- Нет лишнего английского в кнопках, заголовках, статусах (допустимы редкие технические `code` в свёрнутых details).
- Нет debug-текстов вроде `Updated body`, `Risks body`, сырых ключей полей, внутренних id как основного UI.
- Статусы и бейджи понятны без расшифровки.

## 2. Иерархия и читаемость

- Понятный заголовок страницы (topbar / H1–H2).
- Один главный смысл на экран / секцию.
- Карточки и таблицы читаются; нет «каши» из одинаковых блоков.
- Отступы и выравнивание не ломают глаз (не идеальный pixel-perfect — достаточно «аккуратно и понятно»).

## 3. Кнопки и действия

- Подписи кнопок понятны.
- Опасные действия (финализация, apply, revoke, генерация PDF) **визуально отделены** или выглядят вторичными / заблокированными где нужно.
- Primary / secondary не путают «куда кликать».
- На клиентском preview **нет** админ-кнопок (финализация, apply, создать share).

## 4. Формы

- Поля с **видимой рамкой**.
- Focus виден.
- Labels рядом с полями.
- Disabled / locked состояния понятны.
- В этом QA-проходе формы **не отправляем** — смотрим только вид.

## 5. Empty / warning / error

- Пустые состояния объясняют, что делать дальше.
- Warning / lock (финализирован, apply disabled) не «страшные» красные простыни без смысла.
- 404 / redirect на login понятны.

## 6. Client-facing document

- `/preview` и `/preview/print` выглядят как **документ**, не как админка.
- Нет sidebar/admin chrome на print (или минимально приемлемо для print layout).
- Контент отчёта читается сверху вниз как клиентский отчёт.

## 7. Export / share internal

- Служебные экраны могут быть утилитарными, но читаемыми.
- Не светить секреты/токены крупно; оператору не копировать tokens в замечания.

## 8. Brand / shell (internal)

- Sidebar / brand mark согласованы с локальной оболочкой (жёлтый акцент i-SEO где уже внедрён).
- Нет ощущения «сломанного прототипа» на главных экранах.

## 9. Данные и модель (визуально)

- Счётчики работ, статусы отчёта, список экспортов не противоречат ожиданию (report 1 filled / report 5 empty).
- Если данные выглядят «фейковыми» или debug — отметить как content issue.

## 10. Вне scope этой волны

- Pixel-perfect PDF.
- Mobile layout.
- Регенерация export 4.
- Production branding на share PDF stream.

---

## Quick pass / fail cues

| Signal | Likely issue type |
|--------|-------------------|
| Английский в кнопке | text/content |
| Поле без рамки | form |
| Admin button on client preview | client report |
| Непонятно куда идти | navigation |
| Красный баннер без объяснения | warning/error |
| Таблица не читается | layout |
