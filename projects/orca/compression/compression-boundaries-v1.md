# Compression Boundaries v1

## Boundary

ORCA Documentation Compression may help humans prune, merge, or simplify ORCA documentation.

It does not create governance expansion, AI architecture, automation, orchestration, dashboards, telemetry, runtime systems, or intelligence mythology.

## Explicitly Rejected

- documentation for its own sake;
- fake sophistication;
- giant governance layering;
- abstraction inflation;
- pseudo-intelligence narratives;
- methodology addiction;
- cleanup processes that create more bloat.

## Allowed Scope

- documentation pruning;
- duplicate detection;
- low-value layer detection;
- operational usefulness review;
- complexity warning detection;
- stale documentation detection;
- operator overload awareness.

## Required Compression Discipline

- smaller can be better;
- practical usability matters;
- documentation has maintenance cost;
- operator attention is limited;
- low-value layers should be removed;
- stale docs create operational confusion.

## SAFE UNKNOWN

ORCA does not know whether a document is still operationally used unless current human practice or reliable project evidence confirms it.
