# Documentation Compression Rules v1

## Status

Manual cleanup rules. Not governance expansion, automation, telemetry, or intelligence architecture.

## Purpose

Reduce ORCA documentation to what improves practical PPC operator use.

## Compress When

- methodology is duplicated;
- abstractions repeat without new operator value;
- a layer is theoretical-only;
- notes create excessive review loops;
- documentation amplifies operator fatigue;
- stale guidance creates confusion;
- the document exists mainly to look sophisticated.

## Keep When

- the document improves operator speed;
- it supports commercial realism;
- it reduces PPC risk;
- it clarifies evidence use;
- it helps stop or simplify review.

## Required Compression Discipline

Smaller can be better. Practical usability matters. Documentation has maintenance cost. Operator attention is limited. Fake sophistication is dangerous. Low-value layers should be removed. Stale docs create operational confusion.

## Boundary

These rules reject documentation for its own sake, fake sophistication, giant governance layering, abstraction inflation, and pseudo-intelligence narratives.
