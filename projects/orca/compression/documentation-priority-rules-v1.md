# Documentation Priority Rules v1

## Status

Manual priority rules. Not governance expansion, automation, or intelligence scoring.

## Prioritize Documents That

- improve PPC operator speed;
- reduce high-impact risk;
- clarify evidence quality;
- prevent low-value review loops;
- support commercial realism;
- help stop analysis;
- reduce operator overload.

## Deprioritize Documents That

- repeat existing methodology;
- add theoretical-only layers;
- introduce non-operational complexity;
- create excessive review loops;
- increase maintenance cost without usability gain;
- use fake sophistication to hide low value.

## Priority Test

If a document does not help an operator act, stop, simplify, or escalate, it is probably low priority.

## Required Compression Discipline

Smaller can be better. Practical usability matters. Documentation has maintenance cost. Low-value layers should be removed.

## Boundary

These rules reject documentation for its own sake, giant governance layering, abstraction inflation, and pseudo-intelligence narratives.
