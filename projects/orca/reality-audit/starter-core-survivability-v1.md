# Starter Core Survivability v1

## Survivability Verdict

The starter core can survive live use if it remains a decision path, not a document library.

## Minimal Surviving Path

1. `OPERATIONAL-INDEX.md`
2. One primary review:
   - `fast-review/mobile-serp-review-v1.md`
   - or `fast-review/landing-mismatch-review-v1.md`
   - or `essential-signals/semantic-contamination-v1.md`
3. Optional support:
   - `fast-review/mobile-friction-review-v1.md`
   - `fast-review/cta-pattern-review-v1.md`
   - `essential-signals/trust-patterns-v1.md`
   - `essential-signals/aggregator-pressure-v1.md`
4. `reports/orca-live-session-report-template-v1.md`

## What Helps The Next PPC Decision

- SERP pressure: adjust expectation, ad angle, or landing proof.
- Landing mismatch: change landing target, ad promise, grouping, or hold.
- Semantic contamination: add negative candidates, split groups, or hold uncertain terms.
- Mobile friction: send to landing fix list or avoid pushing traffic.
- CTA pattern: align ad and landing action.

## What Threatens Survivability

- Reading all related guides.
- Treating support signals as required.
- Filling report fields that were not reviewed.
- Repeating boundary disclaimers inside every operator-facing doc.
- Letting governance files become part of the live checklist.

## Compression Rule

If a step does not change one of these decisions, remove it from the live session:

- keep;
- change;
- split;
- add negative candidate;
- fix landing;
- hold / SAFE UNKNOWN.

## SAFE UNKNOWN

Survivability is not yet proven. It requires at least one real PPC review with time taken, docs opened, decisions made, and operator friction noted.
