# Workflow Friction Review v1

## Verdict

The fastest workflow is clear only if the operator starts from `OPERATIONAL-INDEX.md`. Starting from folder READMEs creates friction.

## Friction Findings

- `README.md` still exposes the full ORCA documentation map before the live-first path can prove usefulness.
- `fast-review/README.md` mixes starter cards with older broad guides.
- `essential-signals/README.md` mixes starter support cards with older signal models.
- `live-pilot/README.md`, `starter-core/README.md`, and `OPERATIONAL-INDEX.md` repeat the same session rules.
- Report templates are useful, but the live template can invite filling every evidence field.

## Decision Impact

High-friction steps:

- choosing among many similar review docs;
- reading boundary text before the PPC object is clear;
- documenting evidence categories that were not reviewed;
- continuing because another related checklist exists.

Low-friction steps:

- one PPC object;
- one primary review;
- top 3 findings;
- one action or SAFE UNKNOWN;
- explicit stop reason.

## Compression Opportunity

Treat `OPERATIONAL-INDEX.md` as the only live-session entry point.

Treat folder READMEs as reference, not required reading.

## SAFE UNKNOWN

Actual friction must be confirmed by watching one real operator run a live review. This file identifies likely friction from document shape only.
