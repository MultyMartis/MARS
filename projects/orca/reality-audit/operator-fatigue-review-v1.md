# Operator Fatigue Review v1

## Verdict

Starter Core is usable, but fatigue risk appears when the operator opens both new live-first cards and older `rapid-*` / `high-value-*` guides in one session.

## Fatigue Risks

- Too many near-equivalent entry points.
- Repeated boundary language increases reading load.
- `fast-review/README.md` lists broad legacy review docs after the new starter cards.
- `essential-signals/README.md` exposes many signal guides that can pull a live session into taxonomy work.
- The live report asks for several evidence buckets even when the session reviewed only one object.

## Most Likely Failure Mode

The operator starts with one PPC question, opens multiple supporting documents, and spends attention reconciling ORCA docs instead of deciding the next PPC action.

## Compression Bias

- Use `OPERATIONAL-INDEX.md` only.
- Pick one primary card.
- Add one support signal only if the decision is blocked.
- Write top 3 findings, not a complete review.

## STOP ANALYSIS Cues

- Notes are getting longer but less actionable.
- The same issue appears under different labels.
- The operator is checking documents for completeness.
- A finding cannot change ad copy, landing choice, negative keywords, grouping, or hold decision.

## SAFE UNKNOWN

No live operator session has proven the fatigue threshold. Treat the 10-20 minute depth limit as a working constraint, not validated performance evidence.
