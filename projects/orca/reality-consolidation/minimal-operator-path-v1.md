# Minimal Operator Path v1

## Status

Smallest realistic ORCA workflow proposal. Not automation, orchestration, runtime system, dashboard, telemetry, or new architecture.

## Scenario

- one PPC operator;
- one local-service niche;
- one city;
- one small campaign;
- target: minimal useful system.

## Core Principle

Use the fewest ORCA layers that can support a practical PPC decision. Avoid giant process chains, documentation overload, and excessive review loops.

## Minimal Useful Path

### 1. Define Scope

Use:

- `contracts`
- `workflows`

Output:

- niche;
- city;
- service;
- campaign goal;
- explicit exclusions;
- SAFE UNKNOWN.

Stop if scope is unclear.

### 2. Run Fast Market Scan

Use:

- `fast-review`
- `research`

Review only:

- local pack pressure;
- aggregator pressure;
- dominant CTA pattern;
- dominant trust pattern;
- urgent-intent behavior;
- obvious pricing or offer clarity.

Stop after high-impact signals are captured.

### 3. Check Semantic Cleanliness

Use:

- `semantic`
- `search-terms-review`

Review only:

- wrong-service traffic;
- low-commercial-intent contamination;
- broad semantic pollution;
- geo mismatch;
- urgent-intent mismatch.

Stop when the keyword/service meaning is clean enough for a small campaign draft.

### 4. Check Landing And Offer Fit

Use:

- `landing-match`
- `offer-evaluation`

Review only:

- landing mismatch;
- weak CTA alignment;
- trust support;
- pricing mismatch;
- mobile friction;
- local relevance.

Stop when the page can support the ad promise or when the mismatch must be escalated.

### 5. Draft Minimal PPC Assets

Use:

- `ad-copy`
- `ad-extensions`

Create only:

- one small set of ad messages;
- essential extensions;
- CTA aligned to landing;
- trust proof that is actually supported.

Do not create variant sprawl.

### 6. Run Final Practical QA

Use:

- `campaign-qa-assembly`
- `qa`
- `evidence`

Check only:

- semantic consistency;
- ad-to-landing consistency;
- geo consistency;
- CTA consistency;
- trust support;
- mobile path;
- unsupported claims;
- SAFE UNKNOWN.

Stop when the top risks are known.

### 7. Decide Or Escalate

Use:

- `operator-decisions` only if uncertainty remains;
- `minimalism` only to prevent over-review;
- `compression` only if documentation overload appears.

Decision options:

- proceed to human platform preparation;
- revise;
- escalate;
- stop as SAFE UNKNOWN.

## Layers Not Needed In Minimal Path

Usually skip unless evidence demands them:

- `intelligence`
- `methodology`
- `evolution`
- `patterns`
- `heuristics`
- `heuristic-mapping`
- `failure-patterns`
- `essential-signals`
- `observations`
- `confidence`
- `contradictions`
- `review`
- `pilot-cases`
- `live-observations`
- `live-pilots`
- `agents`

These may be useful references, but they should not be required for one operator, one city, one small campaign.

## Stop Rules

Stop review when:

- the next document will not change action;
- the next observation is low-impact;
- the operator is repeating the same uncertainty;
- evidence requires human verification;
- review speed is being sacrificed for fake completeness.

## Minimal Useful System

For the smallest real workflow, ORCA needs:

- scope;
- fast market scan;
- semantic cleanliness;
- landing and offer fit;
- minimal ad assets;
- final QA;
- evidence-aware decision or escalation.

It does not need a giant process chain.

## Boundary

This path is a practical operator route, not a claim that ORCA automates PPC work or makes business decisions.
