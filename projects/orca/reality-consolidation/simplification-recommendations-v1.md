# Simplification Recommendations v1

## Status

Manual recommendation document. No files merged, deleted, moved, archived, or rewritten.

## Reality Note

Simplicity is strategic. ORCA should optimize for real operator usability, not document count.

## What To Merge Later

### Evidence / Confidence / Contradictions

Candidate merge family:

- `evidence`
- `confidence`
- `contradictions`
- parts of `observations`
- parts of `operator-decisions`

Reason: these layers repeat evidence quality, uncertainty, contradiction handling, SAFE UNKNOWN, and false-certainty warnings.

### Fast Review / Minimalism / Essential Signals

Candidate merge family:

- `fast-review`
- `minimalism`
- `essential-signals`

Reason: all three prioritize high-impact signals, speed, stopping discipline, and operator fatigue reduction.

### Methodology / Review / Compression Rules

Candidate merge family:

- `methodology`
- `review`
- selected `compression` guidance

Reason: general review methodology has high abstraction risk. Keep only rules that directly improve operator action.

### Pattern / Heuristic / Failure References

Candidate reference family:

- `patterns`
- `heuristics`
- `heuristic-mapping`
- `failure-patterns`

Reason: these are useful only if treated as optional references, not mandatory process stages.

## What To Shorten

- Repeated "not automation / not orchestration / not runtime" boundary sections.
- Repeated "human review is mandatory" sections.
- Long template families that ask for the same evidence, risk, action, and SAFE UNKNOWN fields.
- Review chains that repeat semantic, landing, trust, CTA, mobile, and risk checks.
- Methodology docs that do not change operator action.

## What To Archive Later

Do not archive now. Later candidates:

- stale examples with no current operator use;
- duplicated templates that differ only by name;
- theoretical methodology files without practical PPC action;
- intelligence-framed docs that risk fake sophistication;
- evolution docs without pilot evidence.

## What To Keep Minimal

- `compression` — must stay a cleanup aid, not governance expansion.
- `minimalism` — must stay an operator stop-rule layer, not a theory layer.
- `fast-review` — must stay short enough for real PPC use.
- `operator-decisions` — must remain practical and not become strategy theater.
- `failure-patterns` — must stay awareness-only, not autonomous diagnosis.
- `essential-signals` — must not duplicate every review layer.

## What To Avoid Expanding

- `intelligence`
- `methodology`
- `evolution`
- broad `heuristic-mapping`
- duplicate meta-review templates
- any new layer that mainly renames existing semantic, trust, landing, or risk logic

## Minimal Consolidation Direction

Keep one practical spine:

1. `research`
2. `semantic`
3. `search-terms-review`
4. `landing-match`
5. `offer-evaluation`
6. `ad-copy`
7. `ad-extensions`
8. `campaign-qa-assembly`
9. `qa`
10. `evidence`
11. `fast-review` or `minimalism`

Everything else should be optional reference, pilot support, or cleanup support.

## Boundary

These are recommendations only. Do not merge, delete, archive, or rename files without a separate explicit cleanup task.
