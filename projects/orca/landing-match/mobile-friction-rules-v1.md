# Mobile Friction Rules v1

## Purpose

Identify obvious mobile landing friction that can weaken PPC traffic quality.

This is not a full UX audit or behavioral analytics system.

## Mobile Friction Signals

- excessive scrolling before service clarity;
- weak CTA visibility;
- form overload;
- slow contact access;
- weak readability;
- clutter;
- trust compression problems;
- small tap targets;
- hidden phone or WhatsApp action;
- large blocks before the next action.

## Mobile-First Review Questions

- Is the service clear on the first screen?
- Is the main CTA visible without hunting?
- Can the user call quickly?
- Is WhatsApp visible if it matters?
- Is trust visible early enough?
- Is the form short enough for mobile?
- Does the page reduce or increase decision effort?

## Trust Compression Problems

Mobile trust compression appears when desktop proof exists but mobile users cannot see it soon enough.

Examples:

- reviews buried below long text;
- equipment proof hidden far down;
- local proof below unrelated sections;
- phone CTA visible but no trust nearby.

## Boundary

ORCA records obvious friction only. It does not measure user behavior, run heatmaps, or claim conversion impact.
