# ORCA Operator Onboarding Path v1

## Status

Smallest onboarding path for practical PPC operators.

This is not a training system, certification path, governance process, or methodology expansion.

## Who This Is For

- PPC operator;
- local service campaign;
- small business;
- one city;
- limited review time;
- practical decisions over documentation completeness.

## What To Read First

Read in this order:

1. `minimal-real-pilot-workflow-v1.md`
2. `session-execution-guide-v1.md`
3. `fast-review/fast-review-workflow-v1.md`
4. `search-terms-review/search-term-cleanliness-rules-v1.md`
5. `landing-match/landing-match-boundaries-v1.md`

Stop there for the first session.

The operator should understand:

- how to run one bounded review;
- when to stop;
- how to catch dirty search intent;
- how to check landing fit;
- how to record SAFE UNKNOWN.

## What To Ignore Initially

Ignore at onboarding:

- architecture documents;
- governance documents;
- methodology expansion;
- advanced pattern libraries;
- full semantic clustering;
- exhaustive competitor review;
- multi-region research;
- launch/export readiness;
- automation or runtime language;
- large evidence normalization.

Reason:

new operators need a small decision path, not a tour of ORCA.

## What To Use Daily

Daily small-campaign stack:

- minimal workflow for session shape;
- session guide for time and stop rules;
- fast review for compression;
- search-term cleanliness for intent waste;
- landing match for page fit and mobile friction;
- ad-copy boundaries when writing or reviewing ads;
- campaign QA boundaries only as final caution.

Daily output should stay short:

- top risks;
- evidence reference;
- action;
- SAFE UNKNOWN;
- escalation if needed.

## What Only Senior Operators Should Use

Senior-only or later-stage layers:

- full semantic clustering;
- detailed campaign assembly;
- multi-region comparison;
- complex contradiction review;
- large competitor inventory;
- advanced pattern work;
- evidence normalization across many sources;
- cleanup or consolidation analysis.

Reason:

these can help complex work, but they can also create false confidence when used before the operator has enough evidence.

## First Session Checklist

Before starting:

- choose one niche;
- choose one city;
- choose 5-10 seed queries;
- set a time limit;
- decide mobile-first or desktop-first;
- prepare a simple notes file.

During review:

- scan SERP pressure;
- note only dominant signals;
- check semantic cleanliness;
- check landing fit;
- check claim support;
- write SAFE UNKNOWN.

After review:

- write one practical decision;
- mark confidence;
- escalate unsupported claims or budget risk;
- stop before fatigue turns into fake completeness.

## Onboarding Success

Onboarding works when the operator can run a small PPC review without asking:

`Which ORCA document should I open next?`

The correct default is:

`Do the small review, make the PPC risk clearer, and stop.`
