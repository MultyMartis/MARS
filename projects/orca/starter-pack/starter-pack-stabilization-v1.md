# ORCA Starter Pack Stabilization v1

## Status

Milestone stabilization note.

This freezes the current starter-pack understanding for future real operational testing. It does not create a new ORCA system, architecture, governance layer, methodology, automation, or runtime.

## Stable Enough For Testing

The following is stable enough to use in a real manual PPC pilot:

- one operator;
- one local-service niche;
- one city or tight region;
- one small campaign;
- one landing page;
- short mobile-first review;
- semantic cleanliness check;
- landing-fit check;
- ad-claim safety check;
- final QA caution;
- SAFE UNKNOWN where evidence is missing.

The starter core is stable as a working subset, not as a proven universal method.

## Stabilized Starter Core

Use as the default visible pack:

- `minimal-real-pilot-workflow-v1.md`
- `session-execution-guide-v1.md`
- `fast-review/fast-review-workflow-v1.md`
- `search-terms-review/search-term-cleanliness-rules-v1.md`

Use only when needed:

- `campaign-qa-assembly/campaign-qa-boundaries-v1.md`
- `operator-decisions/templates/evidence-review-template-candidate-v1.md`

## Still Experimental

These remain experimental or later-stage for starter use:

- candidate templates;
- fictional examples;
- advanced pattern work;
- multi-region comparison;
- large evidence normalization;
- full semantic clustering;
- full competitor inventories;
- detailed UX audits;
- launch/export readiness.

They may have value later, but they should not be exposed as default starter-pack material.

## Should Not Expand Yet

Do not expand:

- the operator stack;
- onboarding sequence;
- template count;
- campaign QA depth;
- evidence forms;
- competitor review chain;
- semantic review depth;
- automation or runtime framing.

Expansion should wait until real sessions prove a repeated operational gap.

## Validate Through Real Use Only

Only real operational testing can validate:

- whether the stack is fast enough;
- whether operators can find the right file quickly;
- whether semantic checks reduce wasted spend;
- whether landing-fit review improves decisions;
- whether optional layers are actually needed;
- whether SAFE UNKNOWN is used instead of guessed around;
- whether fatigue appears before value appears.

## Anti-Bloat Warnings

- Document selection load is operational cost.
- More layers can reduce decision quality.
- Repeated safety warnings can become noise.
- Templates can create fake completeness.
- A layer that does not improve the next PPC decision should stay closed.
- Do not add a document to solve a problem that only needs a stop rule.

## Operator-First Principles

- The operator needs clarity, not system size.
- Practical PPC risk beats theory.
- Speed matters.
- Evidence matters.
- Escalation is healthy.
- SAFE UNKNOWN is valid.
- Real testing matters more than new docs.

## Stabilization Result

ORCA now has a usable operational core for small local-service PPC testing.

The next milestone should be real use, not more structure.
