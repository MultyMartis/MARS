# MARS — Reality audit questions

**Status:** **documented** — **human-reviewed** prompts only. **Not** a form engine, **not** telemetry, **not** automated scoring.

**Purpose:** Lightweight question groups for Reality Audits (see [reality-audit-framework.md](reality-audit-framework.md)). Use selectively; skip groups with no owner.

---

## How to use

- Pick **3–6** groups per audit cycle; depth beats coverage.
- Capture answers as short notes, REPORT excerpts, or lifecycle log pointers—**not** mandatory structured DB.
- Prefer **named humans** over anonymous “the team” when recording friction.

---

## 1. Usefulness

- Which **three** governance or execution docs did operators **actually open** last month?
- Which doc reduced a real decision or prevented a mistake?
- Which artifact is **nice in theory** but **unused in practice**?

## 2. Friction

- Where do people **reread** multiple files to answer one question?
- Which rules require **ceremony** without reducing risk?
- What is consistently **worked around**—and why?

## 3. Onboarding

- Time-to-first-safe-contribution: **improving**, flat, or unknown?
- What must a newcomer read—**minimum** path still accurate?
- Which “optional” reads became **de facto** mandatory—and should they?

## 4. Helper value (S5/S6)

- Which helper last **saved** rework or caught an error?
- Which helper output is **ignored** or distrusted?
- Any helper that **implies** scheduling, autonomy, or platformhood?

## 5. False-positive fatigue

- Which warnings or checklists fire often but rarely change behavior?
- Where did “green checks” replace **thinking**?
- What should be **demoted**, **merged**, or **removed**?

## 6. Governance overhead

- Maintenance cost of indexes and cross-links: **sustainable**?
- Duplicated normative text: shrinking or growing?
- Does governance **block** delivery—or only **clarify** boundaries?

## 7. Terminology clarity

- Terms that **mean different things** in different lanes?
- Prestige or architecture language that **obscures** obligations?
- Registry/runtime vocabulary leaking into **non-runtime** contexts inappropriately?

## 8. Lane survivability

- Parallel lanes: **ownership** clear? **Merge points** documented?
- Handoffs that routinely **lose** context?
- REPORT format: still **worth the effort** for readers?

## 9. REPORT usefulness

- Do REPORTs get **read**—or filed?
- Do REPORT fields match **what reviewers need**?
- Are UNKNOWN / SECURITY RISK sections **honest** or boilerplate?

## 10. Operational continuity

- Migration packages: **used** when context breaks?
- Lifecycle log: **signal** or noise?
- Chat/session loss: recovery path **known**?

## 11. Migration quality

- After migrations, do **old paths** still trap people?
- Deprecation pointers: **accurate**?
- “Historical” material clearly **non-SoT**?

## 12. Semantic drift

- Diagrams/maps **older** than practice?
- Capability language vs **proven** scope: any inflation?
- Three-way split (documented / planned / legacy) **honored** in new prose?

## 13. Runtime mythology risk

- Any doc that reads like a **running system** without in-tree proof?
- Pilots described as **product capabilities**?
- “Interoperability” stated where only **manual export** exists?

## 14. Helper / platform drift

- Scripts acquiring **implicit** state or schedules?
- Helpers **renamed** as services?
- Operator-only utilities creeping toward **mandatory** gates?

## 15. Experimental usefulness (S7)

- Which experiments produced **decisive** evidence?
- Which experiments should **stay isolated** or retire?
- Pattern promotion: **human-gated** and documented—or assumed?

---

## SAFE UNKNOWN

Baseline metrics for any of the above—**SAFE UNKNOWN** unless humans collect lightweight evidence deliberately. Comparative “before/after” scoring—**optional**, not defined here.
